## Context

挂机结算目前由 `game` store 统一处理在线 tick 和离线收益，地区材料只会进入 `bag.items`。奇遇需要跨越纯逻辑、内容配置、存档、store 和挂机页 UI，同时必须遵守核心逻辑纯函数、随机可复现、存档迁移和 390×844 竖屏优先约束。

## Goals / Non-Goals

**Goals:**

- 在线和离线的有效挂机时间都能推进奇遇，并在队列未满时产生地区相关事件。
- 奇遇出现和处理都不改变原有经验、金币、装备、材料、关卡和战斗演出结算。
- 玩家主动打开面板后，可消耗已有地区材料换取明确的小额养成资源。
- 奇遇内容、消耗和奖励全部配置化；生成与结算可用纯函数测试。

**Non-Goals:**

- 首版不做奇遇战斗、限时消失、连续剧情、图鉴、日常任务或独占装备。
- 不把奇遇做成新的底部 Tab，也不引入新的位图美术。
- 不调整现有挂机掉落率和材料掉落表。

## Decisions

### 1. 用“有效挂机秒数”而不是每次击杀概率触发

存档记录奇遇进度秒数。新存档首次奇遇采用较短门槛，后续采用固定间隔；在线 tick 与离线结算都调用同一纯函数推进。这样低攻速玩家不会长期遇不到，高攻速玩家也不会被频繁事件淹没。

备选方案是每次击杀独立掷概率，但触发频率会随攻速显著放大，也会额外消耗主掉落 RNG 序列，因此不采用。

### 2. 待处理队列上限为 3，满队列只阻止新奇遇

奇遇生成后写入存档队列，不弹强制模态框。队列满时丢弃超出容量的挂机时间，不累计隐藏欠账；玩家处理后从正常进度重新积累。挂机收益逻辑完全独立执行。

### 3. 奇遇 RNG 与掉落 RNG 隔离

事件选择使用 `save.seed + generatedCount` 派生的本地 `Rng`，同一存档与生成序号得到相同事件，同时不改变装备、掉落或强化的随机序列。

### 4. 选项奖励在选择前隐藏，结算后随机揭晓

选项结构使用固定 `costs` 与加权 `rewardPool`，奖励资源仅包含金币和 `itemId` 数量范围。界面在选择前不展示奖励种类、数量或概率；纯函数先验证资源，再通过“存档种子 + 奇遇 UID + 选项 ID”派生的本地 RNG 掷出奖励并原子结算。所有付费选项的每个奖励档都至少包含一项正收益，稀有材料事件配置更高的最低回报；每个事件仍保留零成本离开选项。

备选方案包含随机装备实例，但会扩大到装备词条、UID、职业过滤和背包容量，首版暂不采用。

奖励随机流不推进主 RNG，同一待处理奇遇刷新后结果不变，也不会改变装备、掉落或强化的随机序列。

### 5. 入口只在有待处理奇遇时出现

挂机页在战斗区下方显示一条轻量提示；点击后才打开底部抽屉式面板。面板关闭不会处理事件，战斗循环在面板打开期间仍然运行。系统图标使用 Lucide，颜色和卡片样式复用项目现有蓝白粉变量。

## Risks / Trade-offs

- [材料兑换可能破坏经济] → 首版奖励保持小额，不发独占资源；完成后运行模拟器确认主成长曲线未变化。
- [离线时间一次塞满队列] → 上限 3 且不累计超额欠账，避免登录后连续处理大量事件。
- [玩家不知道进度] → 首次事件较快出现；首版只在事件可处理时提示，后续再根据试玩反馈决定是否展示进度条。
- [当前分支还包含自动推进变更] → 奇遇作为独立 OpenSpec 能力和独立代码模块实现，提交前明确文件范围，避免修改自动推进规则。

## Migration Plan

1. `SAVE_VERSION` 从 3 升到 4，新建存档初始化空奇遇状态。
2. v3→v4 迁移只新增奇遇状态，不修改旧资产与进度。
3. 若回滚代码，v4 存档不能被 v3 静默读取；玩家可保留 v4 存档等待功能恢复。

## Open Questions

- 首次与后续触发间隔需根据试玩体感调整；先作为数据常量集中配置，不散落在 UI 或 store。
- 地区 3 以后新增内容时，只追加奇遇配置，不修改核心逻辑。
