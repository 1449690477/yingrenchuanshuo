## Context

PR #9 已用 v8 存档记录角色关系、完成篇章和回答历史，但玩家只能在待处理奇遇弹出时看到角色；三幕结束后只剩单一日常，缺少持续感。项目是无服务器的静态 PWA，动态内容必须由现有存档种子、待处理 UID 和历史最高章节本地确定，刷新或重开不能刷对白、成本或奖励。

本变更堆叠在 PR #9 之上，不修改其一次性篇章语义，也不把回顾或关系阶段接入战斗数值。

## Goals / Non-Goals

**Goals:**

- 提供常驻手札入口，重建玩家已经完成的角色故事和回答。
- 为每名现有角色提供多种可重复日常，并让相同 UID 始终得到相同变体。
- 依据历史最高章节选择日常材料与奖励档位，手动回旧关不降档。
- 队列层面避免同一角色同时出现两件待处理事件。
- 保持普通奇遇、挂机推进、主掉落 RNG 和 v8 存档兼容。

**Non-Goals:**

- 不增加第三名角色、正式立绘、语音、恋爱锁线或坏结局。
- 不提供关系属性、关系奖励倍率或主动刷取奖励的入口。
- 不保存手札回放的逐句游标，不为本次变更升级存档。
- 不建立独立“角色图鉴”主导航；手札是挂机页的轻量辅助入口。

## Decisions

### 1. 手札内容由现有角色进度和剧情配置派生

核心纯函数按 `characterId` 聚合非重复篇章，并用 `completedEncounterIds`、`choiceHistory` 和当前待处理角色生成手札摘要。角色在第一件剧情进入待处理队列时即视为“已遇见”；未遇见角色不显示，未完成篇章不提前泄露标题和内容。

回顾对白由“当时可触发的记忆回响 + 开场对白 + 已选回答对应回应”重建。回顾只读取状态，不生成 UID、不调用奖励 RNG、不写 Store，因此无需额外存档字段。

### 2. 日常变体由存档种子和待处理 UID 派生

可重复日常在同一个 `EncounterDefinition` 中配置 `dailyVariants`，而不是拆成多个候选 ID。核心函数用 `saveSeed + pendingUid + encounterId` 派生变体索引；UID 已持久化，所以关闭、刷新和离线恢复都看到相同内容。

每个变体可配置基础对白和按关系阶段追加的问候语。关系只改变文本，不参与变体权重、成本或奖励，避免形成攻略最优解。

### 3. 阶段援助使用有序章节档位覆盖付费选项

日常定义可配置从早到晚排列的 `supportTiers`。核心函数从已解锁章节集合中选择最后一个满足前置的档位，并用该档位覆盖第一项“援助”选择的成本与奖励池；第二项免费告别始终保留。

Store 和 UI 必须调用同一个纯函数得到有效选项，结算时重新计算并校验，防止界面显示档位和实际扣除档位分叉。每个材料档位都由数据测试确认在该章节或更早已有来源，最低奖励价值仍不得低于成本。

### 4. 同角色去重在候选阶段完成

数据适配层根据当前 pending encounter ID 推导已占队列的 `characterId`，核心候选函数排除相同角色的其他定义。非角色事件仍只按 encounter ID 去重；已处理后角色可再次进入候选池。

相比给存档新增“角色冷却”，此方案能直接解决三格队列重复占位，且不改变产生频率和存档结构。

### 5. 手札使用独立面板，回顾使用只读演出状态

挂机页在玩家遇见至少一名角色后常驻显示“旅途手札”入口，与待处理奇遇入口分开。面板先展示角色卡和已完成幕次；点击已完成幕次后进入只读回顾，沿用场景、占位字形、打字机、跳过和减弱动效规则，但不渲染材料或奖励按钮。

390×844 和 320px 均保持单列、44px 触控目标、无横向滚动；关闭手札不会暂停挂机。

## Risks / Trade-offs

- [手札与奇遇面板可能复制演出代码] → 把对白推进保持在小型局部状态，视觉变量沿用项目 token；本批不为两个面板抽象过度通用框架。
- [章节档位配置顺序错误] → 内容一致性测试校验章节存在、顺序递增、材料来源和奖励价值。
- [关系问候组合导致对白突兀] → 每个变体只追加一句短问候，主体日常保持独立完整。
- [第三层堆叠增加 GitHub 差异] → 独立分支和 PR 明确依赖 #8/#9；上游合并后再逐层重放。
- [本地时间可被修改] → 本批没有每日次数或有奖主动触发，因此不依赖本地日期，也没有改时钟收益。

## Migration Plan

1. 保持 `SAVE_VERSION = 8`；新配置字段均为可选，旧 pending UID 足以稳定派生日常变体。
2. 发布后从现有 `characters` 和 pending 即时生成手札，不补写缓存。
3. 回滚时旧版本忽略新配置和新 UI，不会丢失任何存档字段。

## Open Questions

首批试玩后再决定是否把手札扩展为第三名角色、角色插画或无奖励的主动拜访；这些均不阻塞 E-4。
