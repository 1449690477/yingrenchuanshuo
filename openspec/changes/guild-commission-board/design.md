# Design: 公会协作大版本

## 服务端权威边界

当前已合入的防篡改层会把排行榜战力改为服务器从搭配快照复算，但本地背包材料、金币和装备所有权尚未迁入权威资产账本。因此本期不允许“本地材料捐献 → 联机奖励”或“公会商店发本地装备/货币”。

本期引入独立的服务器功勋小账本：

- 只有 Edge Function 完成一次团本复算，并且数据库已经保存本次新增贡献后，才可由 service role 读取该结果换算功勋。
- 功勋余额、累计获得、消费、领取与每个来源均在 Supabase 表内；前端不提交余额、功勋数量、价格、据点阶段或奖励数量。
- 捐献与领取带全局 request ID；重复请求返回已处理结果，不会再次扣除余额或推进据点。
- 商店只登记赛季收藏徽记，不向本地存档发装备、材料、金币或战力。等完整资产账本生产验收后，才可扩展为资源商店。

## 玩法循环

`异步团本（每天最好分）→ 服务端功勋 → 选择捐献或收藏 → 日建设与周团本共同推进赛季据点`

已有异步远征即为团本：客户端只给角色和八槽快照，Edge 复算伤害和 0～1000 评分，数据库只写“超过今日最好成绩的差额”。本期保留该结算并在成功之后触发功勋。

赛季据点不提供属性：

- 每日建设满额首次完成：+2 据点进度。
- 每周团本首次完成：+10 据点进度。
- 成员可把 1 / 5 / 10 点服务器功勋捐给据点。
- 阶段是纯展示与收藏解锁条件，不增加攻击、掉率、离线收益或排行榜伤害。

## 幂等与并发

- `guild_merit_awards.request_id` 防止团本网络重试重复发功勋。
- `guild_merit_spends.request_id` 防止捐献或领取超时后重复扣费。
- `guild_stronghold_sources(guild, season, source)` 防止同一天建设和同一周团本重复推进。
- 消费函数先锁成员钱包，再检查 request 和收藏记录，最后扣除余额并写来源；任一步失败会回滚整个事务。

## 客户端与降级

公会首页只显示 RPC 返回的据点快照；服务器尚未部署新迁移时据点面板显示“准备中”，仍可进入既有团本，挂机也不会被公会网络错误阻断。页面保持单层子页面，无 dialog 或二级弹窗。

## 部署与回滚

先执行数据库迁移，再运行 `npm run edge:build` 并部署 `guild-expedition`。只发布前端而未部署后端时为可用降级；只部署后端而未发布前端时不会影响既有团本。

回滚时先停止新 Edge 调用或回退前端；保留功勋和据点账本为只读审计数据，不删除玩家记录。
