## ADDED Requirements

### Requirement: 团本评分只能生成服务端功勋
系统 SHALL 仅在 `guild-expedition` 用共享核心逻辑复算团本评分、且原子远征请求已落库后，依据该请求实际新增贡献生成服务器功勋。客户端 MUST NOT 提交功勋余额、功勋数量或奖励数量。

#### Scenario: 重试同一团本请求
- **WHEN** 玩家用同一个 request ID 重试已成功的团本请求
- **THEN** 系统返回同一远征结果，功勋来源账不会新增第二条，余额不再次增加

#### Scenario: 较低分的重复挑战
- **WHEN** 玩家本次评分没有超过当天最好成绩
- **THEN** 系统记录挑战次数但不产出新的功勋，也不重复推进团本进度

### Requirement: 功勋捐献和收藏由服务器事务结算
系统 SHALL 将功勋余额、捐献、消费与收藏领取保存在服务端，并以固定捐献档位、固定价格与幂等 request ID 执行。客户端 MUST NOT 决定价格、扣款或领取状态。

#### Scenario: 连续点击捐献
- **WHEN** 同一捐献 request 因网络超时被重复提交
- **THEN** 系统至多扣除一次功勋，并至多向赛季据点加入一次对应进度

#### Scenario: 未解锁的收藏
- **WHEN** 玩家尝试领取需要更高据点阶段的收藏
- **THEN** 系统拒绝该请求，既不扣功勋也不写入收藏记录

### Requirement: 赛季据点只提供协作展示和收藏解锁
系统 SHALL 让满额日建设、每周团本首次完成和服务器功勋捐献共同推进赛季据点。阶段 MUST NOT 增加角色属性、掉率、离线收益或排行榜战力。

#### Scenario: 团本首次通关
- **WHEN** 公会周团本从未完成变为完成
- **THEN** 系统以一次性来源账推进本季据点；后续刷新或重试不会再次推进

#### Scenario: 后端尚未部署
- **WHEN** 客户端读取不到赛季据点 RPC
- **THEN** 据点面板进入准备态，已有团本和挂机继续可用

### Requirement: 权威资产账本上线前不发放本地可战斗资产
系统 MUST 在装备、材料和货币的完整权威账本生产验收前，将公会商店限制为服务器记录的赛季收藏，不向本地背包发放装备、材料、金币或战力奖励。

#### Scenario: 玩家修改本地材料
- **WHEN** 玩家篡改本地材料数量后尝试参与公会循环
- **THEN** 该材料不会被捐献或兑换，公会服务器余额、据点和收藏不受影响
