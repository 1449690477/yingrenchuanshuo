## Context

最新主分支的 `EquipmentInstance` 已保存 `baseRollPermille`、15 格逐级强化增幅、分目标幸运值、随机词条与锁定状态；存档版本为 v5。新掉落装备生成一次 80%～120% 的隐藏基础浮动，高价值结果会自动锁定；精品装备则由 `createFixedInstance` 生成固定 100% 模板。现版强化、自动进层、背包容量与性能优化都必须保持。

现有问题集中在表达边界：`instanceStats` 直接返回总属性，装备详情又重复列出随机/固定词条；详情与强化台公开了基础浮动档位和百分比；随机词条没有部位倾向。旧 PR2 的 90%～110%、`baseRollBps` 和 v2→v3 迁移方案已经过期，不能带回最新主分支。

## Goals / Non-Goals

**Goals:**

- 在现版字段上将新掉落调整为“多数低于标准、少量优秀、极少极品”的 80%～120% 分布，同时保留逐级强化、幸运值、碎裂和外观阶段。
- 用纯函数明确基础、固定词条、随机词条和总属性四层计算结果。
- 隐藏基础浮动的倍率与档位，仅通过最终数值和换装差值体现个体差异。
- 让部位主词条更常见，同时保留其他合法词条与 seeded RNG 可复现性。
- 背包排序、一键穿戴、锁定、穿戴、分解和详情始终针对真实实例与 UID。
- 为未来洗练、强化和同部位继承预留清晰且互不重掷的数据边界。
- 不改变 v5 存档结构，直接兼容已有玩家装备。

**Non-Goals:**

- 不改变基础浮动范围、概率、品质掉率、词条数量或强化成功率。
- 不实现洗练操作、继承操作、套装激活或新专属战斗效果。
- 不新增成色、评分百分比或第二套品质标签。
- 不把奇遇或其他独立 PR 的新增代码放入本 PR 差异。

## Decisions

### 1. 复用 v5 的 `baseRollPermille`，不迁移存档

`baseRollPermille` 继续使用整数千分数，合法范围从 1000～1200 放宽为 800～1200。字段语义仍是“装备生成时固定、之后不可洗练的隐藏基础浮动”，字段名和结构不变，因此 `SAVE_VERSION` 保持 5，不新增迁移函数。现有 v5 装备全部位于新范围内，可直接读取。

新掉落使用三段隐藏分布：

| 权重 | 范围 | 作用 |
|---|---|---|
| 65% | 800～999 | 多数作为分解或过渡装备 |
| 33% | 1000～1119 | 可参与同部位竞争 |
| 2% | 1120～1200 | 自动锁定的高价值结果 |

期望倍率约为 95.5%。这会让多数掉落成为筛选材料，同时保留极少数明显极品；最终影响必须通过真实实例抽样与模拟器复验。

基础档位仍可作为纯逻辑判断高价值掉落并自动锁定，但不得出现在装备详情、背包卡片、强化台或玩家文案中。精品模板继续固定为 1000，避免商店和可预览 BOSS 同款变成暗抽。

### 2. 属性分解是唯一计算入口

新增 `instanceStatBreakdown(def, inst)`，返回：

```text
base          = 定义基础属性经过隐藏浮动与当前逐级强化后的结果
fixedAffixes  = EquipmentDef.fixedAffixes 的属性贡献
randomAffixes = EquipmentInstance.affixes 的属性贡献
total         = base + fixedAffixes + randomAffixes
```

`instanceStats` 仅返回 `breakdown.total`，战斗、战力、排序和分解价值继续使用同一个总结果。隐藏浮动与强化只作用于 atk / def / hp / acc / eva；暴击率、暴击伤害和攻速等百分比基础属性保持定义值，固定词条和随机词条均不受强化放大。

### 3. 部位词条倾向由数据配置表达

新增 `SLOT_AFFIX_WEIGHT_MUL`。武器偏攻击，衣身与腰带偏防御/生命，首饰偏攻击/暴击，鞋偏闪避/攻速。实际抽取权重为全局权重乘部位倍率；未配置的合法词条倍率为 1，禁止把倾向写死在控制流里。

词条数量仍由品质决定，同一 key 不重复，固定词条 key 继续从随机池排除。统计测试必须证明主词条出现率更高，且其他合法词条仍能出现。

### 4. 确定性生成顺序保持单一入口

所有在线挂机、离线结算、首通奖励与普通 BOSS 掉落继续走 `createInstance(def, rng, uid)`，不得使用 `Math.random()`。同一定义、种子、UID 与生成顺序必须复现相同基础浮动、词条键和值。引入部位权重会有意改变新版本的词条选择分布，但不会重掷已保存装备。

精品购买和精品 BOSS 同款继续走固定模板路径，固定 100%、无随机词条、固定词条来自装备定义，并默认锁定。

### 5. 洗练、强化与继承的数据边界

- 掉落生成：只确定隐藏基础浮动与初始随机词条。
- 固定词条：属于装备定义，不可洗练，不受强化放大。
- 随机词条：属于装备实例，是未来洗练唯一可重掷区域。
- 强化：只更新强化等级、逐级增幅与幸运桶；已掷出的逐级成长掉级后仍保留。
- 继承：未来只在同部位之间转移强化等级、逐级增幅与约定的词条，不重新生成目标装备的隐藏基础浮动。

这次只固定接口语义，不实现洗练或继承操作。

### 6. 装备详情按来源分区，比较按最终结果单列

详情不再展示“稳固胚 / 精工胚 / 奇迹胚”或基础百分比，也不保留“最终属性（已含全部词条）”后再重复列词条。

展示顺序为：

1. 装备贡献战力与总战力差值；
2. 基础属性（已包含隐藏浮动和当前强化）；
3. 固定词条（存在时）；
4. 随机词条（存在时）；
5. 换装后总属性逐项变化；
6. 专属效果（存在时）。

基础区解释“已包含当前强化”，比较区明确是“换装后的角色总属性变化”，从文案上避免玩家误以为词条被加了两次。空槽时以零装备为对照。

### 7. 强化反馈只描述本级成长

强化台装备卡片和选择列表删除基础浮动档位与百分比。成功时仍展示 `gainRoll.permille` 的本级实际成长，并把内部档位文案统一为“稳固 / 精工 / 奇迹”；它只描述这一格强化结果，不描述掉落装备成色。

`forgeStageAt` 的原初 / 微光 / 辉光 / 星铸 / 樱华继续表示累计强化等级对应的外观阶段，装备图标、纸娃娃、粒子和拖尾逻辑保持不变。

### 8. 移动端延续现有蓝白粉底部弹层

复用项目 CSS 变量、品质色、大圆角和现有底部弹层。390×844 下正文可滚动，底部锁定/分解/穿戴按钮固定可达；按钮触控目标至少 44px，长词条和属性差值不得造成横向滚动。桌面端继续使用居中信箱布局，不另做横版信息架构。

## Risks / Trade-offs

- [隐藏成色后玩家不明白同名装备差异] → 用基础属性数值和逐项换装变化解释，不暴露内部倍率。
- [部位倾向抬高平均战力] → 使用温和倍率、批量 seeded 样本和 `npm run sim` 复验，不改单件装备数值。
- [分区后信息变长] → 移动端优先排序，省略空分区并固定操作栏。
- [自动锁定看起来无原因] → 保留锁图标与通用“高价值装备已保护”提示，不公开隐藏档位。
- [旧 PR2 历史包含过期迁移] → 从最新 main 重建并最终用 `--force-with-lease` 更新原分支，只保留干净的新提交。

## Migration Plan

1. 保持 `SAVE_VERSION = 5`，先增加属性分解、部位权重和核心测试。
2. 验证现有 v5 装备实例无需补字段即可通过严格 schema 并保持战力。
3. 更新装备详情、强化台和实例比较 UI，完成 390×844 验收。
4. 更新装备文档、ADR、ROADMAP 与 PROGRESS。
5. 运行 OpenSpec strict、verify、sim、build 与战斗/自动进层/强化台回归。
6. 审阅最终差异后，经项目所有者确认再以 `--force-with-lease` 更新 PR2 原分支。

回滚不需要存档降级；因为本次不改变 v5 结构，旧版和新版可读取同一装备数据。
