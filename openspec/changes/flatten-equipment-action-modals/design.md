## Context

装备详情本身是覆盖页面的 sheet，却直接挂载 `ReforgePanel` 与 `EquipmentAdvancementPanel`。在背包和养成页这是两层窗口，在装备副本奖励里会形成“战斗窗口 → 装备详情 → 操作面板”三层。与此同时，养成页已有功能更完整的 `ReforgeStudio`，旧 `ReforgePanel` 与其重复维护相同规则和候选确认 UI。

## Goals / Non-Goals

**Goals:**

- 装备详情只负责查看与基础装备动作，不再拥有洗练和升阶窗口。
- 页面级调用方负责在详情关闭后打开单层操作台，并把稳定装备 UID 传给操作台。
- 洗练继续遵守“先生成并持久化候选，后选择保留或替换”的事务边界。
- 副本奖励详情不允许继续进入第三层操作面板。
- 保持 390×844 与 320px 下无横向溢出、返回路径唯一、触控目标不小于 44px。

**Non-Goals:**

- 不修改洗练、同调、升阶的成本、概率、随机或数值公式。
- 不改变 `pendingAffixChange`、`SAVE_VERSION=12` 或迁移。
- 不把所有项目弹窗改造成路由页面；本次只处理装备操作链。
- 不取消洗练后的候选对比与玩家决定。

## Decisions

1. **装备详情改用显式请求事件。** `EquipDetail` 发出携带 UID 的 `request-reforge` / `request-advancement`，不再 import 或渲染操作面板。相比在详情内用 CSS 隐藏旧窗口，这能从组件依赖层彻底阻止二级弹窗回归。
2. **父页面采用“先关详情、下一帧开操作台”。** 背包、养成和挂机页先清空详情状态，再打开对应操作台，保证任意时刻只有一个 dialog。相比让两个窗口交叉淡出，这更容易管理焦点和 Escape。
3. **统一使用 `ReforgeStudio`。** 为洗练坊增加可选 `initialUid`，初始化时优先选中调用方指定的装备，再同步该装备的推荐操作和同调目标。旧 `ReforgePanel` 删除，避免两套 UI 漂移。
4. **升阶继续复用现有 `EquipmentAdvancementPanel`。** 该面板已具备事务与焦点控制，只改变由页面直接挂载，不复制逻辑。
5. **副本奖励详情只读到基础装备动作边界。** 奖励详情不提供洗练/升阶请求监听，因此隐藏这两个深层入口；玩家可稍后从背包或养成页处理。
6. **候选结果保持内联状态。** 洗练后在同一 `ReforgeStudio` 内显示原词条/新候选和“保留原词条 / 替换为新词条”，不创建新的结果 dialog。

## Risks / Trade-offs

- [风险] 事件切换时装备可能因其他事务消失 → 操作台始终按 UID 重新从 store 查找，不传递可失效的对象快照。
- [风险] 删除旧面板会让既有源码契约测试失效 → 将测试改为断言详情无嵌套面板、页面接管事件、洗练坊可按 UID 初始化。
- [风险] 副本奖励里少了即时洗练/升阶入口 → 换取不出现三层窗口；详情保留穿戴与比较，深度养成回背包/养成页完成。
- [权衡] 本次仍保留页面级单层 overlay，而不是引入子路由 → 改动更小，也不改变现有五 Tab 导航模型。
