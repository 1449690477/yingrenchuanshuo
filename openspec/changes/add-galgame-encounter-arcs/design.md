## Context

奇遇当前是最多三件的非阻塞队列，定义包含逐句对白与两个直接结算选项；存档只记录待处理事件，不记录角色或选择。`EncounterPanel.vue` 已提供场景、占位立绘、打字机和待处理切换，因此本次重点是连续性和选择状态，不重新发明整套弹窗。

本变更堆叠在 `gate-encounters-by-chapter` 之上：连续篇章同时受章节门槛和前置篇章约束。项目是纯静态单机 PWA，所有状态必须在 IndexedDB 存档中完成。

## Goals / Non-Goals

**Goals:**

- 用配置表达一次性连续篇章、前置关系和主线完成后的可重复日常。
- 让角色回忆玩家此前回答，同时不把剧情选择变成数值攻略题。
- 把剧情回答与材料援助分成两个可中断、可恢复的步骤。
- 保持事件 RNG、奖励 RNG 与主掉落 RNG 隔离，挂机不暂停。
- 在 320～390px 竖屏上保持大场景、清晰对白和 44px 以上触控目标。

**Non-Goals:**

- 不做恋爱锁线、坏结局、多周目、语音、剧情动画或角色图鉴。
- 不给关系阶段永久属性、专属装备或其他强制最优奖励。
- 不为首批角色生成正式立绘；继续使用现有占位与场景退化机制。
- 不重写非角色奇遇或改变其现有材料兑换行为。

## Decisions

### 1. 篇章用显式前置与一次性标记，而不是依赖编号推断

角色剧情配置声明 `characterId`、显示幕次、`requiredEncounterIds` 与 `repeatable`。候选纯函数同时检查地区、章节、已完成篇章和当前待处理队列；一次性篇章已完成后不再生成，可重复日常只在第三幕完成后进入候选池。

显式前置比“episode - 1”更容易支持未来插叙、双前置或跨区域重逢，也能在内容测试中发现缺失 ID 和循环依赖。

### 2. 剧情回答与材料援助分为两个阶段

角色事件先播放开场对白，再展示两个不带成本的 `storyChoices`。选择后将 `storyChoiceId` 写入对应待处理事件并播放该回答的 `responseDialogue`；随后才显示可选材料援助和“不用回礼”的结束操作。

材料援助仍使用现有可复现奖励池。剧情回答不改变成本、奖励、关系增量或篇章解锁，避免玩家为了收益选择不喜欢的台词。

### 3. 关闭面板只持久化已经做出的剧情回答

对白逐字游标仍是 UI 临时状态，关闭后允许重看；一旦选定剧情回答则写入 `PendingEncounter.storyChoiceId`，重新打开直接从角色回应开始，不能反复改答案。资源只有在最终援助 / 告别时才原子变化。

### 4. 角色进度记录完成篇章、选择记忆和隐藏关系值

`EncounterState.characters[characterId]` 保存 `bond`、`completedEncounterIds` 与 `choiceHistory`。每个一次性篇章完成时固定增加 1 点关系，无论选了哪句、是否援助；可重复日常不增加关系，避免无限刷阶段。

UI 只通过纯函数映射为“初遇 / 熟悉 / 亲近 / 信赖”，不显示数值和下一档还差多少。后续篇章可按 `choiceHistory` 追加一两句 `memoryCallbacks`，随后回到共同主线。

### 5. 同一奇遇不能在待处理队列重复占位

生成器从候选池排除队列中已有的 encounter ID。这样离线一次填满队列时不会出现三份同一幕；其他可重复事件在上一份处理后仍可再次生成。没有剩余候选时不生成新事件，挂机收益继续。

### 6. UI 采用“旅途手札”式信息层级

保留现有蓝白粉底部抽屉、场景与打字机，在标题区加入角色名、关系阶段和“第 N 幕”丝带；记忆回响使用一条淡粉手札提示。剧情回答与材料援助绝不同时出现，降低竖屏信息密度。所有按钮最小 44px，320px 下单列排列，减弱动效时关闭打字与漂移动画。

## Risks / Trade-offs

- [内容量比普通事件高] → 首批严格限制两名角色、各三幕加一个日常，以数据模板验证生产成本。
- [玩家关闭后需要重读回应] → 已保存回答但不保存逐句游标；允许跳过，比为每句对话扩存档更简单可靠。
- [PR #8 尚未合并] → 分支堆叠开发并标注依赖；#8 合并后再将最终 PR 基线刷新到最新 main。
- [迁移增加严格存档字段] → v7→v8 只补空 `characters` 和保留原 pending，配完整迁移与导入测试。
- [可重复日常挤占其他奇遇] → 继续使用均匀 seeded 候选；首批不加权，试玩后再决定角色事件权重。

## Migration Plan

1. `SAVE_VERSION` 从 7 升至 8。
2. v7→v8 为 `encounters` 新增空 `characters`，并原样保留计时、计数和待处理事件。
3. 待处理事件的 `storyChoiceId` 为可选字段，旧队列无需逐项改写。
4. 回滚到 v7 时按既有规则拒绝读取 v8 存档，防止静默丢失角色记忆。

## Open Questions

正式立绘、角色手札 / 回忆页和第三名角色将在首批试玩后另开变更，不阻塞本次实现。
