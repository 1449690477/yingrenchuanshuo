## Context

奇遇定义目前只声明可出现地区，store 每次推进奇遇计时器时把该地区全部奇遇交给 seeded RNG。由于选项成本包含章节材料，地区刚开放时可能抽到尚无来源的材料需求。存档已经记录已通关关卡，因此无需新增持久化字段。

## Goals / Non-Goals

**Goals:**

- 让每个奇遇从配置指定的章节起进入候选池。
- 用历史最高关卡进度判定，确保玩家回旧关挂机仍保留已解锁内容。
- 保留可复现随机、现有队列和旧存档兼容性。

**Non-Goals:**

- 不改变事件间隔、随机权重、奖励或材料成本。
- 不加入好感度、连续剧情、图鉴或新的 Galgame UI。
- 不清理或替换已经排队的奇遇。

## Decisions

1. **开放章节属于内容配置。** 在 `EncounterDefinition` 上声明 `unlockChapterId`，避免筛选代码硬编码六个事件；以后新增奇遇时能直接审查材料与章节是否匹配。
2. **筛选使用已解锁章节集合。** store 根据现有 `isStageUnlocked` 规则得到已开放章节，再调用纯筛选函数。相比使用当前关卡，这能支持回头刷图；相比新增“最高章节”存档字段，它不会引入迁移和双份状态。
3. **只筛选新生成候选池。** 待处理队列按事件 ID 继续解析，部署前已经生成的事件仍能保留并在材料足够后处理。
4. **内容测试校验材料时序。** 测试确认每个成本材料在开放章节或更早章节已有掉落来源，防止后续配置再次产生同类问题。

## Risks / Trade-offs

- [每次奇遇推进都需计算已解锁章节] → 当前只有少量静态关卡，集合计算成本可忽略；保持单一解锁规则比缓存更可靠。
- [2-1 暂时没有本地区新奇遇] → 这是避免提前要求 2-2 材料的有意取舍；挂机本身不受影响，已有待处理事件仍保留。
- [配置了错误或不存在的章节] → 数据一致性测试和 OpenSpec 严格校验在提交前拦截。

## Migration Plan

无需存档迁移。部署后仅影响下一次生成奇遇的候选池；回滚代码即可恢复原筛选行为。

## Open Questions

无；连续 NPC 剧情与好感度作为后续独立设计讨论。
