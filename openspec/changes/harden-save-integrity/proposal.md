## Why

《樱刃传说》仍以纯静态 PWA 和本地 IndexedDB 存档为主。现有 Zod 校验、备份槽和 revision/CAS 能防坏档、写盘中断与多标签覆盖，却无法判断“结构合法但数值被人为修改”的装备、货币或材料。公会、排行榜与未来交易会把本地修改扩散到多人环境，因此需要在不破坏离线挂机和 JSON 备份的前提下分层加强存档完整性。

## What Changes

- 为 IndexedDB 主槽与备份槽增加版本化完整性信封：稳定序列化摘要、单调 revision、父摘要链和写入时间，读取时可区分结构损坏、链断裂与普通旧档。
- 保留旧 JSON 存档导入能力，但导入档明确标记为“本地来源”；导入后重新建立本机完整性链，不把它伪装成服务端可信资产。
- 存档完整性异常时优先提供备份恢复、只读导出与清晰提示，不静默清档、不自动覆盖证据。
- 为联网关键资产新增服务端权威账本设计：装备 UID、货币余额、奖励来源、消耗与幂等请求以服务端为准，客户端存档只缓存已确认快照。
- 公会装备奖励、交易与竞争性资产在权威账本落地前保持关闭；现有离线挂机和纯展示公会不受影响。

## Capabilities

### New Capabilities

- `local-save-integrity`: 本地存档信封、摘要链、备份恢复、旧档兼容、导入来源标识和异常交互。
- `authoritative-asset-ledger`: 联网关键资产的服务端所有权、来源流水、幂等变更、快照同步和离线边界。

### Modified Capabilities

无。

## Impact

- 第一阶段修改 `src/save/storage.ts` 的物理存储格式和对应测试，但不修改 `SaveData` 业务字段，因此不提升 `SAVE_VERSION`；IndexedDB 旧裸快照在首次成功保存时升级为信封。
- 第一阶段只能可靠发现意外损坏和低成本直接编辑，不能对掌握开发者工具的玩家保守客户端秘密。
- 第二阶段新增 Supabase 表、原子 RPC、Edge Function 与资产同步状态；涉及经济规则，必须单独实施和上线。
- JSON 导出仍保持可读、可迁移；联机可信度元数据不允许通过导入伪造。
