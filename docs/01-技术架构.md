# 01 · 技术架构

## 技术栈（已定，非经决策记录不得更改）

| 层 | 选型 | 为什么 |
|---|---|---|
| 语言 | **TypeScript**（strict） | 类型是多 AI 协作的护栏，AI 改错了编译器会拦 |
| 构建 | **Vite** | 快，配置少，GitHub Pages 部署简单 |
| UI 框架 | **Vue 3** + `<script setup>` | 竖版挂机 UI 极其密集，Vue 模板写起来最省；中文生态好，AI 生成质量稳 |
| 状态 | **Pinia** | Vue 官方方案，轻，好测 |
| 战斗特效 | **PixiJS**（M4 之后才引入） | 前期用 CSS 动画就够，别过早引入 |
| 存档 | **IndexedDB**（`idb` 库）+ JSON 导入导出 | localStorage 容量不够，且同步阻塞 |
| 后端（可选） | **Supabase** 免费层 | 排行榜/公会/团本；前端直连，无需自建服务器 |
| PWA | `vite-plugin-pwa` | 装到手机桌面、离线可玩 |
| 测试 | **Vitest** | 和 Vite 同源，零配置 |
| 规范 | ESLint + Prettier | 统一多个 AI 的代码风格 |
| 部署 | GitHub Actions → GitHub Pages | 推代码自动上线 |

**分层规则（严格单向依赖）**：

```
views / components
      ↓  只能调用
    stores
      ↓  只能调用
core  ←  读取 →  data
      ↓
    save
```

`core/` **不许** import 任何 `vue`、`pinia`、DOM API。

### 美术源文件目录约定

- `art-source/` 提交**不可再生**的透明母版、对齐母版和生成提示词。AI 图片即使使用
  同一提示词也不能逐像素复现，因此属于源文件，不加入 `.gitignore`。
- `public/assets/` 只放浏览器实际加载的压缩成品；运行时配置只能引用这里。
- `scripts/` 保存从母版生成成品的确定性脚本，例如角色图层对齐、怪物 WebP、
  技能图标和 PWA 图标。
- `tmp/`、`scripts/out/` 与根目录 `tmp-*` 只用于可再生预览，不提交。任务结束前必须清理。
- 单个新源文件原则上不超过 2 MB；超过时先确认是否能无损压缩或只保留 alpha 母版，
  禁止同时提交绿幕图、alpha 图和运行时图三份重复像素。

## 关键架构决策

### 为什么核心逻辑要和 UI 完全隔离

三个理由，按重要性排：

1. **多 AI 协作的安全网**。不同 AI 风格差异极大，但只要 `core/` 的测试全绿，就说明游戏逻辑没被改坏。
2. **数值可批量验证**。可以写脚本模拟「一个玩家玩 30 天」，输出成长曲线图，用来调平衡 —— 这是放置游戏最重要的开发工具。
3. **将来换 UI 不用重写**。如果哪天要出 Electron 桌面版或换 UI 框架，`core/` 原封不动。

### 随机数：为什么禁用 Math.random

`src/core/rng.ts` 提供一个 seeded PRNG（推荐 mulberry32）。

- **可测试**：同一个种子必然产出同一结果，掉落测试才写得出来
- **可复盘**：玩家说「我强化 10 次全失败」，用他的种子能重现
- **将来防作弊**：接服务器校验时，服务端可以用同种子重算

每个战斗 / 强化 / 掉落实例都从全局种子派生自己的子种子。

### 存档迁移：为什么必须做

放置游戏玩家的存档就是他的全部资产。一次更新废掉存档，玩家就永久流失了。

当前代码的 `SAVE_VERSION = 17`，已经存在完整的 v0 → v17 迁移链：

| 迁移 | 新增 / 调整内容 |
|---|---|
| v0 → v1 | 减弱动效设置 `reduceMotion` |
| v1 → v2 | 关卡击杀进度 `stageKills` |
| v2 → v3 | 精品商店限购记录 `shop` |
| v3 → v4 | 装备随机胚子、强化增幅与幸运值 |
| v4 → v5 | 旅途奇遇队列 `encounters` |
| v5 → v6 | 将稳定职业标识扩展为四职业，允许新存档选择 `catkin`（喵喵） |
| v6 → v7 | 新增镜界装备回廊的每日次数与永久通关记录 |
| v7 → v8 | 新增角色奇遇关系、已完成篇章与剧情回答记忆 |
| v8 → v9 | 新增触感设置与四角色好感状态 |
| v9 → v10 | 新增词条洗练的共鸣与待确认候选结构 |
| v10 → v11 | 重标职业词条与 T5，并修复旧档非法槽位 |
| v11 → v12 | 新增周常试炼最佳成绩簿 |
| v12 → v13 | 新增装备烙印套装归属字段 |
| v13 → v14 | 新增登顶速度里程碑记录（不伪造旧档达成时刻） |
| v14 → v15 | 新增关卡首次通关时刻（不按当前时间补写历史） |
| v15 → v16 | 装备副本记录迁入 5 层深度结构，旧首通只认作 d1 |
| v16 → v17 | 新增装备永久图鉴账本，回填当前持有但不捏造已分解历史 |

加载时从 `s.version` 一路跑到 `SAVE_VERSION`。**每个迁移都要有测试。**

IndexedDB 的物理存储层另外使用独立 `envelopeVersion` 的存档信封，记录
单调 `revision`、前一版摘要与当前 payload 的 SHA-256。它不改变
`SaveData`，因此不需要为物理包装提升 `SAVE_VERSION`；旧裸存档在首次
成功保存时自动包装。校验失败时不会静默覆盖，只允许玩家显式恢复备份或
二次确认清空，并可先导出原始诊断数据。

这层使用的是公开哈希，能发现损坏和低成本直接修改，但不是服务端防作弊。
会影响他人的联机资产仍必须以服务端账本和可复算规则为准。

### 离线收益：时间戳而非计时器

存档里记 `lastActiveAt`。打开时用 `now - lastActiveAt` 计算离线时长，套用挂机产出公式一次性结算。

**不要用 setInterval 累加** —— 手机浏览器切后台会被节流，算出来的时间是错的。

**防作弊**（单机阶段象征性做，联网后严格化）：离线时长上限截断；检测系统时间回拨。

## 部署

```yaml
# .github/workflows/deploy.yml 要点
on: push: branches: [main]
steps:
  - npm ci
  - npm run verify        # lint + typecheck + test，不过不部署
  - npm run build
  - 上传 dist/ 到 GitHub Pages
```

Vite 的 `base` 要设成 `/<仓库名>/`，否则 GitHub Pages 上资源路径 404。

## npm scripts 约定

```json
{
  "dev": "vite",
  "build": "vue-tsc --noEmit && vite build",
  "test": "vitest run",
  "lint": "eslint . --ext .ts,.vue",
  "typecheck": "vue-tsc --noEmit",
  "verify": "npm run lint && npm run typecheck && npm run test",
  "sim": "tsx scripts/simulate.ts"
}
```

`npm run verify` 是**任务完成的唯一判据**。
`npm run sim` 是数值模拟器（M3 建立），调平衡靠它。
