# 53 · 竞技场奖励装备与资源清单

> 所有者需求：排行榜要有专属结算奖励装备，每日结算一次；
> 现有红色（神话）与彩虹色（心虹珍藏，好感度专属），
> 希望竞技场也有一个**更强的品质**。四个角色且可切换，需要完整资源清单。
>
> 本文档是给美术与数据实施者（codex）的清单。数值由 claude 负责。
> 承接 [`54-竞技场对战设计.md`](54-竞技场对战设计.md)。

## 零、三个先要说清楚的结论

### 1. 不需要新增品质 —— 圣器（divine）已经建好且完全空置

查证结果：`divine` 在 `src/data/constants.ts` 里**已经完整定义**：

| 项 | 值 | 对比心虹 |
|---|---:|---|
| `QUALITY_RANK` | **7** | 心虹 6 —— 已经在心虹之上 |
| `QUALITY_MUL` | **15.0** | 心虹 11.8 |
| `QUALITY_AFFIX_COUNT` | 6 | 心虹 6 |
| `QUALITY_PCT_SCALE` | **4.6** | 心虹 4.0 |
| 名称 / 前缀 | 圣器 / **圣痕·** | 心虹珍藏 / 心虹· |

**但目前一件 divine 装备都没有。**

所以「更强的品质」不用新建 —— 新建要动 `types.ts`、Zod schema、存档迁移、
以及八张品质表，收益为零。**直接把圣器这个空位填上即可。**

### 2. ⚠ 但圣器不能做成竞技场独占

`scripts/simulate.ts` 的验收锚点里已经写着：

```
{ level: 110, quality: 'divine' },
{ level: 120, quality: 'divine' },
```

**平衡模型已经假设 Lv110 以上的玩家穿的就是圣器。**
如果圣器只能从竞技场拿，那么不打竞技场的玩家在 110 级后
**永远达不到数值模型假设的水平**，主线曲线会塌。

正确做法是拆成两条路：

| 来源 | 产物 | 说明 |
|---|---|---|
| **主线** | 圣器（区域 9 产出，承 docs/44） | 保证人人可得，托住平衡模型 |
| **竞技场** | **圣痕套装** | **同数值**、独占外观、**外加竞技场内生效的套装效果** |

### 3. 竞技场的「更强」体现在哪

**不在裸数值上，而在套装效果上，且该效果只在竞技场内生效。**

这样：
- 竞技场玩家有实打实的、看得见的强度回报 ✅
- 不打竞技场的玩家在主线/挂机上**毫发无损**，不会被迫 PvP ✅
- 不会出现「最强装备只能 PvP 拿」→ 非竞技玩家退坑的经典死法 ✅

> 这条对应 doc 51 的硬约束「排行榜奖励不得含战力（否则强者愈强，墙更高）」。
> 套装效果限定在竞技场内，等于把强度关进了它自己的赛道。

## 一、圣痕套装

### 1.1 规模：第一批做 16 件

| | 数量 | 说明 |
|---|---:|---|
| 职业 | 4 | 剑姬 / 魔女 / 灵巫 / 喵喵 |
| 部位 | **4** | 武器、头冠、衣装、戒指 |
| **合计** | **16 件** | = 16 张图标 |

**为什么先做这 4 个部位**

- 武器 / 头冠 / 衣装是角色立绘上**看得见**的三层（已有换装层管线）
- 戒指是词条大件，玩家最在意
- 项链 / 手镯 / 腰带 / 鞋在外观上不可见，放第二批

**为什么不一次做 8 件**：32 张图标是心虹（40 张）级别的工作量。
4 件正好构成一个完整套装目标，玩家有明确终点，我们也能先验证机制。

第二批补齐 necklace / bracelet / belt / shoes，再 16 张。

### 1.2 等级与数值

- **装备等级锚定 110**（穿戴需求按现有 `QUALITY_LEVEL_OFFSET` 规则自动 +10）
- 基础属性、词条数（6 条，含 1 条职业专属）全部**走现有 divine 品质表**，
  **不要手填任何数值** —— 让它由 `QUALITY_MUL = 15.0` 等既有常量推导
- 词条槽位分布沿用 `affectionEquipment.ts` 里 `slotAffixKeys` 的既有约定

> 落地要求：新增 `src/data/arenaEquipment.ts`，
> 结构参照 `src/data/affectionEquipment.ts`（那是同类「非区域特殊套装」的成熟范例）。

### 1.3 套装效果（需要新增 core 能力）

⚠ **诚实说明**：`EquipmentDef.setId` 字段已存在，
但目前**没有任何套装加成的结算逻辑** ——
`equipmentSetCrafting.ts` 只是碎片合成，不是属性加成。
所以这部分是**新的 core 工作**，不是配数据就能好。

建议实现为 `src/core/equipmentSet.ts` 的纯函数，只在对决结算里调用：

| 件数 | 效果（**仅竞技场内生效**） |
|---:|---|
| 2 件 | 攻击 +8% |
| 4 件 | 攻击 +8%、减伤 +10%；**防守方额外 +5% 减伤** |

「防守方额外加成」是有意的：它让**认真攒套装的人更难被推下去**，
把套装变成排名的护城河，同时不影响他攻击别人时的强度平衡。

### 1.4 命名

前缀 `圣痕·` 由 `QUALITY_PREFIX` 自动拼接，**数据里只写本名**。

### 2.2 生产源

| 类别 | 数量 | 路径 |
|---|---:|---|
| 装备绿幕源 | 16 | `art-source/arena/<class>/<slug>-chroma.png` |
| 物品绿幕源 | 3 | `art-source/arena/<slug>-chroma.png` |
| 徽章绿幕源 | 5 | `art-source/arena/tier-<id>-chroma.png` |
| 横幅源 | 1 | `art-source/arena/arena-banner.png` |
| 提示词 | 1 | `art-source/arena/PROMPTS.md` |

单文件 ≤3MB（沿用既有生产源上限）。

### 2.3 硬性图像规范（沿用既有门禁，会被脚本卡）

- PNG 必须 **RGBA 四通道**，`hasAlpha = true`
- **四角像素 alpha 必须为 0**
- 可见主体占比 **1% ~ 82%**
- **不得残留绿幕像素**（green ≥120 且 green−red ≥60 且 green−blue ≥60 的像素数
  不得超过可见像素的 0.2%）
- 主体**不得触碰画布边缘**（否则有裁切风险）
- 全批**像素级查重**：不允许两张完全相同的占位图

> 落地要求：新增 `scripts/validate-arena-assets.mjs`，
> 照抄 `scripts/validate-reforge-assets.mjs` 的结构（严格白名单 + 上述全部检查），
> 并挂进 `npm run verify`。
> ⚠ 该脚本是**严格白名单**：多一张没登记的图也会让全项目 verify 变红，
> 加图必须同步改清单。

### 2.4 换装层（第二批再做）

武器 / 头冠 / 衣装在角色立绘上是可见图层。
若要让圣痕套装**穿在身上看得见**，还需 3 部位 × 4 职业 = **12 张换装层**。

**建议放第二批**：先出图标验证机制，换装层的对齐成本高（见 docs/35 管线）。

## 三、美术方向（给出图用）

统一意象：**竞技场的荣耀、裁决、冠冕**。与另外两条线明确区分：

| 线 | 意象 | 主色 |
|---|---|---|
| 心虹珍藏（好感） | 柔软、私密、少女心 | 粉 / 虹彩 |
| 副本套装 | 地域风物 | 各区域色 |
| **圣痕（竞技场）** | **庄严、金属、光辉、裁决** | **金 + 白 + 该职业主题色** |

四职业主题色沿用现有角色配色。共同视觉锚点：
**一枚金色「圣痕」纹样**（建议为带翼的冠冕或天平），
在四套装备上以不同形式重复出现 —— 让人一眼认出「这是竞技场的东西」。

> 这一点很重要：**独占外观是竞技场最主要的驱动力**（doc 52 已把强度关进赛道），
> 所以它必须**在缩略图尺寸下就能被认出来**。
> 参照 doc 40 关于「玩家是在扫视，不是在研究」的结论。

## 四、获取方式与定价

### 4.1 荣誉商店

| 部位 | 荣誉印记 |
|---|---:|
| 武器 | 1500 |
| 头冠 | 1200 |
| 衣装 | 1200 |
| 戒指 | 900 |
| **全套** | **4800** |

对照 doc 52 第九节的每日结算产出：

| 段位 | 每日荣誉 | 集齐全套约需 |
|---|---:|---:|
| 樱冠（前 10） | 300 + 防守 | **约 14 天** |
| 绯樱（前 100） | 200 + 防守 | 约 20 天 |
| 青樱（其余） | 50 + 防守 | 约 60 天 |

底层玩家也**一定拿得到**，只是慢。这是有意的：
**不设置「只有前 100 名才配拥有」的门槛** ——
那会让 99% 的人从第一天就放弃。

### 4.2 奖励箱内容

| 箱子 | 来源 | 内容 |
|---|---|---|
| 星辉匣 | 每日结算（全段位） | 荣誉 30~80、洗练石 ×3~8、凝晶砂 ×1~3 |
| 圣痕匣 | 每日结算（绯樱及以上） | 荣誉 120~200、洗练石 ×10、**圣痕碎片 ×1~3** |

**圣痕碎片**：40 枚可换任意一件圣痕装备 —— 给高段位玩家一条更快的路，
但**不是独占路**（荣誉直购人人可走）。

### 4.3 每日结算即时性

所有奖励在**每日 04:00 结算时直接进背包**，不需要玩家点「领取」。

> doc 40 红线：「不领取就清空」属惩罚项。
> 直接发放，玩家哪天不上线也不会损失任何东西。

## 八、一句话总结

> **圣器这个空位早就建好了，填上它就行，不用新增品质。**
> 但它不能是竞技场独占 —— 平衡模型已经假设满级玩家穿圣器。
> 竞技场的「更强」应该落在**独占外观**和**只在竞技场内生效的套装效果**上：
> 竞技玩家拿到实打实看得见的回报，不打竞技场的玩家一点不吃亏。
