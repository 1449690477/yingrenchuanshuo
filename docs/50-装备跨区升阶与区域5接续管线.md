## 一、为什么不能直接继续加区域

区域 3 / 4 已经把可玩内容扩到 120 关，但 `fine` 与 `rare` 区域材料仍缺少
跨区长期消耗端。若立刻增加区域 5，只会再次增加五种材料，把「掉了没用」
的问题继续放大。

因此顺序固定为：

1. 区域装备跨区升阶；
2. 验证材料真实扣除、装备投入完整保留；
3. 区域 5「熔岩神殿」与绯焰套；
4. 再逐区推进区域 6～8；
5. 区域 9 作为独立无尽系统施工，不冒充五个固定章节。

## 二、升阶规则

升阶只允许相邻区域的同部位、同品质装备：

| 路线 | 目标区域材料 | 金币 |
|---|---|---:|
| r1 → r2 | 蜂娘蜜 ×15、祭坛结晶 ×3 | 目标装备等级 ×200 |
| r2 → r3 | 蛛丝束 ×15、虫母之卵 ×3 | 目标装备等级 ×200 |
| r3 → r4 | 碑文拓片 ×15、永眠之泪 ×3 | 目标装备等级 ×200 |
| r4 → r5 | 祭火余烬 ×15、熔心结晶 ×3 | 目标装备等级 ×200 |

若下一地区没有同品质装备，就没有升阶目标。比如 r1 `common` 不能偷偷变成
r2 `fine`；换品质会改变词条容量，已经不是「保留投入」。

R3 / R4 已补齐 `fine / rare / epic` 各八部位及真实掉落来源。当前有效路线为
`r1 → r2` 16 条、`r2 → r3` 24 条、`r3 → r4` 24 条、`r4 → r5` 16 条，
合计 **80 个物品级选项**；内容测试同时锁定四段分布，不能用无素材定义蒙混接线。

成功时只改变 `defId`，完整保留：

- `uid`；
- 强化等级与每级固定增幅；
- 强化幸运值；
- 胚子倍率；
- 已有随机词条（包括词条自身的元素标签）；
- 洗练共鸣；
- 防分解锁定。

武器的**基础攻击元素采用目标定义**，不属于实例投入：例如 R3 炎武器升到
R4 无属性武器后，基础攻击元素明确变为 `none`。面板必须在目标元素变化时展示
前后对比，不能把“保留词条”误写成“保留旧武器基础元素”。

存在未确认洗练候选时硬拒绝升阶，不自动采用、保留或清除。计算过程不使用
RNG，也不改变存档结构，因此不增加 `SAVE_VERSION`、不写迁移。

## 三、实现分层

- `src/core/equipmentAdvancement.ts`：纯计划函数，输入装备、目标和钱包，
  返回失败原因或完整的新装备 / 新钱包；
- `src/data/equipmentAdvancement.ts`：唯一的相邻区域路线、材料和成本；
- store：纯计划成功后进入与洗练共享的付费持久化门禁，暂停实时循环并原地写回，
  **等待 IndexedDB revision/CAS 真正提交后才返回成功**；写失败或跨标签冲突
  精确回滚金币、材料、`defId` 与 RNG，零半扣、零提前战力提示；
- 第二次点击必须用来源 `defId` 防止连续跨两区重复扣费；动作签名固定为
  `advanceEquipment(uid, expectedSourceDefId): Promise<...>`。首笔写盘期间返回
  `persistence-pending`，落盘成功后过期快照返回 `source-changed`；
- UI：展示旧装 → 新装、持有 / 需要、等级条件和洗练候选硬锁原因。

核心层不读取 UI、Pinia 或存档；UI 不复制成本数字。

升阶弹层在写盘期间必须显示“正在安全写入”，禁用确认、关闭、Esc 与外侧点击；
只有 Promise 成功后才派发 `upgraded`。背包快捷入口与穿戴详情入口必须调用
同一事务，不能出现“背包能升、穿着时要先卸下”的绕路。

## 四、区域 5 原子施工口径

`docs/44` 已按运行时生成规则补成 R5 的施工输入，接入时必须同时满足：

- 品质图标不按品质重复绘制；同区域同部位共用基础图，品质由边框和特效表达；
- 区域副标题、主题色、五章 `fire` 元素和怪物原子表统一以 `docs/44` 为准；
- 每章四只普通怪，区域 5 合计 20 普通怪、3 精英、1 BOSS；5-5 精英固定为
  「熔心圣侍」，不能省略后让 BOSS 表代替精英表；
- 绯焰 6 件效果可复用既有统计项，但幽影复活、血月流血 / 回复不是只加数据，
  后续必须各自有纯函数与测试；
- 区域 9 是无尽层，不应同时计入“45 章 / 270 固定关”的固定章节总数；
- 强化推荐必须从区域 4 现行终章目标继续单调上升，R5 五章的具体强化目标与
  材料数值由真实经济模拟生成，不能继续搬用旧表或人工补一条平滑曲线。

### 4.1 已锁定的绯焰决策

- 碎片采用方案 A：全套共用 `frag_crimson`，每 40 个由玩家指定合成一件；
  不拆部位碎片，**不做 3 换 1**；
- 六个套装槽固定为
  `weapon / head / body / necklace / ring / bracelet`，腰带和鞋不计套装；
- R5 普通武器三档与绯焰套武器都为 `fire`，非武器部位不登记武器元素；
- 6 件炎爆每个真实命中用 seeded RNG 判定；炎爆走炎属性克制、炎伤与防御，
  自身不独立暴击、不吸血、不递归触发；
- 炎神官长·维斯塔不直掉绯焰整件。BOSS 的装备峰值是 R5 普通
  `legendary`，套装只通过通用碎片自选合成。

这组规则是 R5 的最终施工口径，取代 `docs/12` 中“部位碎片 + 3 换 1”的旧
通用提案，不再列为待所有者确认项。

### 4.2 碎片与数值的生成边界

`frag_crimson` 必须使用独立套装经济表，不写入 `ChapterSpec.materials`：
当前材料生成器会把 rare 区域材料只路由到 BOSS，直接复用会丢失三只真实精英
的碎片来源。独立表只注入 5-2、5-4、5-5 的真实精英与 5-5 的真实 BOSS；
不得向预生成但没有怪物引用的空表注入。

碎片和普通 `legendary` 的权重、数量、保底，以及 R5 五章强化目标与材料曲线，
全部由读取真实波次 / 击杀速度 / 离线时长 / 装备成本的数据驱动经济模拟生成。
模拟至少输出碎片 P50 / P90 / P95 成套天数、来源贡献、保底触发占比和强化收支；
P95 六件套不得超过 14 个有效日常挂机日，强化材料产出需略高于建议消耗。
超界必须非 0 退出，文档与配置都不得先拍概率再让模拟追认。

当前 `LootEntry.pityCount` 是逐物品计数。R5 的八部位普通 `legendary` 若各自
挂同一个保底，会在计数对齐时一次强制掉出多件；接入前必须增加“品质组保底”
并用单个组计数选择一件目标，不能把八个单物品保底冒充品质保底。

区域 5 原子接入时，需要同时交付数据、掉落、经济模拟、素材、移动端和资产门禁。
