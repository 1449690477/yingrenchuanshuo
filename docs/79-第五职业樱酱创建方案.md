## 三、职业定位与平衡目标

### 3.1 五职业定位一览（新增列为樱酱）

| 指标 | 剑姬 | 魔女 | 灵巫 | 喵喵 | **樱酱（预定）** |
|---|---|---|---|---|---|
| 单体 DPS | 100% | 95% | 95% | 95%⁺ | **≈98%** |
| 群体 DPS | 85% | 125% | 90% | 105% | **95%** |
| 生存能力 | 120% | 70% | 105% | 75% | **95%** |
| 离线稳定性 | 105% | 85% | 120% | 85% | **95%** |
| BOSS 战 | 110% | 100% | 90% | 115% | **110%** |

> ⚠ 2026-08-01 小尺勘误：单体 DPS 行原写「灵巫 85% / 喵喵 105%」，与
> `constants.ts` CLASS_ATK_MUL 注释的校准目标（docs/13 第四节：灵巫 95%、
> 喵喵 95% 基线 + 高暴击与技能多段形成上限）不一致，已按代码口径改正。
> 樱酱 ≈98% 来自 0.85 × 1.15 = 0.9775。**本表是锚定起点，验收只认 sim 门禁。**

**设计理由**：
- 樱酱定位「**均衡单体剑士 + 破甲斩杀**」：单体基线不超四职业带宽、上限低于喵喵（她的爆发上限来自高暴击与多段）、
  BOSS 与剑姬并列（破甲对高防 BOSS 有效）、群体比魔女弱一档但优于剑姬。
- 不给樱酱「离线稳定 120%」——那是灵巫的招牌；也不给「生存 120%」——那是剑姬的招牌。
- 斩杀机制（对低血量敌人增伤）天然利好 BOSS 收尾与推图收波，符合「BOSS 战 110%」。

### 3.2 数值骨架（写入 `CLASS_BASE_STATS` / `CLASS_GROWTH` / `CLASS_ATK_MUL`）

```
Lv1 基础：atk 15, def 6, hp 127, acc 87, eva 9, critRate 9, critDmg 50, spd 1.15
每级成长：atk +2.8, def +1.1, hp +31.1
CLASS_ATK_MUL：0.85   （× spd 1.15 ≈ 0.98，贴近 100% 单体目标）
```

- 暴击率 9%：介于剑姬 5% 与喵喵 10% 之间，靠技能堆暴（见 §四）。
- spd 1.15：低于喵喵 1.25（喵喵是攻速天花板），高于剑姬 1.0 / 魔女 0.9。
- 命中 87 / 闪避 9：略偏进攻向，生存靠技能减伤而非闪避（与喵喵的闪避流区分）。
- ⚠ 最终数值**必须**以 `npm run sim` 四层 KPS 门禁（±20%）实测为准，
  本文数字是推导起点，不是验收结论。禁止只写数字不跑模拟。

## 四、技能设计（14 个，与 docs/13 格式一致）

> 机制关键词：**剑意**（自叠层，强化下一次居合）+ **破甲**（无视防御）+ **斩杀**（低血增伤）。
> 与喵喵印记（敌人身上叠层）形成「自身资源 vs 敌方标记」的机制分叉。

**设计说明**：
- 倍率曲线对齐现有职业（低段 1.5~2.0 / 中段 2.4~3.2 / 终极 4.8）。
  ⚠ 2026-08-01 小尺勘误：原文写「终极低于魔女 5.5 与喵喵 5.2」——**代码里
  不存在 5.5 这个数**。实查 `skills.ts`：只有喵喵有完整 14 技表（终极 5.2 @Lv88）；
  剑姬/魔女/灵巫的表目前到 Lv29 就截止（魔女最大倍率 2.6），完整表在
  C3（M3-3，56 技能）队列里。**4.8 的唯一有效对标是喵喵的 5.2**，
  且喵喵终极带印记消耗增伤 —— 樱酱 4.8 + 剑意快照的实际强度必须等
  执行器落地后用 sim 验，不得以本行数字为验收依据。
- 「剑意」是自身资源：靠施法叠层、居合消耗 → 与喵喵「猫爪印记」机制完全不同，不会重复手感。
- 「斩杀」是樱酱的招牌：对低血目标增伤，配合「无我」被动形成 BOSS 收尾节奏。
- ⚠ 完整角色发布必须让所有五职业进入同一套 M3-3 / M3-4 真实技能执行与服务端复算链。
  当前生产战斗仍读取 `averageSkillMultiplier`，而原三职业各仅 3 个技能；只给樱酱启用执行器会形成
  两套规则并破坏排行公平性。因此本批必须把五职业补齐到 70 技能，统一接通状态归属、条件判断、
  多段伤害、治疗、召唤、控制、破甲、斩杀与被动修正，不能写职业特例。
- 状态条件与状态倍率必须显式区分 `self` / `primary-target`；剑意读自身，猫爪印记读目标，
  禁止执行器按职业名猜归属。`dodgeChance` 是百分点修正，必须进入统一命中结算，不能混作 `eva`。
- 樱酱数据落地时必须同时表达：燕返基础斩杀线 30% / 增伤 50%，无我把斩杀线升到 40% 且
  增伤升到 60%，剑圣之心额外提供 10% 破甲；完成前不得宣称三个招牌机制已生效。

```
kenshi_iai    offense  → 破甲（无视防御 %，固定 4.3 点基准）

kenshi_bushido sustain → 减伤 %
```

- 词条数值沿用通用池公式（基准值 × L^1.3 × 品阶 × ±3%），生成时必须传入当前职业。
- **`kenshi_iai` 必须在本批真实激活**：破甲进入 `CombatBonuses`、伤害公式、客户端与
  12 个 Edge Function 的同源链。当前 CP 只给基础 `Stats` 定价，所有 `CombatBonuses` 都不进 CP，
  不为樱酱写职业特例；它的强度由真实模拟与周常上界覆盖。P1 的 `min=max=0.59 + scalesWithLevel=true` 不能直接放行：按现有
  等级公式会在 Lv40 左右超过 100% 并继续膨胀。必须重定为固定百分比、`scalesWithLevel=false`，
  与技能破甲合并后设物理上限，再以 `npm run sim` / CP 探针定标；不得靠 UI 截断掩盖错误输入。

### 10.2 设计完整性说明
- **技能**：不是只给樱酱“开挂”；旧三职业同时补齐 56 技能缺口，五职业统一 14 技，客户端与服务端复算同源。
- **剧情**：主线、约会、日常幕间、信件、礼物和 10 件心虹装备均围绕“流浪剑士建立自己的道场与共同巡路”，不复制喵喵的宠物系口吻。
- **装备**：区域太刀、精品主题刀、副本四档居合刀、竞技“瞬樱”四件套和心虹十件套覆盖现有全部来源；装备靠打 / 商店兑换，不新增抽卡。
- **美术**：清新蓝白为主、樱粉点缀；成年娇小白发猫耳身份固定，衣装可爱但不使用未成年身份或性化幼态表达。

### 10.3 施工红线（不可违背）
1. **原子合入**：ClassId 是全局类型，`types.ts`与所有 Record<ClassId,…> 必须同批提交；否则 vue-tsc 全红。全量清单见 §七。
2. **统一解释器**：生产入口必须由唯一 `buildDefaultPlayerSkillKit` 构建技能栏；UI、挂机、试炼上界、竞技、公会与 Edge 不得各写一套。
3. **服务端同步**：改完客户端核心后必须跑 `npm run edge:build` 重打包 12 个函数（submit-trial 经 _core-entry 自动放行 kenshi；sync-profile 等相关文件释放后同窗口重部署）。**顺序必须是函数先部署、客户端后发布**——老 bundle 的 z.enum(CLASS_IDS) 会拒掉 kenshi 玩家的所有提交（先发客户端 = 樱酱玩家提交全挂）；反向无害（新 schema 兼容老职业）。
4. **破甲口径**：装备使用百分点，技能 / 被动使用小数；进入伤害公式前统一换算，相加后最多无视 80% 防御。装备词条不随等级成长，禁止 UI 截断掩盖错误数据。
5. **禁止资源回落**：运行时不得把 kenshi 映射到 catkin / swordsman；缺资产应由门禁失败暴露，不能用旧职业占位图兜底。
6. **精品店门禁**：`economy.spec.ts` 的三条价格表结构门禁（各职业总价一致 / 档位递增 / 正整数）在加 kenshi 后必须依旧全绿——它们不是 Record<ClassId>，类型系统拦不住，只有跑 verify 才会暴露。见 §七 boutique 行。
7. **验收**：`npm run verify`、`npm run sim`、副本门禁、12 Edge 构建、smoke-save 五项、迁移链 v9→v19、试炼线上审计与双尺寸浏览器巡检缺一不可。
