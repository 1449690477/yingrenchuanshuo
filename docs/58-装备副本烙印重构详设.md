## 零、采纳什么、不采纳什么、为什么

codex 先后给过两版方案：

| 版本 | 内容 | 裁决 |
|---|---|---|
| B（中间版） | 副本仍掉整装，但品质跟随当前区域掉落池、套装与品质解耦 | ❌ 不采纳。他自己说得对：「即使品质改成随机，副本仍是必须刷的第二套装备来源」 |
| **A（彻底版）** | 副本只掉材料，把主线装备**烙印**成套装件 | ✅ **采纳**，本文档全部围绕它展开 |

A 的判断标准一句话：改完后玩家看到极品掉落时想的是
**「这件胚子很好，我要做成哪一套？」**，而不是
「不是副本套装，品质再好也是垃圾」。这是整份提案里最值钱的一句。

### 命名裁决：叫「烙印」，不叫「刻印」

洗练系统已有**铭刻**（inscribe，必出本职词条）。「刻印」与「铭刻」
一字之差，玩家和代码都会混。定名：

- 系统名：**套装烙印**（imprint）
- 动词：给装备「烙上」某个套装
- 代码：`imprint` / `imprintSetId` / `core/equipmentImprint.ts`

## 一、为什么成本比看起来低：引擎已经在了

实施前核查（2026-07-30）：

- `core/equipmentSets.ts` 的 `resolveEquipmentSetBonuses` + `applyEquipmentSetStats`
  **已经完整实现**套装件数统计与效果结算，含三类特效触发器
  （命中元素伤、致死回复、暴击周期伤）—— 装备副本套装现在就在用它
- 它目前从**装备定义**读 `def.setId`（equipmentSets.ts:131）

**整个重构的核心手术只有一刀**：让结算优先读**实例**上的烙印：

```ts
const setId = instance.imprintSetId ?? definition.setId;
```

烙印后的装备自动获得套装效果、自动参与件数统计、自动触发特效 ——
零新引擎。竞技场圣痕套（docs/53）用的也是这同一个 resolver，不冲突。

## 二、烙印规则（core/equipmentImprint.ts，纯函数）

### 2.1 什么能烙、什么不能

| 判定 | 规则 | 理由 |
|---|---|---|
| ✅ 可烙 | **没有定义级 setId 的普通装备**（各区域普通掉落） | 这是主力场景 |
| ❌ 不可烙 | 定义级已带 setId 的（绯焰、圣痕、副本旧装） | 不允许吃掉既有套装身份 |
| ❌ 不可烙 | `fixedTemplate` 固定珍品（心虹珍藏） | 好感专属身份不可覆盖 |
| ❌ 不可烙 | 有待确认洗练候选的 | 与洗练互斥，防止半事务纠缠 |

### 2.2 烙印做什么、不做什么（codex 四不原则照单全收）

烙印**只写入** `imprintSetId`。**绝不**：提升品质、重置胚子、
改动词条、直接制造毕业装。品质、浮动、词条、强化全部原样保留 ——
玩家此前的洗练与强化投入 100% 保值。

### 2.3 重烙与覆盖

- 同一件装备可以**重烙**为另一套：直接覆盖旧烙印，全价收费
- 不做「烙印转移」：装备间转移养成是**继承**系统的职责，别抢

## 三、材料经济（数值，claude 负责）

### 3.1 材料表（每档 1 种 + 1 种通用，共 5 个新物品）

| 物品 | 来源 | 用途 |
|---|---|---|
| 苍蓝烙印晶 | 苍蓝副本胜利 | 烙印苍蓝套 |
| 绛紫烙印晶 | 绛紫副本胜利 | 烙印绛紫套 |
| 辉金烙印晶 | 辉金副本胜利 | 烙印辉金套 |
| 赤红烙印晶 | 赤红副本胜利（区域 7 后） | 烙印赤红套 |
| **星纹核** | 全档稀有掉落（保底） | 任意套装通用，补缺口 |

### 3.2 产出与定价

| 项 | 数值 | 推导 |
|---|---|---|
| 每次胜利掉烙印晶 | **2~3**（均值 2.5） | 每日 3 次 ≈ 7.5 晶/天 |
| 星纹核保底 | 每 **6** 次胜利必出 1 | ≈ 每 2 天 1 颗 |
| 烙印一件的成本 | **烙印晶 ×6**（或 星纹核 ×1 + 晶 ×2）+ 金币（装备等级 × 120） | ≈ 每天烙 1 件 |
| 首通奖励（每入口一次性） | 烙印晶 ×4 + 解锁该档套装图纸 | 首通日能烙起第 1 件，仍然爽 |

**节奏推导**：2 件套 ≈ 第 2 天、4 件套 ≈ 第 4~5 天、6 件套 ≈ 第 8~10 天。
套装从「解锁日毕业」变成一到两周的**流派养成线**，正好接住
docs/56 重排后「每天有明确要做的事」的空档。

- 图纸 = 解锁资格：首通该档**任意一个入口**即解锁该档套装可烙
- 多余烙印晶的出口（P2）：分解为洗练砂，接进既有消耗端

### 3.3 副本掉落表怎么改

副本战斗、每日 3 次、失败不扣次、双掉补偿逻辑**全部保留**，
只把掉落物从装备定义换成材料：

- 普通胜利：烙印晶 ×2~3（`minCount 2 / maxCount 3`）
- 星纹核走既有 pity 机制（`pityCount: 6`）
- 首通 bonus roll 保留，改掉烙印晶 ×4

## 四、套装结构调整（codex 的 2/4/6 采纳，8 件降级）

- **2 件**：基础流派效果（保持现强度）
- **4 件**：核心机制（保持现强度）
- **6 件**：进阶机制（保持现强度）
- **8 件**：**移除战斗效果**，改为称号 + 外观徽记（数据里保留字段，
  效果清空）—— 8 件战斗效果逼全员穿整套，混搭才是烙印的意义

强度先不动（codex 建议一致）：解耦后玩家穿的是「主线品质 × 套装效果」，
总强度结构变了，**改完必须重跑平衡模拟再调**（见第七节门禁）。

混搭示例（改完的目标体验）：苍蓝 4 + 绛紫 2 / 辉金 4 + 高胚散件 ×4 /
只拿苍蓝 2 触发流派机制。

## 五、存档与迁移（v12 → v13）

### 5.1 schema 改动（纯增量）

```ts
// EquipmentInstance 新增可选字段
imprintSetId?: string;   // 校验：必须是已登记套装 id
```

旧档无此字段 → 全部合法，**零改写迁移**。

### 5.2 已有副本装备怎么办（不能没收）

玩家存档里已掉落的副本整装（定义级 setId）：

- **原样保留**：可穿、可强化、可洗练，套装效果照常生效（定义级 setId 继续走原路径）
- 定义**保持注册**（严格读档要求定义存在），只从掉落表移除
- 不折算、不回收 —— docs/40 红线；它们的品质优势会被 docs/56 的
  正常节奏自然稀释，无需干预

### 5.3 UI 里的旧装标识

旧副本整装加「绝版」小标（kimi），避免玩家困惑「为什么我刷不到这件」。

## 七、验收门禁（改完必须全绿）

| 检查项 | 目标 |
|---|---|
| 副本掉落含任何装备定义 | **0**（只掉材料） |
| 烙印改变品质/胚子/词条 | **0**（有反例测试锁定） |
| 定义级 setId 装备被烙印 | **必须被拒**（反例测试） |

| 平衡脚本（新入场模型） | 胜率/时长门禁全绿 |
| `npm run sim` 全部既有门禁 | 保持全绿 |
| 2/4/6 件到手日 | ≈ D2 / D4~5 / D8~10（±2 天） |
