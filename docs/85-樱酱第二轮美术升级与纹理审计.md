## 二、纹理问题的第一性原理结论

首轮问题不是 PNG 压缩，也不是浏览器把图片变糊，而是透明边缘本身带了错误颜色：

- 多张 `*-chroma.png` 的背景并非统一 `#00ff00`，而是带光照渐变、阴影和生成模型留下的绿色噪声；
- 旧抠图把一部分边缘变成半透明，但半透明像素仍保留黑色蒙版或青绿色背景；
- 旧资产门禁主要统计不透明区域里的强绿色，无法发现“半透明但颜色错误”的边缘；
- 640×960 原图里污染只占很窄一圈，缩到战斗卡片约 160px 宽时被重采样到主体上，视觉上就变成黑点、青边和颗粒纹理。

源绿幕审计已经把这个差异量化。例如旧技能特效图集的背景风险分为 `132.8185`，
技能图标图集为 `104.4725`，基础纸娃娃为 `72.0850`；这说明旧母版不能再靠固定色差直接抠图。

本轮不做模糊、磨皮或在 UI 上遮盖问题。修复发生在唯一资产主路：先识别真实边框颜色，再生成软遮罩、去绿色溢色，
只清理半透明区域里的绿污染与近黑蒙版，最后重建标准尺寸运行时 PNG。

## 三、第二轮视觉合同

### 3.1 立绘与角色识别

- 身份：成年剑士少女，不使用未成年身份或性化幼态表达。
- 体型：娇小、轻盈，保持可爱感，但战斗姿态明确是居合剑士。
- 识别锚点：雪白长发、白色猫耳、蓝色眼睛、蓝白羽织与短裙、樱粉小面积点缀、居合太刀。
- 与喵喵区分：樱酱使用太刀、剑弧、冰霜法阵和樱吹雪；不使用肉球、爪痕和宠物式动作语言。
- 两张权威立绘：`kenshi-sakura.png` 用于创建/展示，`kenshi-sakura-cast.png` 用于战斗/剧情叠层。

### 3.2 纸娃娃与完整替换

- 所有纸娃娃输出统一为 `640×960` RGBA，脚底锚点固定在 `y=925` 附近。
- 区域武器仍按 `docs/79` 的居合佩刀锚点放置，不能漂浮，也不能退回其他职业图层。
- 区域 `r1`～`r7` 的 7 张普通整身 replacement、苍蓝/幽紫/鎏金/赤红 4 张副本 replacement，以及莓霜/月糖/绯夜 3 张精品店 replacement，均保留完整角色与衣裙，但鞋区必须与 `base-noshoes` 一致；对应的 14 组独立鞋层继续真实叠加。每一组实际鞋 mask 内 premultiplied RGB MAE 与 alpha MAE 都不得超过 `0.1`，禁止靠 `replacementIncludes` 吞掉鞋槽。
- `r5-crimson`、`r6-shadow`、`r7-bloodmoon` 三张套装 body 走套装槽位合同，不纳入普通区域无鞋裁切，避免误伤套装完整鞋型。
- 荣誉商店“瞬樱·归鞘指环”必须是右手/手腕锚点上的真实可见层：金色圣痕环 + 湖蓝剑气 + 小樱花；`alpha>20` 保持 2500–5000 像素、手腕合同区至少 900，与人物 alpha 至少相交 250 像素且占戒指自身 20%，bbox 填充率不得超过 58%，禁止退回圆形商品贴图、悬浮光盘或 `slot-only`。
- 完整替换层若发梢触顶，只允许等比缩入 2px～3px 安全边后重新对齐脚底；禁止裁掉猫耳或靠 UI `overflow` 隐藏。

### 3.3 技能表现

- 14 个技能各有独立 `256×256` 图标。
- 9 个主动技能各有独立 `512×512` 大特效，基础普攻另有 1 张居合特效。
- 战斗纸娃娃在 attack / flurry / spin / counter 使用蓝白剑弧，dash 使用横向突进剑弧，cast / spin / victory 使用冰霜法阵。
- 所有新 CSS 动效服从组件 `reduceMotion` 与系统 `prefers-reduced-motion`，不改变战斗时序或伤害结算。

## 四、可复现生产管线

### 4.1 唯一重建命令

```powershell
node scripts/build-kenshi-r2-assets.mjs --rebuild
node scripts/build-kenshi-r2-assets.mjs --check
node scripts/build-kenshi-r2-assets.mjs --source-check
```

脚本固定执行以下步骤：

1. `--rebuild` / `--source-check` 调用 Codex ImageGen 官方 `remove_chroma_key.py`；
2. 使用 `--auto-key border --soft-matte --transparent-threshold 12 --opaque-threshold 220 --despill --force`；
3. 只对半透明区域的绿色溢色和近黑蒙版做邻域颜色恢复；
4. 按角色、身体、头饰、武器、图标、特效各自合同输出；
5. `--check` 只依赖仓内透明母版重建运行资产，供 Windows/Linux 和 GitHub Actions 使用；
6. `--source-check` 从绿幕重新抠出透明母版与运行资产并逐像素比较，作为有 Codex 工具环境的发布前门禁。

`--check` 与 `--source-check` 都只比较、不写仓库；尺寸或平均绝对误差超过合同即失败。
这样 CI 不依赖个人电脑的 `.codex` 路径，同时绿幕到透明母版的上游也没有被放弃。

当前可复现范围：2 张立绘、39 张纸娃娃母版/运行时输出、1 张竞技戒指真实可穿层、2 张技能图集透明母版、
14 张技能图标、9 张主动特效和 1 张基础居合特效。

### 4.2 纹理审计命令

```powershell
node scripts/audit-kenshi-r2-assets.mjs
npm run assets:kenshi:check
```

审计输出：

- `art-source/qa/kenshi-r2-texture-audit.json`：183 项樱酱相关运行时资产的原生尺寸与 160px 显示尺寸指标，以及 46 张绿幕源的背景一致性；
- `art-source/qa/kenshi-r2-texture-audit.webp`：立绘、基础身体、区域/精品/副本身体和代表性技能资产接触表；
- `scripts/validate-kenshi-assets.mjs`：把核心 R2 资产的半透明绿边、近黑蒙版、尺寸、触边、体积、图层锚点和资源接线变成失败门禁。

这里要区分两个概念：JSON 的 `riskScore` 用于排查全角色历史资产，不是“分数越高就自动失败”；
上线门禁只使用有明确物理含义的绿边、黑蒙版、尺寸、触边、重复像素和锚点阈值，再由接触表与实机确认美术观感。
