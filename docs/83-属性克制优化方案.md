# 83 · 属性克制趣味化优化流程（参考文献驱动）

> 状态：**评审中**（2026-08-02，小灯起草；数值线小衡已给 Q1~Q5 结论，批 2 已认领）
> 老板目标：在不违背当前游戏数值基数的前提下，把属性克制做得**更有趣、更有策略**。
> 参考文献：《提瓦特元素反应机理综述》（rubbish-journal.org 上传 PDF，共 8 页，已通读）

---

## 0. 结论先行

现状一句话：**克制是一个「开战前换一次装」的静态乘区**（×1.25 / ×0.85 / ×1.00），
战斗过程中没有任何可积累、可触发、可感知的元素互动。

优化方向一句话：**把克制从「换装开关」升级为「战斗中可积累、可触发、可感知的互动层」**，
让玩家在挂机观看、试炼出招、副本配装时都有「我做了个聪明选择」的体感。

四条硬约束（老板红线，任何一版方案都不得违反）：

1. **不改克制基数**：`ELEM_ADVANTAGE=1.25 / ELEM_DISADVANTAGE=0.85 / ELEM_NEUTRAL=1.0`
   与 `ELEMENT_BEATS`（炎→冰→雷→炎）不动。
2. **不改伤害主公式**：基础伤害、防御减伤、暴击、挂机聚合、CP 战力计算不因本方案改变。
3. **不加存档字段**：所有新增状态都是**战斗期运行时状态**，`SAVE_VERSION` 不变。
4. **不加新元素**：保持炎/冰/雷/无四值三角，避免装备、词条、怪物配置大爆炸。

## 2. 参考文献提炼：五条可迁移原则

参考文献把元素互动拆成了五类反应（增幅 / 剧变 / 结晶 / 激化 / 月反应），
底层是五个可迁移的设计原则。逐条映射到本游戏：

| # | 参考原则 | 原文要点 | 本游戏迁移方式 |
|---|---|---|---|
| P1 | **双元素 + 触发顺序** | 蒸发/融化 1.5× / 2.0× 取决于谁先附着 | 攻击元素的「先后顺序」产生差异：先攒印记、后克制触发，收益高于直接克制 |
| P2 | **附着量 / 层数** | 反应强度与元素附着量、浓度正相关；激化 1:1 最佳 | 同元素连续命中积累「元素印记层数」，层数决定反应强度 |
| P3 | **能量形态分化** | 增幅=伤害；剧变=独立伤害+控制；结晶=护盾；月绽放=治疗 | 克制触发不再只是乘区：不同元素触发不同形态（炎=持续灼烧、冰=冻结、雷=麻痹） |
| P4 | **反应独立结算 + 稳定性/内置冷却** | 剧变伤害独立计算；反应有触发条件与稳定性 | 反应追加伤害走既有「追加元素伤害段」，用内置冷却（ICD）防高频白嫖 |
| P5 | **区域 / 地脉调节** | 不同区域同组合反应强度不同 | 副本/关卡「环境元素」：数据驱动的战场加减乘区，增加配装场景差异 |

## 3. 方案总览（四层，按 A → D 顺序，每层可独立交付）

```
A 感知层（纯 UI，零数值）→ B 玩法层（纯函数核心，主菜）→ C 内容层（环境/弱点数据）→ D 决策层（切装与教学）
```

每一层都有独立验收边界，可以只做 A，也可以一路做到 D；B 是「更有趣」的主体。

## 5. B 玩法层：元素印记 + 反应触发（主菜，纯函数）

### 5.1 核心设计

**元素印记（Element Gauge）**——战斗期运行时状态，**不落存档**：

```ts
// 新文件 src/core/elementGauge.ts（纯 TypeScript，零 UI）
interface ElementGauge {
  element: Element;      // 当前印记元素（fire/ice/thunder/none）
  stacks: number;        // 1~3
  decayTick: number;     // 战斗时钟过期刻度（挂机/试炼用同一时钟源）
}
```

规则（第一版，全部可复现、可单测）：

| 规则 | 内容 |
|---|---|
| G1 命中积层 | 同元素命中 +1 层（上限 3）；异元素命中 → 切换元素并重置为 1；`none` 攻击不产生印记 |
| G2 克制额外 | **克制命中的同元素命中额外 +1 层**（鼓励「对了属性再输出」） |
| G3 自然衰减 | 印记 5 秒（挂机 tick 数）未续则归零；衰减只影响层数，不影响现有伤害 |
| G4 反应触发 | 目标印记满 3 层时，下一次**同元素命中**触发「元素共鸣」，清空印记并进入内置冷却 |
| G5 内置冷却 | 每目标每元素共鸣 ICD = 2.5 秒（防高频白嫖；数值线可调） |

**共鸣效果**（能量形态分化，复用状态引擎）：

| 元素 | 共鸣形态 | 效果（第一版建议值，数值线拍板） |
|---|---|---|
| 炎 | 伤害 + 持续 | 追加一段炎元素伤害（走 `formula.ts` 追加伤害段，不暴击），并挂 1 层 `burn`（已有状态） |
| 冰 | 控制 | 追加一段冰元素伤害，并挂 `freeze` 控制（已有 control 类型） |
| 雷 | 控制 + 传导 | 追加一段雷元素伤害，并挂 `slow`（已有 control 类型） |

**为什么不动基数**：×1.25/×0.85 原样保留；共鸣只是「印记满层后的附加事件」，
主伤害链的每一笔数字都与今天完全相同；共鸣伤害单独走追加段，独立统计、独立门禁。

### 5.2 涉及文件

- 新增 `src/core/elementGauge.ts`（纯函数：`applyHitToGauge`、`resolveReaction`、`tickGauge`）
- 新增 `src/core/__tests__/elementGauge.spec.ts`（覆盖 G1~G5、三元素、ICD、衰减、与既有状态引擎联动）

## 6. C 内容层：环境元素与弱点（数据驱动）

### 6.1 环境元素（地脉）

在关卡/副本数据表增加可选字段 `environmentElement: Element | null`：

- `src/data/regions.ts` / `region34.ts` / `equipmentDungeons.ts` 逐关登记
- 效果（第一版建议）：环境中同系伤害 **+10%**、被克系 **−10%**（战斗内乘区，**不进 CP**）
- 挂机页/关卡入口显示「地脉：炎潮」小标签（接 M5-7 提示管线）

### 6.2 弱点/抗性（第二属性）

怪物/关卡数据增加 `weaknessElement: Element | null`（可选第二弱点）：

- 克制提示从「单点克制」升级为「主属性 × 弱点」双维度推荐（接 `elementMatchupPresentation.ts`）
- 第一版只做**展示与推荐**，不做第二套乘区（避免数值基数被二次放大）

### 6.3 服务端一致性红线

**凡进入战斗结算的环境乘区，必须同时进入试炼/竞技服务端复算路径**（同一份 `src/core`），
否则只允许在挂机/副本等本地模式启用，并在 UI 明示「仅本地生效」。
此条为硬门槛，避免重现今天「客户端与服务端两把尺」的事故族。

### 6.4 验收

- 数据表逐关有值/无值可复现；环境标签与战斗乘区同源（读同一常量）
- 试炼/竞技相关测试断言：环境乘区要么两侧同源、要么本地模式不参与提交
