## 二、核心公式

### 2.1 伤害公式

```
减伤率     = def / (def + K_DEF × 攻击者等级)          K_DEF = 50
命中率     = clamp(0.75 + (acc - eva) / 800, 0.55, 1.0)
暴击倍率   = 暴击时 1.5 + critDmg/100，否则 1.0
浮动       = random(0.92, 1.08)
克制系数   = 见 2.4
属性词条   = 攻击属性对应的 elemDmg 百分点；无属性或系别不符时为 0
词条减伤   = clamp(dmgReduce / 100, 0, 1)
破甲比例   = clamp(技能破甲 + 被动破甲 + armorPenetration/100, 0, 0.8)
有效防御   = def × (1 - 破甲比例)

最终伤害 = atk × 技能倍率 × (1 - 有效防御减伤率) × (1 - 词条减伤)
         × 浮动 × 暴击倍率 × (克制系数 + 属性词条/100)
保底伤害 = atk × 0.05        ← 最终伤害不得低于此值
```

**为什么这么设计**：
- 传奇原版是 `攻击(min~max) - 防御(min~max)`，会出现「防御太高完全打不动」，放置游戏里这会让玩家直接卡死。
- 改成**除法减伤**后，防御永远有收益但永不无敌，曲线平滑。
- `K_DEF = 50` 的含义：当 `def = 50 × 等级` 时减伤正好 50%。Lv60 玩家需要 3000 防御才减伤一半 —— 这个数字要靠全套紫装以上才能凑到，符合养成节奏。
- `dmgReduce` 与防御减伤相乘，不会把两个百分比直接相加；`lifesteal`
  按实际非过量伤害回复，并受最大生命限制。三类词条的落地边界见
  [`43-词条与洗练系统.md`](43-词条与洗练系统.md)。
- 破甲只改“防御”这一项，不绕过独立减伤；装备使用百分点、技能使用小数，进入公式前
  统一换算。80% 是总上限，避免装备 + 技能叠满后让防御属性彻底失效。樱酱
  `kenshi_iai` 固定基准为 4.3 个百分点、只随品阶变化，不随等级指数增长。

### 2.2 战力（CP）

战力只是给玩家看的**单一数字指标**，用来判断「能不能打过这关」。
当前公式完整覆盖基础 `Stats`，但 `dmgReduce` / `elemDmg` / `lifesteal` / `armorPenetration`
的价值取决于玩家面对的具体怪物与自身配装，尚不能诚实压成一个固定 CP 权重。
因此 CP 和“一键最优”只作粗略参考，不能替代真实战斗效率。

```
参考怪 = Lv1、无属性、普通怪（固定锚点）
DPS    = 对参考怪的单次期望伤害 × spd
EHP    = hp ÷ 参考怪对玩家的单次期望伤害
CP     = sqrt(DPS × EHP)
```

固定锚点让“升级但没换装”不会因为参考怪跟着升级而反向掉战力；命中、闪避、暴击、攻速、
攻击、防御和生命都通过同一战斗公式自然定价。`CombatBonuses` 暂不进入 CP，不允许只为某一
职业偷偷加权；它们的真实价值由模拟器、周常上界和服务端复算覆盖。战力公式版本由
`CP_FORMULA_VERSION` 标记，改输出必须新增版本，不能修改历史指纹。详见 ADR-009 与 docs/73。

**推荐战力**：每个关卡配一个 `recommendCP`，只作为玩家判断难度的参考值，
不再形成“低于 60% 就停挂”的硬墙。真实收益由下文的承伤效率 η 连续调节：
装备不足会变慢，但不会让已经投入的挂机时间归零。

### 2.3 成长曲线

> ⚠ 以下参数在 M1-10 阶段被模拟器推翻重定过一次，见 [ADR-005](32-决策记录.md)。
> **最初的 `monsterHp = 200 × L^2.3` 是错的** —— 玩家战力上限由装备决定（`L^1.35`），
> 怪物血量指数远高于它会导致差距无限拉大，Lv50 时杀一只怪要 3800 秒。

```
升级所需经验    expToNext(L)  = round(30 × L^3.25)
怪物血量        monsterHp(L)  = round(60 × L^1.45 × expectedGearFactor(L) × 怪物类型系数)
怪物攻击        monsterAtk(L) = round(4.9 × L^1.35 × 怪物类型系数)
怪物给予经验    monsterExp(L) = round(20 × L^1.55) × 怪物类型系数
怪物给予金币    monsterGold(L)= round(8  × L^1.4)  × 怪物类型系数
怪物防御        monsterDef(L) = round(4  × L^1.3)  × (BOSS 2.0 / 精英 1.4 / 小怪 1.0)
```

**指数之间的关系才是关键**，单个数字没有意义：

| 关系 | 含义 |
|---|---|
| `MONSTER_HP_POW(1.45)` + `expectedGearFactor(L)` 品质锚点 | 基础指数只比装备成长快 0.1，品质锚点再同步承接换装跳档，防止后期 TTK 随品质倍率坍塌 |
| `EXP_POW(3.25)` − `MONSTER_EXP_POW(1.55)` = 1.7 | 决定每级需要打多少只怪的增长速度 |

改任何一个都要同步检查另一个。

**怪物类型系数**：

| 类型 | hp 系数 | atk 系数 | exp 系数 | 出现频率 |
|---|---|---|---|---|
| 小怪 | 1.0 | 1.0 | 1.0 | 85% |
| 精英 | 6.0 | 1.8 | 5.0 | 14% |
| BOSS | 40.0 | 3.0 | 30.0 | 1%（或定点刷新） |

|---|---|---|---|---|
| 1 | 30 | 20 | 222 | 237 |
| 10 | 53,348 | 635 | 393 | 751 |
| 20 | 507,538 | 2,518 | 583 | 1,982 |
| 30 | 1,895,681 | 6,848 | 773 | 4,511 |
| 50 | 9,971,805 | 25,020 | 1,153 | 12,907 |

**核心健康指标：玩家当前能打的最高关，击杀单只小怪耗时（TTK）目标为 5±1.5 秒。**
TTK 失控是这类游戏最常见的死法 —— 太长玩家觉得卡，太短产出溢出。当前模拟器的
`typicalQuality` 是“到等级立刻换齐整套目标品质”的理想模型，会在品质门槛制造战力跳变，
只能验证指数与上限，**不能证明真实掉落过程的 TTK 已达标**。M2 先记录真实内容模型问题，
M5 套装落地时把模拟器改成逐件掉落/穿戴后再以此目标验收，见 ADR-010。

### 2.4 属性克制（三角）

```
炎 → 冰 → 雷 → 炎
```

| 关系 | 系数 |
|---|---|
| 克制 | ×1.25 |
| 被克 | ×0.85 |
| 无关 | ×1.00 |

**当前元素权威来源**：

- 基础攻击只读取**已穿武器定义上的 `element`**；没穿武器时合法地视为 `none`。
- `elemDmg` / `wit_elem` 只增强与攻击属性同系的伤害，绝不能反过来给无属性武器
  赋予炎 / 冰 / 雷。否则一条 `+X%` 词条会额外白送整段 `×1.25` 克制。
- 区域 1 / 4 武器显式为无属性，区域 2 / 3 武器为炎属性；精品主题提供莓果炎、
  月糖冰、蔷薇雷与纸箱无属性，装备副本提供晴蓝冰、月紫雷、琥珀炎、绯樱雷。
  所有来源都登记在静态装备定义里，禁止根据词条、名字或怪物属性猜测。
- 元素词条的生成等级不能早于真实武器来源：装备等级 Lv16 开放炎 / 冰，
  Lv20 再开放雷；Lv15 及以下的掉落和重铸候选都不会出现 `elemDmg` / `wit_elem`。
- M3-4 接入逐击技能后，技能自身声明的元素可覆盖该次技能命中；在此之前，挂机聚合模型
  使用当前武器元素。M5-7 已把同一真实关系接入关卡选择、挂机窗口与武器详情；最多三套
  预设及按关卡属性自动切换仍属于 M5-8。

这套设计的目的是**让玩家需要准备多套装备**，增加养成深度和材料消耗；但每种属性都必须
先有玩家可追溯的真实来源，不能靠 UI 文案或词条兜底伪造。`npm run sim` 也必须从
`EQUIPMENT` 选择当前等级真实可获得的元素武器；禁止在脚本里写死 `fire`。满级前任一天
不升级会直接让模拟退出非零，不能只打印警告后继续通过。

## 三、挂机与离线

### 3.1 挂机产出

```
玩家DPS = atk × spd × 平均技能倍率 × (1 - 代表怪物减伤) × 期望暴击系数
杀怪耗时 TTK = 代表怪物血量 / 玩家DPS

每场承伤 = max(0, 怪物DPS - 玩家吸血DPS) × TTK
承伤比 R = 每场承伤 / 玩家最大生命
超额承伤 R' = max(0, R - 0.25)
战斗效率 η = 1 / (1 + R')

每秒击杀数 killsPerSec = clamp((玩家DPS / 代表怪物血量) × η, 0, 关卡上限)

每秒经验 = killsPerSec × monsterExp(关卡等级)
每秒金币 = killsPerSec × monsterGold(关卡等级)
掉落     = 每次击杀独立 roll 该怪物的掉落表
```

**关卡上限**（`maxKillsPerSec`）：防止高战玩家在低级图无限刷。建议设为 `3.0`，即一秒最多 3 只。

`η=1` 表示正常战斗不损失产出；承伤越高，η 越低，但公式永远大于 0。
界面用绿 / 黄 / 橙三档显示效率，不使用红色警告或惊叹号。`canSustain`
是核心层的语义辅助：η 低于 30% 时可用于换图提示，不再阻断战斗；
当前主界面直接采用上面的 90% / 60% 三档文案。

> **当前实现边界**：挂机结算暂取第一波第一只怪作为“代表怪物”，而战场血条按真实
> 波次目标播放。未来若改为全波次加权，必须连同精英 / BOSS 材料日产一起复验，
> 不能只改视觉或只改 KPS。

### 3.2 离线结算

| 项 | 值 |
|---|---|
| 离线上限（初始） | 8 小时 |
| 离线上限（可提升至） | 12h / 16h / 24h（道具、成就、月卡） |
| 离线效率 | **100%**（不打折） |
| 结算范围 | 仅当前挂机关卡 |

**不打折的理由**：放置游戏的核心承诺是「你不在的时候我也在帮你打」。打折会让玩家产生「必须一直开着」的焦虑，反而伤留存。用**时长上限**来限制，不用效率。

### 3.3 扫荡

- **前置**：该关卡已通关
- **消耗**：体力 5 点 / 次
- **收益**：等同 30 分钟挂机产出（掉落按期望值 roll）
- **批量**：可一次扫荡 10 次

### 3.4 体力

| 项 | 值 |
|---|---|
| 上限 | 120（Lv40→150，Lv70→180，Lv100→240） |
| 恢复 | 1 点 / 5 分钟（288 点/天） |
| 每日免费领取 | 3 次 × 30 点（固定时段） |
| 溢出 | 满了不再恢复，UI 要提醒 |

日均可用体力约 **378 点 ≈ 75 次扫荡**。

## 四、强化系统

### 4.1 强化收益

```
实例绝对基础属性 = 配置表绝对基础属性
                   × (胚子倍率千分数 / 1000)
                   × 强化倍率

强化倍率 = 1 + min(已生效的逐级强化增幅之和, 1350) / 1000
```

胚子倍率只在普通掉落装备生成时随机一次，之后永久固定：

| 胚子档位 | 概率 | 千分数范围 | 玩家看到的倍率 |
|---|---:|---:|---:|
| 稳定 | 80% | 1000 ~ 1060 | 100.0% ~ 106.0% |
| 精工 | 18% | 1061 ~ 1120 | 106.1% ~ 112.0% |
| 奇迹 | 2% | 1121 ~ 1200 | 112.1% ~ 120.0% |

每次**首次成功**到达一个强化等级时，再固定该级的单级增幅：

| 强化增幅档位 | 概率 | 千分数范围 | 单级提升 |
|---|---:|---:|---:|
| 稳定 | 86% | 80 ~ 82 | +8.0% ~ +8.2% |
| 优秀 | 13% | 83 ~ 95 | +8.3% ~ +9.5% |
| 奇迹 | 1% | 110 ~ 125 | +11.0% ~ +12.5% |

- 最低档不低于旧版每级 +8%，不会因随机出现负向成长。
- 掉级后保留已经掷出的逐级增幅，重新升回该级时直接复用，不能反复重掷刷极品。
- 强化增幅之和最多按 1350 计算，因此**强化倍率上限为 ×2.35**。配合 120% 奇迹胚子时，绝对基础属性的组合上限为 ×2.82。
- 胚子和强化只放大 atk / def / hp / acc / eva 的配置表基础值；百分比基础属性与固定 / 随机词条不参与乘算。

> **旧存档兼容**：v3 装备迁移时固定写入 1000 胚子；已经拥有的每级强化写入 80，
> 尚未到达的等级写入 0，幸运桶清空。因此旧 +15 仍是 `1 + 15 × 0.08 = ×2.2`，
> 迁移前后战力不下降。

> **固定模板装备**：精品商店与其 BOSS 同款掉落使用同一确定模板，
> 获取时固定为 1000 胚子、无实例随机词条，只读取装备定义里的固定词条；
> 后续主动强化时仍按上表生成逐级增幅。

### 4.2 成功率与惩罚

| 强化等级 | 成功率 | 失败后果 |
|---|---|---|
| +1 ~ +5 | 100% | — |
| +6 | 85% | 无 |
| +7 | 75% | 无 |
| +8 | 65% | 无 |
| +9 | 55% | 无 |
| +10 | 45% | **掉 1 级** |
| +11 | 38% | 掉 1 级 |
| +12 | 30% | 掉 1 级 |
| +13 | 22% | **碎裂**（可用保护符防止） |
| +14 | 15% | 碎裂 |
| +15 | 8% | 碎裂 |

### 4.3 保底机制（幸运值）

```
每次失败：幸运值 += 100 / 当前成功率(%)  的向上取整
幸运值 ≥ 100 时：下一次强化必定成功，然后清零
```

例：+15 成功率 8%，失败一次 +13 点幸运。**连续失败 8 次必成**。

> 这条是本项目和传奇原版最大的差异，也是必须要有的现代化改良。
> 纯随机会导致极端非酋玩家直接退游，而保底让最坏情况可预期。

### 4.4 消耗

设本次要到达的目标强化等级为 `T`，装备需求等级为 `L`：

```
强化石 = T²
金币   = T² × L × 8
```

| 目标强化段 | 额外材料 |
|---|---|
| +1~+9 | 无 |
| +10~+12 | **玄铁矿** × 5 |
| +13~+15 | 玄铁矿 × 20 + **幸运九** × 1 |
| 保护符 | 防碎裂，区域最终关 BOSS / 首通产出，不设直接付费购买 |

每次合法尝试都会消耗基础材料与金币，不因失败退还。保护符只有在 +13
以上实际失败并防住碎裂时才消耗；普通成功与幸运值保底成功都不消耗。

### 4.5 章节产出与推荐强化

区域 1～2 的材料曲线集中配置在 `src/data/enhanceProgression.ts`。挂机先结算本章
`normal` 基础表，再按真实波次中的怪物类型追加 `elite` / `boss` 专属表；在线与离线
共用同一规则，离线获得的玄铁矿、幸运九和保护符必须出现在欢迎回来结算中。

| 章节 | 建议全身 | 建议主养 | 本章关键来源 |

### 4.6 一键强化安全规则

- 单件模式连续尝试到指定目标或资源不足；全身模式按槽位稳定排序，并按
  +5 → +9 → +12 → +15 里程碑逐轮均衡，避免第一件装备吃光全部资源。
- +13～+15 的非保底尝试自动使用保护符；没有保护符就停下且不推进 RNG，一键操作
  永远不会碎掉装备。手动单次强化仍保留玩家主动承担碎裂风险的选择。
- 完整结果先在克隆钱包、装备和 seeded RNG 上规划，之后只提交一次存档；单次操作
  最多 1,024 次尝试，防止异常配置占满主线程。
- 领域接口为 `autoEnhanceEquipment(uid, targetLevel)` 与
  `autoEnhanceAllEquipped(targetLevel)`；本节只定义逻辑，具体按钮布局由锻造 UI 批次接入。

### 4.7 锻造外观节点

强化节点会改变装备图标边框、辉光、粒子和角色身上的装备表现，但**不会改变装备品质、词条数或掉落表**。

| 强化等级 | 外观阶段 | 表现重点 |
|---|---|---|
| +0 ~ +4 | 原貌 `original` | 保持装备原始外观 |
| +5 ~ +8 | 微光 `gleam` | 初级描边与少量粒子 |
| +9 ~ +11 | 辉光 `radiant` | 更亮边框与持续辉光 |
| +12 ~ +14 | 星铸 `starforged` | 星屑粒子与高阶流光 |
| +15 | 樱华 `sakura` | 最高阶樱光与武器拖尾 |

## 五、平衡调参手册

当出现以下症状时，改对应参数（都在 `src/data/constants.ts`）：

| 症状 | 调什么 | 方向 |
|---|---|---|
| 前期升级太慢，新手流失 | `EXP_BASE`（30） | 小幅下调，并复验 30 天曲线 |
| 中期卡点太狠 | `MONSTER_HP_POW`（1.45）或对应 `expectedGearFactor` 锚点 | 先定位是连续斜率还是换装跳档，再只改对应参数 |
| 后期成长没感觉 | 装备品质属性跨度 | 拉大 |
| 防御属性没用 | `K_DEF`（50） | 调低到 40（防御更强） |
| 暴击流一家独大 | CP 里 `critRate` 权重 250 | 调低 / 给暴击加递减 |
| 挂机产出过剩 | `maxKillsPerSec`（3.0） | 调低到 2.0 |

**每次调参必须**：
1. 跑 `npm run sim` 输出 30 天成长曲线
2. 在 `docs/32-决策记录.md` 记一条：改了什么、为什么、预期效果

`npm run sim` 的词条样本矩阵显式覆盖普通、精良、稀有、史诗、传说、神话、心虹珍藏、
圣器全部品质，并额外在 Lv120 复验区间末端。职业平衡执行四层硬门禁：基础角色、
新鲜掉落、全 T5，以及玩家可通过定向洗练达到的“八件职业槽可达混合输出 T5”极值。
极值层会枚举同职业多种输出词条的全部可达分配，不能只测八条同 key；四层统一聚合每个样本的真实 `killsPerSecond`；
不得用“平均 η ÷ 平均 TTK”或格式化后的字符串代替，因为
`E[η / TTK] ≠ E[η] / E[TTK]`。任一层偏离均值超过 20% 时脚本必须退出非零。
