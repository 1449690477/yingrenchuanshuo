# 45 · 承伤模型与词条数值修正

> 起因：所有者在实机里发现「玩家血量归零也不会死，血条清空又回满，
> 但伤害够高照样推图」，并质疑伤害与双方血量的设计。
>
> 查下来这不是一个 bug，而是**挂机结算模型里根本没有玩家承伤这一环**，
> 由此还牵出词条数值与职业平衡的连锁问题。
>
> 本文档定义修复方案。**优先级高于 [`42`](42-关卡扩充与掉落编排.md) /
> [`44`](44-区域5至9内容规划.md) 的内容扩充** —— 那两份是加内容，
> 这份是修地基。

---

## 一、诊断

### 1.1 玩家承伤完全不参与挂机结算

`core/idle.ts` 的核心公式只有一行：

```ts
killsPerSecond = 玩家DPS / 怪物血量        // 上限 3.0
```

**玩家的防御、生命、减伤、吸血一个都没进来。** 所以：

- 堆攻击力 → 击杀更快 ✅
- 堆防御 / 生命 → **对挂机产出毫无影响** ❌

这意味着装备词条里的 `def`、`hp`、`dmgReduce` 在挂机里是**废词条**，
而挂机是本作的主体玩法。

### 1.2 血条是纯装饰

界面上的玩家血条来自 `core/battleVisual.ts` 的 `battleVitalsAtProgress`，
它按「战斗进度」投影一个血量数字**只用于显示**，
换下一只怪时 progress 归零，血条自然「回满」。

> 所有者看到的「血量归零又变满、但不会死」，就是这个投影的必然结果。
> 它不是 bug，是**展示了一个没有后果的资源** ——
> 按 [`40`](40-玩法设计透镜.md) 的可用性透镜，这比不显示更糟：
> 玩家会以为自己快死了，实际什么都不会发生。

### 1.3 「挂不住」的判断写了，但从来没接上

`core/combat.ts` 里有 `canSustain()`，注释写得很清楚：

> 玩家在一场战斗中承受的伤害如果超过血量上限的 60%，
> 就认为这张图挂不住（会死，需要吃药或者换图）

**全项目只有测试在调用它，游戏本体一次都没用过。** 它是死代码。

### 1.4 裸装生存比（实测）

| 等级 | 杀一只怪 | 被杀 | 生存倍数 |
|---:|---:|---:|---:|
| 15 | 31.6s | 2.6s | 0.08 |
| 50 | 47.9s | 1.4s | 0.03 |
| 120 | 56.1s | 1.0s | 0.02 |

裸装状态下玩家死得比杀怪快 **12～50 倍**。
装备会大幅改善这个数字，但暴露出一个结构问题：

**玩家基础生命是线性成长（`base + growth × L`），
而怪物攻击是指数成长（`10 × L^1.35`）。**
两条曲线必然发散，只能靠装备生命（也是 `L^1.35`）去接。
一旦玩家装备落后，承伤会急剧恶化 —— 这是后期最容易崩的地方。

## 二、修复方案：承伤影响效率

**所有者已拍板：不做真实死亡，改为承伤高则挂机效率下降。**

理由：真实死亡在放置游戏里是硬性打断，玩家回来发现白挂八小时，
属于 [`40`](40-玩法设计透镜.md) 红线里的惩罚性机制。
效率下降则是**软反馈** —— 玩家能感知「我太脆了」，但不会被剥夺已投入的时间。

### 2.1 模型

心智模型是「**边打边恢复，承伤越高，恢复占用的时间越多**」。

```
每场战斗承伤  = max(0, 怪物DPS − 玩家吸血) × 杀怪耗时
承伤比 R      = 每场战斗承伤 / 玩家最大生命
超额承伤 R'   = max(0, R − FREE_RATIO)          FREE_RATIO = 0.25
战斗效率 η    = 1 / (1 + R')

每秒击杀 = min(玩家DPS / 怪物血量 × η, 上限 3.0)
```

**为什么用 `1/(1+R')` 而不是线性衰减**

- 它**永远不会归零**，也永远不会为负 —— 没有硬墙，玩家再脆也还能慢慢打，
  只是很慢。这保住了「自愿参与」，玩家自己会想去换图或补装备。
- 边际收益递减自然成立：从很脆变到不那么脆收益巨大，
  从很肉变到更肉收益很小 —— 符合玩家直觉，也防止无脑堆防。
- 只有一个常数，没有分段魔法数字。

**`FREE_RATIO = 0.25` 的含义**：一场战斗承伤不超过最大生命 25% 时
**完全不损失效率**。装备正常的玩家在合适的图上感觉不到这个机制存在，
它只在「越级挂机」时才开始咬人。

### 2.2 效率曲线

| 承伤比 R | 超额 R' | 效率 η | 玩家体感 |
|---:|---:|---:|---|
| 0.10 | 0 | **100%** | 轻松，毫无损失 |
| 0.25 | 0 | **100%** | 舒适上限 |
| 0.50 | 0.25 | 80% | 略吃力 |
| 1.00 | 0.75 | 57% | 明显变慢，该换装备了 |
| 2.00 | 1.75 | 36% | 很勉强 |
| 5.00 | 4.75 | 17% | 几乎挂不动，但不会归零 |

### 2.3 这一改动带来的连锁收益

| 收益 | 说明 |
|---|---|
| **防御 / 生命 / 减伤 / 吸血立刻有用** | 它们通过降低 R 提升 η，直接影响产出 |
| **血条不再是装饰** | 可以把 η 显示在界面上（见 2.5） |
| **职业平衡自然收敛** | 灵巫的高生命终于变成产出优势（见第四节） |
| **`canSustain` 死代码有了归宿** | 改为「效率低于 30% 时给出换图提示」，不再是硬判断 |
| **词条 `dmgReduce`/`lifesteal` 有了结算入口** | [`43`](43-词条与洗练系统.md) 要求接的三条死词条，正好接在这里 |

### 2.4 必须配套的数值检查

改这个模型会让所有关卡的产出下降，**必须同步复验**：

1. 跑 `npm run sim`，确认各等级 η 落在 **0.75 ~ 1.0** 之间（正常推图时）
2. 如果大面积低于 0.75，说明**怪物攻击相对玩家生命偏高**，
   优先下调 `MONSTER_ATK_BASE`（当前 10）而不是抬玩家生命 ——
   抬生命会连带抬战力，影响推荐战力判定
3. 确认 `MONSTER_ATK_POW`（当前 1.35）与玩家装备生命成长（`ITEM_POW` 1.35）
   一致 —— 这两个指数**必须相等**，否则后期必然发散

> ⚠ 第 3 点是结构性的。当前两者都是 1.35，是对的，
> 但玩家**基础**生命是线性的，所以裸装玩家会越来越脆。
> 这是设计意图（逼玩家换装备），但要确保装备产出跟得上。

### 2.5 界面表达（交给 codex）

血条保留，但增加一行**效率**显示：

```
战斗效率 92%          ← η ≥ 0.9  绿色
战斗效率 71% · 略吃力  ← 0.6 ≤ η < 0.9  黄色
战斗效率 38% · 建议换图或提升装备  ← η < 0.6  橙色
```

**不要用红色和惊叹号。** 这是信息提示不是警告，
玩家有权选择继续在高压图里挂 —— 那是他的自由（自愿参与）。

## 三、词条数值修正（[`43`](43-词条与洗练系统.md) 的勘误）

模拟器已经在报红，三项验收全部未过。**这是我的设计失误，逐条修正。**

### 3.1 错误一：词条数量膨胀

**原设计**：把每个品质的词条槽都 +1（fine 1→2、rare 2→3、epic 3→4…）。

**后果**：新掉落装备比旧装备强 **+19.6%**（目标 ≤8%）。
即使单条期望系数只有 0.887，条数多了一条，总量还是涨。

**修正**：**只把普通品质从 0 改成 1，其余全部维持原值。**

| 品质 | 原值 | ~~43 号原方案~~ | **修正值** |
|---|---:|---:|---:|
| 普通 common | 0 | ~~1~~ | **1** ✅ 保留 |
| 精良 fine | 1 | ~~2~~ | **1** |
| 稀有 rare | 2 | ~~3~~ | **2** |
| 史诗 epic | 3 | ~~4~~ | **3** |
| 传说 legendary | 4 | ~~5~~ | **4** |
| 神话 mythic | 5 | ~~6~~ | **5** |
| 棱彩 / 神圣 | 6 | 6 | **6** |

所有者「装备全部都要加上词条」的要求由普通品质 0→1 满足，
其余品质靠**品阶**制造成长空间，而不是靠堆数量。

### 3.2 错误二：品阶期望值偏低

**原设计**期望系数 0.887，导致新掉落比旧装备弱 11%（也超出 ±8% 的门槛）。

**修正**：把品阶系数整体上调，使期望落在 **0.95** 左右。

| 品阶 | 名称 | 权重 | ~~原系数~~ | **修正系数** |
|---|---|---:|---:|---:|
| T1 | 粗糙 | 38 | ~~0.70~~ | **0.80** |
| T2 | 普通 | 28 | ~~0.85~~ | **0.92** |
| T3 | 优良 | 19 | ~~1.00~~ | **1.00** |
| T4 | 卓越 | 11 | ~~1.25~~ | **1.18** |
| T5 | 极品 | 4 | ~~1.60~~ | **1.42** |

```
修正后期望 = 0.38×0.80 + 0.28×0.92 + 0.19×1.00 + 0.11×1.18 + 0.04×1.42
           = 0.304 + 0.258 + 0.190 + 0.130 + 0.057
           = 0.939        ← 相对旧装备 −6.1%，落在 ±8% 内 ✅
全 T5      = 1.42         ← 相对新掉落 +51% 的词条区间
```

### 3.3 错误三：全 T5 目标定得不现实

**原设计**写「全 T5 战力相对新掉落 +40%~55%」。

**这个目标是错的**，因为我没有先确认词条占总战力的比例。
实测词条只占约 **20%**，所以词条内部 1.5 倍的差距，
反映到总战力上只有 **+11%~28%**。

**修正后的目标**：

| 指标 | ~~原目标~~ | **修正目标** |
|---|---|---|
| 新掉落 vs 旧装备 | ≤ 8% | **±8%**（含负向） |
| 全 T5 vs 新掉落（**总战力**） | ~~+40%~55%~~ | **+12%~25%** |
| 全 T5 vs 新掉落（**词条部分**） | — | **+50% 左右** |

> 教训写在这里：**定平衡目标前，先确认这个系统占总战力的比重。**
> 一个只占 20% 权重的系统，无论内部怎么调，都撬不动 40% 的总量。

### 3.4 错误四：职业专属词条打破平衡

**实测四职业 TTK 偏离 42.86%**（目标 ≤20%）。

**原因**：我给魔女的专属词条是 `wit_power`（攻击力，直接提升 DPS），
给灵巫的是 `sha_vitality`（生命值）——
**而生命在当前模型里对挂机产出毫无影响**（见 1.1）。
于是灵巫的专属槽等于空转，天生比魔女弱一截。

**这与第二节是同一个病根。** 修正分两步：

1. **先落地承伤模型**（第二节）。生命与防御开始影响产出后，
   灵巫的专属词条自然获得价值，偏离会大幅收敛。
2. **再复跑 sim**。若仍超 20%，按下表微调专属词条权重
   （**不要改基准值**，改权重对平衡的扰动更小）：

| 职业 | 若偏强 | 若偏弱 |
|---|---|---|
| 魔女 | 下调 `wit_power` 权重 30→25 | — |
| 灵巫 | — | 上调 `sha_vitality` 权重 30→35 |

## 四、实施顺序

```
1. 词条数量与品阶系数修正（第三节 3.1 / 3.2）
     ↓ 跑 sim，确认「新掉落 vs 旧装备」落回 ±8%
2. 承伤影响效率模型（第二节）
     ↓ 跑 sim，确认各级 η 在 0.75~1.0，四职业偏离收敛
3. 若怪物攻击偏高，下调 MONSTER_ATK_BASE
     ↓ 再跑 sim，确认 TTK 回到 5±1.5 秒
4. 界面加战斗效率显示（2.5）
5. canSustain 改为「效率低于 30% 时提示换图」
6. 接上 dmgReduce / lifesteal 的真实结算（它们的入口就在承伤公式里）
     ↓ 全部通过后，再继续 42 / 44 的内容扩充
```

**第 1 步单独就能让模拟器转绿**，可以先做、先解除对 codex 的阻塞。

| 检查项 | 目标 |

| 新掉落 vs 旧装备总战力 | ±8% 内 |
| 全 T5 vs 新掉落总战力 | +12% ~ 25% |

| 30 天成长曲线 | 无断档、满级前无停滞 |

## 六、一句话总结

> **血条必须有后果，否则它就是在骗玩家。**
> 但后果不该是「死亡」这种硬性剥夺，
> 而该是「变慢」这种玩家能自己判断、自己解决的软反馈。
