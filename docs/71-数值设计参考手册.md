## 一、核心公理（一切战斗数值的根）

1. **战斗力 = 输出 × 承受**（FC = DPS × HP；一般形式：输出对承受的积分）。
   任何一场标准战斗中，**双方战斗力之差保持不变**（网易·战斗过程守恒律）。
   推论：可直接预测胜负、剩余血量、连战续航；"血过半≈战力过半"。
2. **EHP / EDPS 抽象**（青木公）：一切防御类属性的价值 = 提高 EHP；一切攻击类属性的价值 = 提高 EDPS；
   **平砍节奏 = EHP / EDPS**。公式结构不是口味，是从"想要的属性价值性质"反解出来的：
   目标 = 每个属性对 EHP/EDPS 的**导数为常数**（价值线性稳定，消灭"越堆越赚"的边际效应）。
   护甲减伤取 `x/(x+A)` 的唯一理由：它使 EHP 对护甲**线性**（存活时间 = hp/dps × (1+armor/A)）。
3. **平衡的定义不是属性相等**，是 **生存时间A ≈ 生存时间B，容差带 0.8~1.25**（雪焰；
   本项目跨档带宽门禁 1.25×、跨职业 1.35× 与此同源）。若各职业攻防血按同一比例系数成长，生存时间不变。
4. **推荐战力与实际难度必须是同一个式子的两次读数**；所有公式统一调用同一条成长曲线 f(lvl)，
   节奏就与等级解耦（想怎么调成长斜率都不破坏平衡）。两条曲线各自漂移 = 悬崖/断层的根源
   （深度标定悬崖事故的教科书病因，见 docs/66）。
5. **兰彻斯特平方律**：n 个单位集火战斗力 ∝ n²；单挑多方获得不完全平方加成；AOE 使平方退化。
   凡是设计多打一（团本）或一打多（清怪），必须意识到规模的平方效应。
6. 时间是第四维：FC 相等 ≠ 体验相等。高输出职业 PVE 效率高，同 FC 下坦克应 PK 更强或有恢复补偿——
   **PVE 效率与 PVP 强度要分开记账**。

## 二、成长与经验曲线（先定时间，再导出一切）

行业四个独立来源（caicai / 六步法 / 雪焰 / baorile）给出同一条铁律：
**时间是根，经验是导出量。永远不要先拍经验公式再分解。**

标准推导序：
1. 拍体验锚点：等级上限、满级总时长、各等级段时长（参考：日均在线预算、总时长 600~1000 小时量级拍脑门值只允许出现在这一层）。
2. 每级升级所需**时长**曲线：常用 `(lv-1)³×k + b`（三次方主导，k 由终点总时长反解）。
3. 拍战斗节奏：杀一只同级怪的用时（含跑路回复；行业带：即时 3~8 秒/怪，ARPG 玩家 1~3 刀杀怪、怪 3~15 下杀玩家，BOSS 30 秒~5 分钟）。
4. 升级经验 = 每级时长 ÷ 单怪用时 × 单怪经验（单怪经验用线性 `lv×k+b` 即可）。
5. 数值美化：floor(x, 50/100) 取整。**检查整型上限**（int32 21 亿；本项目 Supabase 列型注意）。
6. 之后才叠：经验来源配比（杀怪:任务:其他 ≈ 6:3:1，前期任务重后期轻）、组队/双倍等扰动、付费提速空间。
- 等级差修正参考 WOW：高 4 级封顶 1.2×，低于灰名归零，中间线性递减（分母随等级变）。
- **不推荐经验消耗类设计**：玩家不消耗→超速，消耗→卡级，两头输（雪焰）。
- 升级实测速度必须与设计一致（平均+极限双卡）；上线后靠**数据采样**验证（采样需求要提前提给后端）。

## 三、战斗公式选型（没有"最好"，只有"要什么性质"）

| 结构 | 性质 | 适用 | 坑 |
|---|---|---|---|
| 减法 伤=攻-防 | 直观；攻收益递减、防收益递增；会不破防 | 小数值规模、回合 | 不破防→一夫当关；循环相克无传递性；需上下限 |
| 除法 伤=攻×(1-减免)，减免=甲/(甲+C) | 防可无限叠、上限可控、EHP 线性 | 大数值规模、长线成长 | 玩家难理解；C 要吃等级项抗膨胀（DNF: C=攻方等级×200） |
| 混合 | 各取所长 | 大多数现代游戏 | **要山寨就山寨到底**——两套体系混搭且各自半吊子是失败之源 |

- 增益连加、减益连乘（英雄无敌律）：加成连乘会爆炸，减成连加会归零。
- 多个同类破防属性必须定义**结算顺序**（LOL：%削减>定值削减>定值穿透>%穿透；削减可打成负甲、穿透不能）。
- 命中两式：`a/(a+b)`（双曲、有渐近下限）vs `(a-b)/a`（对 b 线性、会归零）——按"堆同样数值的收益曲线该长什么样"选。
  有界比值型 `基准+x/(k(x+y))` 天然防溢出（神仙道实录）。
- **离散断点效应**：少一刀杀死的临界点附近，1 点攻击的价值远超面板（星际 Zealot +1 攻=3 刀变 2 刀=150% 效率）。
  溢出伤害是纯浪费——本项目 90 秒限时同理：**限时把连续难度切成阶跃，标定用均时（连续量）不用胜率（阶跃量）**。
- 随机性三结论（网易）：加大信息量与趣味；客观上保护弱者；对游戏有利。但战斗轮次不能太少（纯赌博），
  轮次多则方差自然收敛。

## 四、概率系统（转盘/圆桌/保底/防挫败）

1. **转盘算法**：权重随便填，除以权重和自动归一化；"评估价值→反比出比重"两步法替代直接拍概率；
   多级奖励表（大类转盘→子转盘，真实概率=链乘）。
2. **圆桌算法**：优先级排列+固定空间，前排项变大把后排**挤下桌**（面板 50% 暴击在高闪避目标上远达不到 50%）。
   注意：同桌属性价值互相关联——要么接受，要么分开掷骰。技能不可闪避=把闪避排除出该次圆桌。
3. **非重置随机（牌组）**：把掷骰换成抽牌可把"连续 N 次坏运气"降一个数量级以上，且硬性封顶最坏连败。
   **小概率×大基数=必然事件**：千分之一的挫败序列在活跃服务器上每月发生几十次——尾部体验必须设计。
4. **保底/伪随机的通用形态**：概率随失败次数上升（或权重随历史再分配）+ 硬保底封顶 + 满槽后概率转移。
   多槽自平衡公式族见书库《高阶数值》篇；本项目 r5 品质组保底、深度首破必掉即此族。
5. **强化期望闭式公式**（必背，验数用）：成功率 C，
   - 失败不变：每级期望次数 = 1/C
   - 失败降 1：Y = (1 + X − C·X) / C（X 为上一级期望，递推）
   - 失败爆 0：X = (Z+1)/C − Z（Z 为至上一级的累计期望）
   任何强化/升星消耗评估先用它算理论值，再用大样本模拟对拍——两者对不上=实现有 bug。
   风险阶梯设计标杆（DNF）：+1~4 必成 / +5~7 失败降1 / +8~10 失败爆0 / +11+ 分解。

## 五、属性与装备体系（预算制，不是拍脑门制）

1. **属性池 / item budget**（暴雪）：每属性定效用值（W_x），物品等级决定预算池大小，
   装备属性组合从池里"购买"——装备千变万化不失衡。价值记账全部命名化（W_x、K_x_y），
   **公式里除 0/1 外不许出现数字字面量**（对应本项目铁律 2：数据与逻辑分离）。
2. **标准玩家模型**：一切推导基于"预期玩家最可能的状态"（=docs/65 的 expectedBuildCp）。
   模型特征参数（总减伤、总暴击、平砍击杀秒数…）集中一张表，条件：不常变、相互无逻辑关系。
   **神装/BUFF 直接加"率值"是平衡炸弹**——技能给"强度"不给"率"，率值必须可控。
3. **RaT 换算法**：Δhp/Δdps 等价比由 T_pvp、T_pve 两个体验时间反解（用体验反推属性结构，不是反过来）。
4. 装备结构参考带：品质间等比（~1.13），强化前段等差后段等比（~1.08）；
   顶配/基准的能力比是**显式设计目标**（"一个顶配打 3~4 个基准"要写出来，不是事后发现）。
   跨级锚定：上一级强 7 ≈ 下一级强 0（换装节奏的锚）。
5. 来源配比表：先定"装备总和=人物本体的 N 倍"，再按 部位×来源(基础/强化/词条/镶嵌) 分配。
   装备基础属性必须与人物攻防血**同比例**，否则生存回合数随成长单调下降（后期互秒的根源）。
   随机词条只控上限与均值；随机范围大反而不易引发不平衡感。
6. 属性量化的极限（减法系）：一劳永逸的等价换算不存在（等价关系随基础值漂移）——
   **从模拟侧解决**（列模块最大属性→伤害公式模拟生存时间→回调），不要死磕公式侧。

## 六、怪物与难度标定

1. **从体验目标反推怪属性，绝不"公式直接算怪、脱离人物"**（雪焰点名的山寨做法，必然不破防或打人太疼）：
   先定"玩家几刀杀怪、怪几刀杀玩家、该等级段可同时对付几只"，有了人物 DPS/EHP 再解怪物血攻。
2. 多人内容用**假想最优组合**估算（NPC 集火坦克、治疗补量、控制折算成免伤），非最优组合不予考虑。
3. 难度必须与玩家实际可达到的装备/养成锚定在**同一条链**上（量化阶梯 vs 连续曲线的缝隙会全部变成胜率断崖——
   深度标定事故的直接教训：装备定义是阶梯，expectedFullGearCp 是连续曲线，两者之差随深度累积成悬崖）。
4. 限时类玩法：均时是连续标定量、胜率是阶跃观测量；0% 的"整齐"是超时指纹、40~60% 的"抖动"是被打死指纹。

## 七、经济系统

1. **水池模型**：出水口大开广开（无底洞消费），进水口严防机械刷；稳货币价格调**输入**端；高位靠活动回收。
2. **产出为消耗服务**：不消耗的货币不需要产出；先定消耗目的，再开对应产出。每个成长阶段都要有个性化消耗。
3. **产出/消耗曲线交叉点 = 付费起点**，其后差值 = 付费空间（免费游戏结构）。
4. **五阶段生命周期**（东北大包子）：小农（自给自足）→小商品（必然通缩，玩家打钱自发缓解）→
   商品经济（通胀开始）→市场经济（稳定=生命尾声）→新资料片拉回小商品期，周而复始。
   **没有消耗出口的货币必然恶性通胀**（奇迹 vs WOW 修理费/绑定 的对照实验）。
5. **多轨货币隔离**（神仙道）：铜钱/元宝/声望/阅历各管一类消耗——把不同玩法的产出与消耗隔离，防互相污染。
   （本项目：金币/烙印晶/胚子/各榜积分同理，新增货币先画收支环——每种资源列全"获得途径/支出途径"成环。）
6. 收集/卡牌类：单一途径只满足 ~1/2 需求，缺口逼交互、扩展玩法或付费——三个结果都对游戏有利（妖怪online）。

## 八、工程纪律（数值的"怎么做"比"是什么"更决定质量）

1. **数值是算出来的，不是测出来的**。评价标准 = 调参循环次数（目标压到接近 1）。
   一个体系只允许存在少数几个显式"拍脑门"锚点，其余全部推导（=docs/65 单一权威口径的行业出处）。
2. 模拟器要能做到：输入装备配置→输出属性与游戏内一致到小数点；输入行为模式→输出成长/经济轨迹。
   **用错的人群测出来的绿灯比红灯更危险**（门禁人群必须与设计意图人群一致——F5 事故教训）。
3. 理论值与模拟值**双轨对拍**：期望公式算一遍、大样本跑一遍，对不上=有 bug（强化、掉落、保底都适用）。
4. 表结构预留扩展（新增职业/档位不应推倒重来）；打表=公式→数字工件（本项目：TS 数据表+生成脚本同理）。
5. 上线前想好**数据采样需求**并提给后端——"设计目的是否实现"只能靠采样验证，不能靠感觉。
6. 断言不能自证（两边引用同一公式的门禁永远绿）；只有下界的门禁等于没有上界的门禁；
   一条被调到永远能过的门禁比没有门禁更糟（虚假安全感）。——本项目今天已经吃过的三次亏，书里 2010 年就写了。
