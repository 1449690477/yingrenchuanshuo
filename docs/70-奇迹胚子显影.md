# 奇迹胚子显影（docs/66 §4.3 · UI ②）

>  把已经存在的方差**显影**，不增加任何数值。
>  只做「出了奇迹」的正向峰，绝不做负向提示（G-9 / docs/40 损失厌恶）。

## 一、这是什么

深度副本的变量奖励只有**胚子档（稳定/精工/奇迹）与随机词条**（docs/66 §3.3
的结构性保证让品质跳档不可能发生）。胚子档从第一件装备落地起就存在于
`EQUIPMENT_BASE_ROLL_TIERS`（80/18/2），但此前在结算卡里只是一个小号文字
徽标 —— 数学上有方差，扫视时看不见（docs/40 §一.4：玩家是在扫视，不是在
研究）。本批把这套既有方差翻译成演出，**一行数值都没动**。

## 二、两件半事

### 1. 掉落卡演出按胚子档升级（EquipmentDungeonReward.vue）

| 胚子档 | 演出 |
| --- | --- |
| 奇迹（2%） | 渐变金 ribbon（带 ✦ 图标）+ 金边常亮 + 两轮金色 halo + 扫面光带两轮 + 结算面板 8 颗 ✦ burst（burst 原为品质档 prize 专属，现在 miracle 同样触发） |
| 精工（18%） | 淡紫 ribbon + 紫银描边 + 一轮轻 halo（不抢奇迹的戏） |
| 稳定（80%） | **完全安静** —— 稀缺感靠对比撑起来，不是靠特效堆出来 |

- 胚子档阈值从 `EQUIPMENT_BASE_ROLL_TIERS` 的 `min` 推导，替换了原先硬编码的
  1121/1061（掉率表是唯一权威，组件只是它的读者）。
- 减弱动效：光带与 burst 不渲染、halo 全停，但金边/紫边与 ribbon 保留 ——
  「这件是好东西」的信息不丢（与既有 prize 演出同一条纪律）。
- 与品质档 prize 演出**并列且独立**：普通品质 roll 出奇迹胚子同样有完整演出
  （那同样是心跳）；奇迹卡同时是 prize 品质时以奇迹演出为准（奇迹是更稀的那刻）。

### 2. 记录留痕（DungeonDepthPanel.vue + DungeonView.vue）

页脚上方新增留痕行：**当前持有奇迹胚子 ×N**（N>0 才渲染）。

- 「往更深走 → 更容易出奇迹胚子」的因果前半句本来就可读：阶梯节点上
  稳定掉率 12/18/26/36/50% 逐层展示。留痕行补上后半句 —— 玩家自己的
  奇迹收获摆在那里。
- **持有口径**：从背包与身上推导（`baseRollPermille ≥ miracle.min`），
  行上写明「看的是背包与身上的持有数」—— 与套装图鉴（fba1fa0）同一条
  措辞纪律，不是收集史，不用屯着不敢分解。
- **N=0 整行不渲染**：「0」本身是一种嘲讽，不给（G-9 同款精神）。

### 2.5 不在本批的事（留给谁、为什么）

- **持久化收集史**（「历史上共出过多少奇迹」）：需要存档字段，而
  save/schema 在 claude-drops 的深度批次 claim 里，且 SAVE_VERSION 刚升 16。
  已在频道提出；若要做，归存档迁移档期统一排，不在 UI 批里私设。
- 掉落日志（lootLog）显示胚子档徽标：pushLog 签名不带 roll 信息，
  改签名要动 game.ts（同在 drops claim 里），本批不碰。

## 三、红线与验收

- **G-9 全文扫描**：EquipmentDungeonReward.vue 与 DungeonDepthPanel.vue
  源码不含任何负向措辞（`没出 / 未出奇迹 / 错过 / 差一点 / 空手而归 /
  运气不好`），blankReveal.spec.ts 钉死。
- 留痕行是持有口径：源码不含「收集史 / 曾经拥有 / 累计获得」。
- 阈值边界测试：`miracle.min` 是奇迹、`min-1` 是精工、`refined.min-1`
  是稳定 —— 上下各取一点，不接受手写数字。
- 挂载冒烟：奇迹卡 ribbon/光带/burst 齐；精工卡只有紫边；稳定卡全安静；
  减弱动效下动画停、信息留；留痕行 ×N 与持有说明在、N=0 不存在。
