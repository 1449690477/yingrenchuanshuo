# 12 · 装备体系

> **传奇的灵魂在装备。** 抽卡游戏的爽点是抽到，传奇的爽点是「刷了三天终于爆了」。
> 本项目所有橙色及以上装备**必须有掉落获取路径**，这是不可妥协的设计铁律。

---

## 一、部位（8 槽）

| 槽位 | 代号 | 主属性倾向 |
|---|---|---|
| 武器 | `weapon` | atk（最高权重） |
| 头冠 | `head` | acc / critRate |
| 衣裙 | `body` | def / hp（最高权重） |
| 项链 | `necklace` | atk / critDmg |
| 手镯 | `bracelet` | atk / acc |
| 戒指 | `ring` | critRate / critDmg |
| 腰带 | `belt` | def / hp |
| 鞋 | `shoes` | eva / spd |

> 传奇原版有双手镯双戒指共 10 槽。本作简化为单槽，减少界面复杂度和配置量。
> 手机竖屏上 8 槽（左右各 4）是最舒服的布局。

## 二、品质（8 级）

| 品质 | 内部代号 | 颜色 | 词条总容量 | 职业槽 | 属性系数 | 主要来源 |
|---|---|---|---:|---:|---:|---|
| 普通 | `common` | 灰白 `--q-common` | 1 | 0 | 1.0 | 小怪 |
| 精良 | `fine` | 绿 `--q-fine` | 1 | 0 | 1.5 | 小怪 / 精英 |
| 稀有 | `rare` | 蓝 `--q-rare` | 2 | 0 | 2.3 | 精英 / 副本 |
| 史诗 | `epic` | 紫 `--q-epic` | 3 | 1 | 3.6 | BOSS / 装备副本 |
| 传说 | `legendary` | 橙 `--q-legendary` | 4 | 1 | 5.8 | 区域 BOSS / 套装 |
| 神话 | `mythic` | 红 `--q-mythic` | 5 | 1 | 9.2 | 世界 BOSS / 团本 |
| 心虹珍藏 | `prismatic` | 心虹渐变 | 6 | 1 | 11.8 | 好感收藏 |
| 圣器 | `divine` | 金 `--q-divine` | 6 | 1 | 15.0 | 无尽回廊 / 合成 |

**装备基础属性公式**：

```
基础属性 = 部位基准值(等级) × 品质系数 × 部位权重
部位基准值(L) = round(6 × L^1.35)
```

例：Lv50 武器（部位权重 atk=2.0）
- 基准值 = 6 × 50^1.35 = 6 × 197 = 1,182
- 紫色（3.6）→ atk = 1182 × 3.6 × 2.0 / 10 = **851**

> 除以 10 是量纲调整系数（`ITEM_SCALE`，在 `constants.ts`）。调整整体装备强度时改这个数。

### 装备胚子（实例基础随机）

普通掉落装备生成时会固定一个不低于基准值的胚子倍率。同名、同等级、同品质的两件装备，
除了随机词条不同，配置表绝对基础属性也可能有小幅差异：

| 胚子档位 | 概率 | 千分数范围 | 基础倍率 |
|---|---:|---:|---:|
| 稳定 | 80% | 1000 ~ 1060 | 100.0% ~ 106.0% |
| 精工 | 18% | 1061 ~ 1120 | 106.1% ~ 112.0% |
| 奇迹 | 2% | 1121 ~ 1200 | 112.1% ~ 120.0% |

```
实例最终绝对基础属性 = 配置表绝对基础属性
                       × 胚子倍率
                       × 强化倍率
```

- 胚子只放大 atk / def / hp / acc / eva；critRate / critDmg / spd 与所有词条不参与胚子乘算。
- 传说及以上装备生成后必定自动锁定；奇迹胚子只有达到史诗及以上才自动锁定。
  白 / 绿 / 蓝即使摇到奇迹胚子也不永久上锁，避免低品质装备长期堆满背包。
- 精品商店与其 BOSS 同款掉落是**固定模板装备**：固定为 1000 胚子、实例随机词条为空，
  只使用装备定义里的固定词条，保证商店预览、购买实物和 BOSS 掉落完全一致，不做盲抽。

### 武器攻击元素

- `EquipmentDef` 使用按槽位判别的类型：武器必须显式填写 `element`，非武器禁止携带该字段。
- 基础攻击属性只来自当前已穿武器；无武器或无属性武器均为 `none`。
- 属性伤害词条只提供同系加成，不赋予攻击属性。无属性武器带炎伤词条仍然是无属性，
  炎武器即使没有炎伤词条也仍然是炎属性。
- 真实来源按静态定义登记：区域 2 / 3 与莓果 / 琥珀武器提供炎，月糖 / 晴蓝提供冰，
  蔷薇 / 月紫 / 绯樱提供雷；区域 1 / 4 与纸箱武器保留无属性。
- 元素词条按装备等级与来源同步解锁：Lv16 可生成炎 / 冰，Lv20 可生成雷；
  Lv15 及以下不能掉落或重铸出 `elemDmg` / `wit_elem`。
- 元素属于静态装备定义，实例存档仍只保存 `defId`，所以**元素接入本身**不需要迁移。
  当前 `SAVE_VERSION=11` 是为职业词条重标与 T5 系数变更升级，不能把两件事混为一谈。

## 三、随机词条

普通掉落装备生成时按品质容量随机抽词条，**随机词条与固定词条的 key 都不得重复**。
完整固定模板装备不生成随机词条；带部分固定词条的装备由固定词条占用总容量，
剩余槽位继续随机。也就是说，表格数字不是“固定词条之外再额外生成”的数量。
史诗及以上装备末尾保留职业槽，只从掉落时当前职业的专属池生成，保证高品质装备带有职业特色。

> ⚠ **重要**：装备属性分两类，公式不同，见 [ADR-006](32-决策记录.md)。
>
> | 类别 | 属性 | 公式 |
> |---|---|---|
> | 数值型 | atk / def / hp / acc / eva | `装备基准值 × 品质系数 × 部位权重`，**随等级 L^1.35 增长** |
> | 百分比型 | critRate / critDmg / spd | `QUALITY_PCT_SCALE × 部位权重`，**只随品质增长，与等级无关** |
>
> 百分比属性若跟着 L^1.35 缩放，Lv120 神装一把武器就能给 115% 暴击率。

### 词条品阶

同一种词条分为五档，玩家先看品阶颜色就能判断好坏，不必猜一个连续随机数是否接近上限：

| 品阶 | 名称 | 概率 | 数值系数 |
|---|---|---:|---:|
| T1 | 粗糙 | 40% | 0.62 |
| T2 | 普通 | 27% | 0.76 |
| T3 | 优良 | 18% | 0.88 |
| T4 | 卓越 | 11% | 1.10 |
| T5 | 极品 | 4% | 1.64 |

```
词条值 = 词条基准值 × 品阶系数 × (1 ± 3%)
```

新掉落与新洗练只使用已经真实结算的通用词条；`dmgReduce`、`elemDmg`、`lifesteal`
已经接入承伤与伤害管线。旧档若带有 `skillMul` 会原值保留并标注「待 M3-4」，
但它不会进入新掉落、淬炼或同调候选，只能通过重铸替换。
完整职业候选池生成职业槽时，不把整张池直接混抽：先在“输出 / 生存”两种定位中
各 50% 选择，再在该定位内按词条权重抽取。重铸则必须先排除旧 key 与同件装备已占用
的 key，再只在**剩余仍有候选**的定位间等概率选择；如果某个定位已被排空，就只从另一个
可用定位抽取，不能为了表面 50 / 50 重新放回重复或旧词条。魔女补入生存词条“星纱”，
灵巫补入输出词条“灵击”，避免职业池条数不同把某职业的高品质装备偷偷推成纯输出或纯生存。
完整数值、职业专属池与真实结算边界统一以
[`43-词条与洗练系统.md`](43-词条与洗练系统.md) 和
[`45-承伤模型与词条数值修正.md`](45-承伤模型与词条数值修正.md) 为准。

### 洗练与养成

- **重铸**：从本次未锁词条里等概率选一条，重掷类型和品阶，不再整件全部推翻。
- **淬炼**：从本次未定契且已真实结算的词条中随机选一条，只重掷品阶，
  保留词条类型与属性系别。
- **定契**：仅供重铸 / 淬炼临时锁住不想动的词条；锁 N 条的总价为
  `2^(N-1)`，即锁 0 / 1 / 2 / 3 / 4 条消耗 0 / 1 / 2 / 4 / 8 张定契符。
- **铭刻**：只能改写史诗及以上装备末尾预留的那一个职业槽，在重铸消耗外追加当前
  职业徽记；它不能改通用槽、不能新增第二个职业槽，也**不能使用定契符**。
- **同调**：玩家指定一条并消耗同调结晶，确定提升一个品阶；T5 不可继续提升。
- **共鸣保底**：随机洗练连续不出 T4+ 会积累共鸣；满 20 后下一次随机结果必为 T4 或 T5。
- **付费候选必须落档**：材料在生成候选时扣除，刷新页面后仍显示原词条和新候选；
  玩家必须主动选择「采用」或「保留原样」，系统绝不强制覆盖。生成、采用、保留都要
  等 IndexedDB 写事务完成后才向界面返回成功；写盘失败必须精确回滚本次金币、材料、
  RNG、共鸣、词条和候选，不能靠全局错误提示假装事务成功。
- 存在待决定候选的装备视为硬锁：不得分解、自动清包或进入可能碎裂的强化操作，
  直到玩家处理候选。
- 角色达到 Lv12 才开放洗练；完整固定模板和没有随机词条的旧普通装备不可洗练。

### 强化成长随机

每次首次成功到达 +1 ~ +15 的某一级时，会把该级增幅永久记录在装备实例上：

| 单级增幅档位 | 概率 | 千分数范围 | 单级提升 |
|---|---:|---:|---:|
| 稳定 | 86% | 80 ~ 82 | +8.0% ~ +8.2% |
| 优秀 | 13% | 83 ~ 95 | +8.3% ~ +9.5% |
| 奇迹 | 1% | 110 ~ 125 | +11.0% ~ +12.5% |

强化最低不会低于旧版每级 +8%。掉级时保留已经得到的增幅，重新升回不重掷；
当前强化等级以内的增幅累计最多按 +135% 计算，即强化倍率上限为 **×2.35**。
完整成功率、惩罚、幸运值和成本公式见 [`10-数值与战斗.md`](10-数值与战斗.md) 第四节。

单次尝试的基础成本由目标强化等级 `T` 与装备需求等级 `L` 决定：

```
强化石 = T²
金币   = T² × L × 8
```

+10 ~ +12 额外消耗玄铁矿 ×5；+13 ~ +15 额外消耗玄铁矿 ×20、幸运九 ×1。
保护符只在 +13 以上实际防住碎裂时消耗，成功与幸运值保底成功都不消耗。

材料来源与关卡目标不是分散硬编码：`src/data/enhanceProgression.ts` 同时定义每章的
全身 / 主养推荐强化、普通 / 精英 / BOSS 材料项、保底和六关首通奖励。精英与 BOSS
专属表按真实战斗波次结算，离线奖励也会展示高阶材料。区域 1 主目标是全身 +5、主养
+8；区域 2 主目标是全身 +9、主养 +10；+12 以上是反复刷最终 BOSS 的进阶追求。

一键强化分为两种纯事务：

- **单件连续**：指定一件装备和目标等级，直到到达目标、材料不足或 1,024 次上限。
- **全身均衡**：只处理当前穿戴，按固定槽位和 +5 → +9 → +12 → +15 里程碑轮转，
  不让第一件装备先耗尽资源。
- 冲击 +13～+15 时自动保护；非幸运保底但缺少保护符就停下且不推进 RNG，一键操作
  不允许碎装。完整计划成功后只提交一次钱包、装备和随机状态。
- 逻辑 / store / UI 已经接通；锻造 UI 只调用
  `inventory.autoEnhance()` / `inventory.autoEnhanceAll()`，由 store 转交
  `autoEnhanceEquipment()` / `autoEnhanceAllEquipped()`，不得在组件里复制循环与成本。

强化外观分为五档，并与图标、角色装备层和粒子表现同步：

| 强化等级 | 外观阶段 |
|---|---|
| +0 ~ +4 | 原貌 `original` |
| +5 ~ +8 | 微光 `gleam` |
| +9 ~ +11 | 辉光 `radiant` |
| +12 ~ +14 | 星铸 `starforged` |
| +15 | 樱华 `sakura` |

四个非原貌阶段各有一张 256×256 透明通用光环，统一由
`src/data/forgeVisuals.ts` 映射，并由 `EquipmentIcon.vue` 统一叠加。光环只叠加视觉，不改变真实装备品质、词条数量或
掉落概率；UI 不得把“樱华 +15”显示成神话 / 圣痕品质。

> **旧存档迁移**：v3 装备统一迁成 1000 胚子；已有强化等级的每一格写入 80，
> 未到达的格子写入 0，幸运桶初始化为空。这样旧装备迁移前后战力完全一致。

### 批量分解与保护

- 玩家可按白、绿、蓝、紫、橙、红、金七档品质明确选择本次批量分解范围，默认只选择白 / 绿。
- **锁定装备永不分解**，任何界面选项都不能绕过这条硬保护。
- +1 及以上强化装备默认保护；玩家必须单独开启“包含已强化装备”才会进入预览。
- 只要选择紫色及以上品质，确认按钮前必须再次勾选高品质风险提示。
- 打开分解面板时固定一份背包快照，面板打开后新掉落的装备不会混入本次操作。
- 背包超过安全容量时的自动清理只处理白 / 绿 / 蓝，并继续保护锁定装备、紫色以上装备和
  每个部位战力最高的一件。
- 减伤、吸血与三系属性伤害不强行换算成固定战力。自动清包会额外按
  “部位 × 减伤 / 吸血 / 炎伤 / 冰伤 / 雷伤”动态保留一件 T4+ 最优装备；
  先比品阶，再比词条值，再比既有装备评分。新冠军会自然替换旧冠军，不修改 `locked`，
  因而这是最多 40 个“部位 × 战斗用途”动态冠军位置。
- 基础攻击元素来自武器定义，不能被上述词条冠军代替；自动清包还会分别保留评分最高的
  炎 / 冰 / 雷武器冠军，最多再占 3 个动态位置。这里描述的是 **40 + 至多 3 个保护位置**，
  不是“背包总体最多只可超容量 43 件”；锁定、高品质、待确认候选等硬保护仍可能让背包
  超出容量，系统宁可多留也不能误删。
- 上述动态保护只约束系统自动裁剪；玩家主动批量分解仍以确认快照与手动锁定为准。

### 职业切换时的装备保护

- 四职业共享同一份账号存档和装备资产，不建立四套会分叉的等级、材料或关卡进度。
- 未填写 `classId` 的通用装备继续留在原槽；与目标职业不兼容的专属装备完整移回背包并自动锁定。
- 回包只允许改变装备位置以及必要的 `locked` 状态；UID、胚子、强化等级、强化增幅、幸运值和词条不得重掷或丢失。
- 切换事务不自动分解装备、不裁剪背包、不推进 RNG；背包已满时允许因安全回包暂时超过容量。
- 不自动从背包换上目标职业武器，避免系统替玩家覆盖穿搭选择；玩家可在切换后手动穿戴或使用一键最优。

## 四、套装

套装是**中后期的核心追求目标**，也是留存的主要抓手。

|---|---|---|---|---|

### 套装效果模板（以绯焰套为例）

| 件数 | 效果 |
|---|---|
| 2 件 | 攻击力 +8% |
| 3 件 | 炎属性伤害 +15% |
| 4 件 | 暴击率 +5% |
| 5 件 | 生命值 +12% |
| **6 件** | **【绯焰】攻击时 15% 概率附加一次 120% 攻击力的炎爆伤害** |

> 设计要点：**满件效果必须是一个「质变」而非「量变」**。
> 2~5 件给百分比属性，满件给一个有画面感的特殊机制。这是玩家愿意刷满一套的理由。

### 套装碎片与保底

- BOSS 掉落套装碎片，N 个碎片合成 1 件
- **保底**：同一 BOSS 累计击杀 30 次必掉 1 个碎片（计数存档，不可重置）
- 碎片可跨部位转换（3 换 1），解决「就差那一件」的痛苦

### 已落地：镜界装备回廊

8 个部位各有一座主题门户，每座有蓝 / 紫 / 橙 / 红 4 档，共 32 关。
四档分别在 Lv20 / 35 / 50 / 78 开放，并要求同部位前一档首通。

- 每日 3 次只在胜利领奖后扣除，失败不扣次数、不推进保底和 RNG；
- 武器与礼服按当前职业定向；其余六部位每档两款；
- 每关必掉 1 件，首次胜利额外掉 1 件；
- 通用双款连续两次缺失后触发补偿掉落；
- 首批共 80 件，四职业每一档都能穿齐 8 槽；
- 每档组成独立 2 / 4 / 6 / 8 件套，属性与平均技能倍率真实进入结算；
- 礼服使用整人替换图，武器 / 头冠 / 鞋使用独立纸娃娃层，不复用珍品商店时装。

这是解决「刷了 100 次全是不要的部位」的关键系统。完整数据、存档事务、平衡线与
168 个运行时素材的重建方式见 [`36-装备副本设计与资产管线.md`](36-装备副本设计与资产管线.md)。

## 六、装备继承（Lv80 解锁）

把旧装备的强化等级和词条转移到新装备上。

- 强化等级 100% 继承（同部位）
- 词条继承需消耗「传承石」，每条单独选择
- **目的**：让玩家敢于强化过渡装备，不会因为「以后要换」而不敢投入

## 七、内容填充清单

每个区域需要配置的装备数量：

```
每区域 × 8 部位 × 平均 4 个品质档 ≈ 32 件
9 个区域 ≈ 288 件基础装备
+ 8 套套装 × 平均 6 件 = 48 件
+ 特殊/活动装备 ≈ 60 件
────────────────────────
总计约 400 件
```

**填充时用生成器而非手写**：写一个 `scripts/genEquipment.ts`，
按区域等级 + 部位 + 品质自动生成基础属性，人工只填名字、图标、特殊效果。
