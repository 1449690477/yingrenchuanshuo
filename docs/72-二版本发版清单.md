## 三、发版顺序（依赖图）

```
②深度 UI 直连 ──┐
                 ├─→ 两个开关同批翻 true ─→ 全链复核 ─→ 二版本发布
①深度难度标定 ──┘                              │
                                                └─→（另发）③收权限迁移
```

- **①②必须同批翻开关**：任一边先出，玩家会看到半成品（烙印批次的教训）
- **③单独发**：动 RLS，出问题要能独立回滚，且要等旧客户端更新

## 四、发版当天的收尾清单

按顺序做，每条都要有**实测**而不是「应该没问题」：

1. `npm run verify` + `npm run build` + `npm run edge:build` 全绿（隔离 worktree 上跑，**不要在共享工作树跑 edge:build**）
2. 受内容影响的 Edge Function 重新部署（改过 `src/core` 或 `src/data` 就必须重打包，docs/62 教训）
3. 推 main → 等 Pages run 成功 → **抓线上 bundle 确认新代码真的在里面**（不是看工作流绿就算）
4. 线上探针：每个榜至少读一次真实行数；新函数至少验一次拒绝路径 + 一次写入路径
5. 更新 `docs/31-PROGRESS.md` 的状态表与变更日志
6. 频道 `release` 掉自己的 claim
7. **PWA 是 prompt 更新**：玩家必须点「发现新版本」才会加载新包，发版通知里要写这句

## 五、明确**不进**二版本的（防止无限扩张）

这些都有价值，但排在二版本之后。写在这里是为了让「二版本还差什么」有一个封闭的答案：

| 项 | 为什么推迟 |
|---|---|
| 体力系统失效（供给是需求的 16~20 倍，docs/65 §四） | 要动存档，且它当前不伤害玩家体验（只是形同虚设） |
| 鉴藏榜 | 前置刚刚才有（装备永久图鉴 v17 落地），数据要攒一段时间才有意义 |
| CP 暴击 / 百分比属性错价（实锤 B） | 标尺问题，影响门禁读数不影响玩家；下版本「标尺与地基专线」处理 |
| 怪物威胁轴全局漂移 | 同上，督导已记入下版本专线 |
| 秘境榜（我的分支 claude/dungeon-board） | 代码可随时合，但**写入点在深度 UI 侧**；表建好没人写就是 milestones 那个坑，等 ② 落地后再一起接 |
| 技能系统 / 宠物 / 日常任务等路线图未勾项 | 从来不在二版本范围内 |
