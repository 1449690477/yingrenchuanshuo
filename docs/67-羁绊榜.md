# 羁绊榜（docs/63 §三 · P2）——心意总榜

> 2026-07-30 · kimi-boards · 已上线
> 排期与设计出处：docs/63 §三；三条硬口径来自 claude 2026-07-30 20:39 的派活消息。

## 一、这个榜是什么

不打战斗的旅人也有自己的赛道。按**四角色心意（好感）点数之和**排名，
榜上只有这一个总数。价值不在竞争，在「让陪伴被看见」。

## 二、三条硬口径（不可偏离）

1. **按四角色之和排，不按单角色排** —— 按单角色会逼玩家「选最优角色」，
   破坏 galgame 线的自主性。
2. **不显示单角色明细** —— 谁给谁刷了多少好感是私事。
   落实方式：单角色快照只在上报载荷里存在，服务端**用完即弃不落库**；
   `profiles` 表上只有 `affection_total` 一个数，网络上不流动明细。
3. **弱化名次、强化「你陪伴了多久」** —— UI 刻意不做奖牌 / 皇冠 /
   点击查看他人；名次小号暗色，只是找到自己的锚点；陪伴卡的主数字是
   心意总值，副标题是「已累计相伴 N 次」，百分比用「超过 X% 的旅人」。

## 三、数据流

```
存档 affection.characters[职业].{points,totalInteractions,completedStoryIds}
  → stores/affectionBoard.collectClaims() 取快照
    （storyCount = completedStoryIds.length：主剧情幕与约会幕同一个列表，
      两者都走 completeAffectionStory 写入，幕数不会少报）
  → 玩家点「同步心意」（玩家主动触发，不做自动上传 —— 同 docs/51 §7 边界 3）
  → submit-affection Edge Function
  → profiles.affection_total（只升不降）
  → fetchAffectionBoard 直读 profiles（>0 降序，同分先达者在前）
```

`affection_total` 必须保持 anon 可读：它就是榜单要展示的数字本身，
与战力榜直读 `profiles.combat_power` 同一条口径。表上不存在需要遮的列
（明细不落库），所以**不做列级 revoke** —— 做了会把榜单读取路径拆掉。

## 四、反作弊（与速度榜同构：服务端无法复算，下界是唯一防线）

「你陪了她多少次」是已经过去的历史，服务端手里没有任何东西能重建它。
三层防线都在服务端，规则与客户端**同一份 core 实现**（edge:build 单源打包，
docs/61 §2.2：同一份口径不许两处实现）：

- **L1 结构白名单** —— 点数 ≤ 单角色上限、幕数 ≤ 幕数上限（常量全部从
  src/data 真实数据推导：主剧情 12 幕 + 约会 3 幕 = 15/角色），
  结构不合法 → 400。
- **L2 合理性下界** —— 互动有 4 次/角色/日硬上限，账龄 N 天的账号次数
  不可能超过 4N；心意 ≤ (min(次数, 日限×账龄) × 单次上限 18 + 幕数 × 60)
  × 余量 2。触发 → **200 + updated:false**（不写库，也不给造假者边界信息；
  真实玩家数学上不可能触到，防误伤有余量断言守着）。
- **L3 只升不降** —— 好感在游戏内只增不减，写入带
  `.lt('affection_total', nextTotal)`，更小的提交不改写，天然挡洗白。
