# 48 · 洗练系统体检与调整

> 所有者反馈：「这个洗练的推荐系统逻辑和整体逻辑还有 UI 有点问题」，
> 并把后续完善交给数值/逻辑侧决定。
>
> 本文档记录本轮查到的四个问题、各自的根因与处理，以及尚未动的部分，
> 供 codex / kimi 后续接手。数值由 claude 负责。

## 一、推荐排序无视「这件装备还穿不穿」

### 现象

工坊四个推荐位清一色「史诗 · 背包 · Lv20」，而玩家身上穿的是更高级的装备。
玩家照着推荐洗，洗的全是永远不会上身的东西。

### 根因

`priority` 由规则档位常量主导：

| 规则 | 基础分 |
|---|---:|
| 死词条 | 108 |
| 他职专属 | 96 |
| 同调 | 78 |
| 铭刻 | 68 |
| 淬炼 | 52 |
| 重铸 | 42 |

而装备本身只以 `worthScore × 0.2~0.3` 参与，其中等级又只按 `level / 10` 计入。
**Lv20 与 Lv80 的差距不到两分**，乘 0.3 之后连一分都不到。
于是「哪条规则更紧急」彻底压过「这件装备还穿不穿」。

### 处理

新增相关度模型（`src/core/reforgeAdvisor.ts`）：

- `referenceLevelOf`：以穿戴中的最高等级作为「玩家在用的装备等级」
- `relevanceOf`：
  - 穿戴中 → `1`
  - 同部位正穿着的那件不比它差 → `0`（永远不会换上去）
  - 等级不到在用装备的 **70%** → `0`
  - 其余 → `min(1, 0.45 + 等级比 × 0.35)`
- 排序分 `sortScoreOf` = `priority × relevance + (穿戴中 ? 40 : 0)`
- `relevance === 0` 的不再产出任何建议，但仍可手动选中洗练

效果：「身上这件需要同调」`78×1+40=118` 排在
「背包同级备选有死词条」`108×0.6≈65` 前面 —— **先修正在生效的装备**。

> 70% 这个门槛的取法：装备主属性按 `L^ITEM_POW` 增长，
> 落后三成等级大致等于落后一个品质档，此时无论词条洗得多好都不会换上去。

## 二、操作台与建议不同步（会让玩家白扣材料）

### 现象

卡片上写着「建议同调」、推荐横幅也写着同调，**操作页签却停在默认的「重铸」**。
玩家顺手点「洗练一次」就会做错操作，材料照扣。

### 根因

`ReforgeStudio.vue` 开局只设了 `selectedUid`，没设 `operation`，
后者始终是 `ref('reforge')` 的初值。切换装备卡片时同理。

### 处理

抽出 `adoptRecommendation()`，在两处调用：开局初始化、点选装备卡片。
同步操作与同调目标。操作页签仍在旁边，玩家想改随时能改。

## 三、共鸣值（保底）几乎摸不到

### 现象

界面常年显示「共鸣值 0 / 20」，且经常卡在某个数字不动。

### 根因

原增长表 `T1:+2 / T2:+1 / T3:0`，T4/T5 清零。
`AFFIX_TIERS` 权重 40/27/18/11/4，即 **P(T4或T5) = 15%**。

非好词条平均只推进 `1.26` 点，要**连续 16 次不出 T4/T5** 才能填满 20，
概率约 `0.85^16 ≈ 7.5%`。实测保底只贡献 **7.8%** 的 T4+ 产出 ——
玩家盯着的那条进度条基本永远填不满，还经常因为 T3 不加分而卡住。

### 处理

改为 `T1:+3 / T2:+2 / T3:+1`，**上限仍是 20**（不触动存档校验与既有迁移）。

| 增长表 | 保底占比 | 平均次数/T4+ |
|---|---:|---:|
| 原 +2/+1/0 | 7.7% | 6.23 |
| **现 +3/+2/+1** | **22.8%** | **5.37** |
| +4/+2/+1 | 29.0% | 5.02 |

选 22.8%：倒霉的人有兜底，运气好的人本来也用不上它。
且 T3 也推进进度条，**每一次不如意都看得见前进**。

> 之所以不动 `REFORGE_RESONANCE_MAX`：老存档里的 `reforgeResonance`
> 可能大于新上限，会撞 `assertResonance`，要额外写迁移。改增长表零风险。

## 四、随机洗练会误伤好词条，界面却不提示

### 现象

重铸 / 淬炼才会「从**未定契**且有合法候选的词条里随机挑一条改掉」。
一件三词条的装备只要有一条 T4，不定契就有 **1/3** 概率把它洗没。
界面原本只说「本次会从全部 3 条中随机选 1 条」，没人会自己去算这个概率。

铭刻不是第三种同构随机操作：它只改史诗及以上装备末尾预留的职业槽，不能改通用槽、
不能增加第二个职业槽，也不接受 `lockedIndices` / 定契符。因此下面的“保护好词条”
提示与定契费用只适用于重铸 / 淬炼。

### 处理

- `ReforgeRecommendation.protectIndices`：随机操作时标出该保护的词条
  （门槛 **T4**，见下）
- 界面新增橙色提示条：「本次有 **33%** 概率洗掉「暴击率」」+「定契保护」按钮
- 该按钮只设定 `lockedIndices`、刷新费用预览，**不直接花材料**；
  材料仍在玩家点「洗练一次」时才扣

> 门槛定在 T4 而不是 T3：T3 还在随机洗练的期望附近，
> 锁它等于花材料保护一条本来就容易再摇出来的词条。

## 五、小屏适配

`320×568` 实测：装饰性头部 `min-height: 128px` 吃掉 **23%** 的屏幕，
正文只剩 440px —— 推荐横幅加装备轨就占满了，洗练台要滚很久才看得到。

| 断点 | 处理 | 头部高度 | 占屏 |
|---|---|---:|---:|
| 默认 | — | 128px | 23% |
| `max-height: 700px` | 压缩内边距、缩标题、隐藏装饰星点 | 84px | 15% |
| `max-height: 560px` | 再隐藏主标题，只留身份与件数 | 62px | 13% |

四个操作卡在 320px 上各 63px 宽、齐平 84px 高、无溢出；全程无横向滚动。

另修 `.advisor-banner` 被压扁的问题：它带 `overflow: hidden`，
而 **flex item 的 `min-height: auto` 在 `overflow` 非 `visible` 时会解析成 0**，
于是能被压到远低于内容高度再自行裁掉（实测内容 197px 只渲染出 74px）。
修法是 `.studio-body > * { flex-shrink: 0 }`。

> 这条对 kimi 后续做浮层通用：**滚动 flex 列里任何带 `overflow: hidden`
> 的子块都要显式 `flex-shrink: 0`**，否则会被压扁并裁掉内容。

## 六、查证后确认「不是问题」的

- **死词条会不会一直被洗出来**：不会。`skillMul` 的 `generation` 也是
  `deferred`，新掉落与重铸候选都不会产出它，只在老存档的旧装备上残留。
  推荐引擎的「先换掉死词条」正是这批遗留装备的清理路径。

## 七、尚未处理，留给后续

1. **低档副本装备的去处**（承 [`47`](47-装备副本门槛与奖励重排.md) 第 4.2 节）：
   洗练材料可以考虑接受淘汰装备分解，让「已淘汰 77 件」有出口。
   目前这 77 件除了占背包没有任何用途。
2. **定契费用曲线** `2^(N-1)`：锁 3 条要 4 张、锁 4 条要 8 张。
   八词条装备（心虹珍藏扩到 8 槽）上锁 6 条要 32 张，可能过陡，
   等玩家实际摸到八槽装备后再看数据。
3. **推荐引擎目前不看装备的强化等级差**：`worthScore` 里 `enhance × 2`
   参与很轻。若之后强化投入变重，应把它并入相关度。
4. **构建产物用了媒体查询 Level 4 范围语法**（全项目性问题，非本次引入）：
   打包后 `@media (max-height: 700px)` 会被压缩成 `@media (height<=700px)`。
   该语法需要 Chrome 104 / Safari 16.4 / Firefox 102，**高于 Vite
   默认 target 所暗示的下限**；老浏览器会整块跳过。
   产物里已有 13 处 `width<=`、3 处 `width>=` 是同样情况，
   本次只是又多了 2 处 `height<=`。
   小屏往往正是老设备，若要照顾它们，应由构建配置负责人显式设置
   `build.cssTarget`，而不是各组件绕开写法。

## 八、2026-07-29 完整性收口

本轮继续追查了五处会让“功能看似完成、长期游玩却出错”的 P1：

1. **元素来源**：旧实现用最高 `elemDmg` 词条反推攻击元素，一条加成词条会额外白送
   整段克制倍率。现改为已穿武器定义是基础攻击元素的唯一来源；无武器 / 无属性武器
   明确为 `none`，词条只增强同系伤害。武器元素是静态定义，**元素接入本身**不需要
   迁移；当前存档升级 v11 是为词条重标，不能据此写成“存档仍是 v10”。真实来源补齐为
   莓果 / 琥珀炎、月糖 / 晴蓝冰、蔷薇 / 月紫 / 绯樱雷；生成与重铸统一按装备等级
   Lv16 开炎 / 冰、Lv20 开雷，Lv15 以下不生成元素词条。模拟器从真实装备表选武器，
   不再写死 `fire`。
2. **自动清包**：减伤、吸血、元素伤害不属于八项 Stats，旧评分会把它们当 0。
   现按“部位 × 五类战斗用途”动态保留一件 T4+ 冠军，比较顺序为品阶、词条值、
   原装备评分；不改永久锁定，形成最多 40 个动态保护位置。基础攻击元素另按炎 / 冰 /
   雷各保留评分最高的一把武器，最多再增加 3 个保护位置。这里是 **40 + 至多 3 个
   冠军位置**，不是“背包总体最多超容量 43 件”；其他硬保护仍可能让背包继续超容，
   手动分解不受影响。
3. **职业平衡假绿**：旧模拟只打印职业红表，验收函数没有判它；还使用
   “平均 η ÷ 平均 TTK”近似真实产出。现直接聚合样本 `killsPerSecond`，让通用随机
   跨职业配对；前三层样本覆盖普通到圣器，八件职业槽可达混合输出 T5 极值层覆盖
   史诗到圣器，并统一在 Lv120 复验。四层分别硬判基础 / 新掉落 / 全 T5 / 可达混合
   输出 T5 极值；极值会枚举同职业全部输出词条分配，
   不能只测八条同 key。
4. **存档重标**：T5 系数改为 1.64，职业输出基准改为 `swd_heavy=27`、
   `wit_power=0.53`、`wit_elem=4.3`、`sha_spirit=0.84`、`cat_swift=0.027`。
   v10→v11 按比例迁移四条旧职业词条、全部 T5 与待确认候选，不重掷 RNG；existing
   保留发布版已接受的有限历史值，不夹洗到后来新增的随机区间；随机 pending 候选才投影
   到当前可生成边界，同调候选基于迁移后的目标值和新相邻品阶比例精确复算。
   旧错槽 / 超额职业词条会保留最优一条到预留末槽，其余按同品阶、同百分位转为通用
   词条并退对应职业徽记。pending 跟随原目标身份，跨槽型重铸候选同步转换到新合法池。
   迁移前按发布版 v10 冻结 schema 和 235 项装备 ID 白名单严格验证；非法重复 key /
   未知字段 / 非有限值 / 非法候选不会被归一化后退款，但 existing 不误套候选掷骰范围；
   转换与换位后按当前结果重算占用 key，避免已消失的职业 key 继续形成幽灵占用。
   v10 曾允许的 equipped 外层错槽会在 v11 收紧校验前无损移回背包；目标槽已占或多个
   错槽并存时也只回包，不覆盖正确穿戴。
5. **持久化真事务**：旧 store 在 `void persist()` 后立刻返回成功，IndexedDB 失败时
   刷新会倒退。现在候选生成、采用、保留都等待真实写事务；等待中暂停 tick 并拒绝并发，
   写失败精确回滚金币、材料、RNG、共鸣、词条与 pending。存档结构校验错误仍直接抛出，
   不伪装成浏览器存储故障；大背包写入先 `toRaw`，但仍由 Zod 完整校验和克隆。
   前后台恢复在事务结束后只结算一次；IDB revision/CAS 拒绝跨标签旧快照覆盖或旧页
   清档，冲突页会停机并提示刷新。重开角色事务会隔离旧内存档并门禁保存 / 导入 / 新建 /
   恢复，清档墓碑之后没有迟到旧快照；隐藏状态下完成初始化也不会启动 rAF，回前台只恢复
   一条循环，重复 pagehide 不改写首次离线起点。

完整职业候选池同时改成“输出 / 生存定位先各 50%，定位内再按权重”，新增魔女星纱
与灵巫灵击。重铸先排除旧 key 和同件已占用 key，再只在剩余有候选的定位中抽取；
某定位耗尽时只抽另一个定位。最终模拟：普通 0→1 条单列为 +14.85%～+15.86%；
精良以上新掉落战力 −4.40%～+2.50%，全 T5 +12.46%～+24.69%，
Lv50 TTK 5.07～5.33 秒；η 新掉落 0.768～1.000、全 T5 0.873～1.000；
四层职业最大偏离 15.72% / 13.73% / 17.80% / 18.03%，全部通过正式门禁；
30 天模型到 Lv118，满级前任何一天停滞都会让脚本直接失败。
## 九、2026-07-30 装备窗口层级收口

旧结构允许装备详情继续挂载 `ReforgePanel` 与 `EquipmentAdvancementPanel`；从装备副本奖励进入时会形成“战斗 → 详情 → 操作台”三层窗口。现改为：

- `EquipDetail` 只发出携带 UID 的洗练 / 升阶请求，不再拥有任何养成面板；
- 背包、养成、挂机页先关闭详情，再打开唯一的 `ReforgeStudio` 或升阶台；
- 洗练坊支持按 UID 初始化，待确认候选仍在原操作台内展示，按钮明确为“保留原词条 / 替换为新词条”；
- 副本奖励详情隐藏深层养成入口，防止出现第三层窗口；
- 390×844 与 320px 实测均只有一个 `aria-modal`，无页面或面板横向溢出，触控按钮不小于 44px；
- 不修改洗练成本、概率、随机、事务或存档，`SAVE_VERSION` 保持 v12。

同时将 Vitest worker 固定为 2，并给 144 张怪物图逐像素审计独立 15 秒预算，避免多个 Sharp/libvips 资产测试并行争抢原生内存；断言内容保持不变。
