# 02 · 数据表规范

> 所有游戏内容都写在 `src/data/` 下的 TypeScript 文件里。
> **用 TS 而不是 JSON**，因为类型检查能在编译期拦住填错的字段 —— 这对多 AI 协作至关重要。

---

## 通用约定

- ID 命名：`<类型>_<区域>_<序号>`，全小写下划线，例：`mon_5_12`、`eq_weapon_5_epic_01`
- 所有数值字段用**基准值**，实际值由公式计算，不要预先算好填进去
- 每个表导出一个 `Record<string, T>`，key 即 id
- 新增内容**只加不改**，改已有 id 的数值属于平衡调整，要在 `32-决策记录.md` 记录

## Monster（怪物）

```ts
export interface Monster {
  id: string;
  name: string;                          // 「熔岩卫娘」
  level: number;
  type: 'normal' | 'elite' | 'boss';     // 决定属性系数，见 docs/10
  element: 'fire' | 'ice' | 'thunder' | 'none';
  hpMul?: number;                        // 类型系数之上的微调，默认 1.0
  atkMul?: number;
  expMul?: number;
  lootTableId: string;
  sprite: string;                        // 'assets/monsters/mon_5_12.png'
  skills?: string[];                     // 怪物技能 id，可空
  desc?: string;                         // 图鉴描述
}
```

**填写规则**：
- `hpMul`/`atkMul` 只在需要单独调整某只怪时填，**默认不填**，靠 type 系数
- BOSS 必须填 `desc` 和 `skills`
- `level` 决定基础属性，跟着所在关卡走

## Equipment（装备）

```ts
export interface EquipmentDef {
  id: string;
  name: string;
  slot: 'weapon' | 'head' | 'body' | 'necklace' | 'bracelet' | 'ring' | 'belt' | 'shoes';
  quality: 'common' | 'fine' | 'rare' | 'epic' | 'legendary' | 'mythic' | 'divine';
  level: number;                         // 需求等级，也是属性基准
  element?: 'fire' | 'ice' | 'thunder';
  setId?: string;                        // 属于哪个套装
  icon: string;
  fixedAffixes?: Affix[];                // 固定词条（套装件常用）
  uniqueEffect?: string;                 // 金色装备的专属效果描述
}
```

**基础属性不填** —— 由 `level × quality系数 × slot权重` 自动算出（见 `docs/12`）。

## Skill（技能）

```ts
export interface Skill {
  id: string;
  name: string;
  class: 'swordsman' | 'witch' | 'shaman';
  type: 'active' | 'passive';
  element: 'fire' | 'ice' | 'thunder' | 'none';
  unlockLevel: number;
  baseMultiplier: number;                // 主动技能倍率；被动填 0
  perLevelMultiplier: number;            // 每级增幅，通常 0.06
  cooldown: number;                      // 秒；被动填 0
  targets: number;                       // 1=单体, 0=全体, N=N个目标
  passiveEffect?: PassiveEffect;         // 被动效果
  effect?: SkillEffect;                  // 附加效果（灼烧/眩晕/中毒等）
  priority: number;                      // 自动释放优先级，数字越大越优先
  icon: string;
  desc: string;
}
```

## Stage（关卡）

```ts
export interface Stage {
  id: string;
  chapterId: string;
  name: string;
  level: number;
  waves: Wave[];                         // 每波怪物
  bossId?: string;                       // 章节最后一关填
  recommendCP: number;                   // 由 sim 脚本生成，不要手填
  firstClearRewards: Reward[];
  lootTableId: string;
  maxKillsPerSec: number;                // 默认 3.0
  element: 'fire' | 'ice' | 'thunder' | 'none';
}

export interface Wave {
  monsters: { id: string; count: number }[];
}
```

关卡背景不再重复写进 `Stage`。它属于章节配置 `ChapterSpec`：

- `mapAsset`：768 × 1024 竖版章节封面，用于关卡选择和当前章节条；
- `battleAsset`：1536 × 1024 横版战场，用于人物与怪物实际战斗的场景画布。

两个字段都必须显式配置并由内容测试检查文件；禁止相互兜底，否则纵版封面被横向裁切时会掩盖缺图。

## LootTable（掉落表）

```ts
export interface LootTable {
  id: string;
  entries: LootEntry[];
  guaranteed?: LootEntry[];              // 必掉
}

export interface LootEntry {
  itemId: string;
  weight: number;                        // 权重，不是概率
  minCount: number;
  maxCount: number;
  pityCount?: number;                    // 保底：累计 N 次未掉则必掉
}
```

**权重制而非概率制的原因**：加新掉落物时不用重新调整所有概率使其和为 1。
实际概率 = `weight / 所有 weight 之和`。

## 填表工作流

1. 先在对应设计文档（`11`/`12`/`13`）里确定内容
2. 用生成脚本产出骨架：`npm run gen:equipment -- --region 5`
3. 人工补名字、图标、特殊效果、描述
4. 跑 `npm run verify` 确认类型没错
5. 跑 `npm run sim` 确认没有破坏数值曲线

**永远不要手写 300 条装备数据。** 写生成器，人工只补需要创意的部分。
