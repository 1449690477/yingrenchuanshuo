## 二、数据只维护一份

`src/data/region34.ts` 是这两个区域在制作阶段的内容清单，集中登记：

- 两个区域与十章的名称、等级、属性、教程和场景路径；
- 47 只怪物的稳定 ID、显示名和动作性格；
- 八种材料的档位、售价、来源和描述；
- 两套装备的八部位名称与视觉关键词。

`regions.ts` 接入后，现有生成器继续负责关卡、怪物和掉落表。禁止手写 60 个
关卡或逐只复制数值，这样后续区域 5～9 仍能复用同一条管线。

### 波次规则

- 普通关：三波小怪；
- 有精英的第 3 / 6 关：两波小怪 + 精英；
- 最终 BOSS 关：两波小怪 + 精英 + BOSS；
- 只有在真实存在精英或 BOSS 时才让出普通波，不能仅凭「第 3 / 6 关」
  把三波误缩成两波。

## 三、区域材料来源

来源契约由 `src/data/materialSources.ts` 统一定义：

| 怪物类型 | 允许掉落的区域材料档位 | 单次数量 |
|---|---|---:|
| 普通怪 | `common` | 1～2 |
| 精英 | `fine` | 1～3 |
| BOSS | `rare` | 3～6 |

掉落生成器必须先按档位筛选章节材料，再建立对应怪物表。未知材料直接报配置
错误；禁止把章节里的全部材料同时塞进普通、精英和 BOSS 表，否则玩家无法从
物品档位判断该去刷谁。

八种材料各自使用独立透明图标，普通、进阶、稀有三档用轮廓、亮度和宝石感
形成明显层级，不靠同图换色冒充新掉落。

## 四、美术清单与重建

唯一清单是 `scripts/region34-assets-manifest.mjs`，运行时共 **117 项**：

| 类别 | 数量 | 运行时规格 |
|---|---:|---|
| 区域总览 + 章节封面 | 12 | 768×1024 WebP |
| 挂机战场 | 10 | 1536×1024 WebP |
| 怪物 | 47 | 512×512 透明 WebP，脚底锚点 y=503 |
| 材料图标 | 8 | 256×256 透明 PNG |
| 装备图标 | 16 | 256×256 透明 PNG |
| 四职业换装层 | 24 | 640×960 透明 PNG，同画布叠加 |

所有 ImageGen 原图、透明母版和提示词均保留在 `art-source/`。117 个稳定键
分别对应 117 次独立生成，源图与运行图都禁止像素重复。运行时资产只能由
归档母版确定性重建：

```bash
node scripts/build-region34-assets.mjs
node scripts/validate-region34-assets.mjs
node scripts/build-region34-contact-sheets.mjs
```

门禁会检查提示词稳定键、精确数量、格式、尺寸、体积、四角透明、绿幕残留、
怪物脚底锚点，以及 117 张源图和 117 项运行资产的像素重复。联系表同时检查
地图差异、怪物身份、材料稀有度、装备部位和四职业整套叠装，不能只看单张
原图就宣告完成。

## 五、加载策略

地图、战场、怪物、装备和换装层属于后续区域的大体积内容，不进入 PWA 首次
预缓存；玩家进入相关页面时使用 `CacheFirst` 下载并保留 30 天。八张材料小图
仍随主包缓存，掉落弹窗第一次出现时不会临时破图。

这只改变下载时机，不改变资源路径；离线玩过一次的区域仍可继续使用缓存。

## 六、原子接入顺序

新区域必须按下面顺序在同一个可验证提交中启用：

1. 八种 `ITEMS`；
2. 两个区域的装备主题和 48 件生成装备；
3. 十章强化成长配置；
4. 区域材料来源分层与稀有材料保底；
5. 怪物视觉表和四职业换装表；
6. `REGIONS`、关卡、怪物与掉落表；
7. 装备跨区升阶消耗端；
8. 资产门禁、数值模拟、手机界面和生产构建。

不能先把 `REGIONS` 接上再补材料或素材。因为关卡、怪物、掉落都是模块加载时
生成，半套接入会在启动阶段直接制造缺物品、缺视觉或缺强化配置。

## 七、验收边界

- 4 区域、20 章节、120 关都能从关卡选择页正确定位；
- 新区 47 只怪物均使用独立正式图，不复用旧区占位；
- 普通 / 精英 / BOSS 只掉自己档位的区域材料；
- 稀有材料有真实 BOSS 来源、可见保底和装备升阶消耗端；
- 若启用区域 3 属性教学，炎属性装备必须来自真实武器元素，并在挂机结算里
  确实提高对冰怪效率；没有合法来源时必须隐藏教学；
- 新关入场后人物、怪物、技能卡和命中特效立即继续播放；
- 390×844 与 320×568 下无横向溢出、裁脸、破图或控制台错误；
- `npm run verify`、`npm run sim`、生产构建和 117 项资产审计全部通过。
