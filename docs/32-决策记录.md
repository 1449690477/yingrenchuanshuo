## ADR-001 · 不使用任何传奇开源/泄露源码，从零开发

**日期**：2026-07-26

**背景**：项目所有者手上有 7 个传奇服务端版本（GameOfMir 商业引擎、传奇2Ex C++ 源码、
兰达尔/AppleM2、OpenMir2 .NET8、Zircon 传奇3 C#、MirServer-Delphi）。
最初考虑在 Zircon 基础上改造。

**结论**：全部不用，从零用 Web 技术栈开发。

**原因**：
1. 目标平台是 GitHub Pages + 手机竖屏，所有源码都是 Windows PC 客户端
2. Zircon 是 DirectX9 + WinForms，横版 1024×768，无法上手机
3. 目标形态是「扫荡/副本/团本」的现代放置手游，传奇引擎里这些系统一个都没有
4. 传奇的 8 方向精灵美术管线与「AI 生成立绘」的资源方案冲突
5. 泄露源码无 LICENSE，商业化有法律风险

**代价**：放弃了 Zircon 现成的战斗/掉落/技能 C# 实现，需要自己写。
但由于形态差异巨大，实际可复用比例极低，损失可接受。

## ADR-002 · 选择 Vue 3 而非 React / Godot / Cocos

**日期**：2026-07-26

**结论**：Vue 3 + TypeScript + Vite。

**原因**：
- 竖版放置游戏 90% 是密集 UI，DOM + CSS 就够，不需要游戏引擎
- Vue 模板在密集 UI 场景下代码量最少
- 中文生态最好，AI 生成 Vue 代码质量稳定
- Godot/Cocos 导出 Web 包体大、首屏慢，且项目所有者要额外装编辑器

**代价**：复杂战斗特效需要后期引入 PixiJS 作为独立图层。

## ADR-003 · 核心逻辑与 UI 严格分层

**日期**：2026-07-26

**结论**：`src/core/` 为纯函数层，禁止 import vue / pinia / DOM API。

**原因**：这是「不同 AI 轮流开发不崩」的核心保障。
只要 `core/` 的测试全绿，就能确信游戏逻辑没被改坏。
同时使数值模拟器成为可能 —— 这是放置游戏最重要的开发工具。

**代价**：需要多写一层 store 做胶水，前期代码量略增。

## ADR-004 · 强化保留碎率，但加幸运值保底

**日期**：2026-07-26

**结论**：+13 及以上有碎裂风险，同时引入「连续失败累积幸运值，满则必成」。

**原因**：碎装备的心跳感是传奇的核心记忆点，不能砍。
但纯随机会让极端非酋玩家直接退游。保底让最坏情况可预期。

**代价**：削弱了一部分「赌」的刺激感。可接受。
