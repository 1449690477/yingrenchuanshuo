# 32 · 决策记录（ADR）

> 记录重大技术与设计决策及其原因。
> **想推翻某个已有设计前，先来这里看当初为什么这么定。**
> 格式：日期 / 决策 / 背景 / 结论 / 代价

---

## ADR-001 · 不使用任何传奇开源/泄露源码，从零开发

**日期**：2026-07-26

**背景**：项目所有者手上有 7 个传奇服务端版本（GameOfMir 商业引擎、传奇2Ex C++ 源码、
兰达尔/AppleM2、OpenMir2 .NET8、Zircon 传奇3 C#、MirServer-Delphi）。
最初考虑在 Zircon 基础上改造。

**结论**：全部不用，从零用 Web 技术栈开发。

**原因**：
1. 目标平台是 GitHub Pages + 手机竖屏，所有源码都是 Windows PC 客户端
2. Zircon 是 DirectX9 + WinForms，横版 1024×768，无法上手机
3. 目标形态是「扫荡/副本/团本」的现代放置手游，传奇引擎里这些系统一个都没有
4. 传奇的 8 方向精灵美术管线与「AI 生成立绘」的资源方案冲突
5. 泄露源码无 LICENSE，商业化有法律风险

**代价**：放弃了 Zircon 现成的战斗/掉落/技能 C# 实现，需要自己写。
但由于形态差异巨大，实际可复用比例极低，损失可接受。

## ADR-002 · 选择 Vue 3 而非 React / Godot / Cocos

**日期**：2026-07-26

**结论**：Vue 3 + TypeScript + Vite。

**原因**：
- 竖版放置游戏 90% 是密集 UI，DOM + CSS 就够，不需要游戏引擎
- Vue 模板在密集 UI 场景下代码量最少
- 中文生态最好，AI 生成 Vue 代码质量稳定
- Godot/Cocos 导出 Web 包体大、首屏慢，且项目所有者要额外装编辑器

**代价**：复杂战斗特效需要后期引入 PixiJS 作为独立图层。

## ADR-003 · 核心逻辑与 UI 严格分层

**日期**：2026-07-26

**结论**：`src/core/` 为纯函数层，禁止 import vue / pinia / DOM API。

**原因**：这是「不同 AI 轮流开发不崩」的核心保障。
只要 `core/` 的测试全绿，就能确信游戏逻辑没被改坏。
同时使数值模拟器成为可能 —— 这是放置游戏最重要的开发工具。

**代价**：需要多写一层 store 做胶水，前期代码量略增。

## ADR-004 · 强化保留碎率，但加幸运值保底

**日期**：2026-07-26

**结论**：+13 及以上有碎裂风险，同时引入「连续失败累积幸运值，满则必成」。

**实现约束**：

- 幸运值按「装备 UID × 目标强化等级」分别累计。冲 +10 失败掉级后，重新回到
  +9 再冲 +10 时，原来的 +10 幸运值仍然保留；不能拿低级装备垫出高阶保底。
- 装备碎裂后该装备与全部幸运桶一起消失；结果不得返回一个还能继续持久化的幸运值。
- 保护符只在实际防住碎裂时消耗；成功与幸运保底成功都不消耗。
- 每次合法强化尝试固定推进一次 seeded RNG，包括 100% 成功段与幸运保底，
  保证「一次玩家操作 = 一格随机流」，便于复盘。

**原因**：碎装备的心跳感是传奇的核心记忆点，不能砍。
但纯随机会让极端非酋玩家直接退游。保底让最坏情况可预期。

**代价**：削弱了一部分「赌」的刺激感。可接受。

## ADR-005 · 怪物血量指数必须贴近装备成长指数

**日期**：2026-07-26（M1-10 数值校验阶段）

**背景**：文档最初拍脑袋定了 `monsterHp = 200 × L^2.3`、`expToNext = 100 × L^1.9`。
M1-9 写完模拟器跑第一次，立刻发现 **Lv50 时每秒击杀 0.000 —— 杀一只怪要 3800 秒**，
游戏在中期直接卡死。

**根因**：玩家战力的成长上限由装备决定。docs/12 定的装备公式是 `ITEM_BASE × L^1.35`，
也就是玩家有效战力渐近于 `L^1.35`。强化（×2.2）、技能倍率（×2.6）、套装
这些都是**有界常数**，不随等级增长。而怪物血量按 `L^2.3` 增长，
指数差 0.95 —— 到 Lv120 差距达 40 倍，且随等级无限拉大。

**结论**：怪物曲线全部下调，指数贴近 `ITEM_POW`：

| 参数 | 原值 | 新值 |
|---|---|---|
| `MONSTER_HP_BASE / POW` | 200 / 2.3 | **60 / 1.45** |
| `MONSTER_ATK_BASE / POW` | 15 / 1.5 | **10 / 1.35** |
| `EXP_BASE / POW` | 100 / 1.9 | **30 / 3.25** |

新参数下 TTK 全程稳定在 4.8–6.7 秒，满级约需 30 天。

**代价**：绝对数值变小了（Lv120 小怪 6.2 万血而非 1200 万），
「大数字」的爽感弱一些。但可以靠 UI 展示（伤害飘字、总输出统计）补足，
而曲线崩了是无法靠 UI 补救的。

**教训**：**数值设计里单个指数没有意义，只有指数之间的差值有意义。**
任何 AI 想调 `MONSTER_HP_POW`，必须同时检查 `ITEM_POW`。

## ADR-006 · 百分比属性不得随等级缩放

**日期**：2026-07-26（M1-10）

**背景**：docs/12 最初把 `critRate` 和 `critDmg` 和攻击力一样放在 `SLOT_WEIGHTS` 里，
统一乘装备基准值（`L^1.35`）。模拟器跑出来 **Lv120 神装单把武器给 115% 暴击率**。

**根因**：绝对数值属性（攻击/防御/生命）需要随等级指数增长才能跟上怪物；
但百分比属性（暴击率/暴伤/攻速）的合理区间是固定的（暴击率 0~75%），
乘上一个指数增长的基准值必然爆表。**两类属性的量纲不同，不能用同一个公式。**

**结论**：拆成两张表。

- `SLOT_WEIGHTS` —— 只放 atk / def / hp / acc / eva，乘装备基准值（随等级增长）
- `SLOT_PCT_WEIGHTS` —— 放 critRate / critDmg / spd，乘 `QUALITY_PCT_SCALE`（**只随品质增长，与等级无关**）
- 新增 `CRIT_RATE_CAP = 75` 硬上限

**代价**：高等级玩家的暴击收益不再随等级自动提升，只能靠换更高品质装备。
这其实是好事 —— 给了品质升级更明确的价值。

## ADR-007 · 职业差异用百分比系数，不用属性成长

**日期**：2026-07-26（M1-10）

**背景**：三职业原本靠 `CLASS_GROWTH`（每级 +2.2 / +3.4 / +1.9 攻击）体现差异。
模拟器显示中后期三职业挂机效率趋同，且**攻速最高的灵巫反而输出最高** ——
与 docs/13 设计的「灵巫单体 DPS 最低」完全相反。

**根因**：装备是职业通用的，到 Lv50 装备已贡献 90%+ 的攻击力，
`CLASS_GROWTH` 那点线性差异被彻底冲淡，只剩 `spd` 这个乘数在起作用。

**结论**：新增 `CLASS_ATK_MUL`，作用于「裸属性 + 装备」累加**之后**：

```
剑姬 1.00 × spd 1.0 = 100%
魔女 1.06 × spd 0.9 =  95%
灵巫 0.78 × spd 1.1 =  86%
```

实测三职业偏离收敛到 ±17% 以内（Lv10 最差，之后收敛到 ±9%），在 ±20% 平衡带内。

**教训**：凡是要在**所有等级段**都成立的差异，必须用百分比系数，不能用线性加值。

## ADR-008 · 美术与 UI 风格基调：可爱 / 青春 / 清纯 / 蓝白粉

**日期**：2026-07-26（由项目所有者决定）

**结论**：全项目视觉基调为 **可爱、青春、清纯**，主色为 **蓝白粉**。

**这意味着什么**（后续所有 AI 必须遵守）：

| 维度 | 要求 |
|---|---|
| 底色 | **浅色**（白 / 极浅蓝），不是暗色 |
| 主强调色 | 樱粉 `#ff9ec4` |
| 次强调色 | 天蓝 `#7ec8f2` |
| 圆角 | 大圆角（14–20px），不用锐角 |
| 阴影 | 柔和、带蓝色调，不用纯黑阴影 |
| 文字 | 柔和石板灰 `#46596b`，**不用纯黑** |
| 立绘 prompt 基调 | 明亮日系、柔光、清透、校园感；避免暗黑、血腥、成熟性感 |
| 怪物设计 | 即使是「亡灵」「恶魔」也要走可爱路线（Q 版、圆润、无恐怖元素） |

**代价**：M0 阶段做的暗紫色主题需要整套重做。
另外 docs/11 里区域 4「月下墓园」、区域 7「血月峡谷」这类偏暗的主题，
美术上要按「可爱化」重新诠释（月下墓园 → 柔和月光 + 兔耳幽灵娘，
血月峡谷 → 粉紫夜空 + 小恶魔娘），世界观文字不变。

**为什么值得记一条 ADR**：视觉基调一旦定下，几百张 AI 立绘都要按它生成。
中途更改的返工成本极高，所以任何 AI 都不得擅自偏离，需要变更必须先改本条。

## ADR-009 · 攻速在战力公式中必须作为乘数

**日期**：2026-07-26（M2 首次完整流程测试）

**背景**：旧战力公式用 `(spd - 1) × 1500` 表示攻速。魔女初始攻速为 0.9，
因此 Lv1 会被固定扣掉 150 战力，而她的总战力只有约 200。结果是新建魔女后，
系统直接判定低于第一关 60% 推荐战力，挂机在开始前就被暂停。

**根因**：攻速的单位是“每秒攻击次数”，作用方式是把整体输出乘快或乘慢，
不是一项能与攻击、防御直接相加的固定分数。

**结论**：

```
CP =（攻击、防御、生命、命中、闪避、暴击的加权和）× spd
```

单件装备也不能脱离角色直接套这个公式，因为大多数单件装备自身 `spd = 0`，
会被乘成零。装备比较改为“把候选装备替换进角色当前整套装备后，总战力变化多少”。

**代价**：所有推荐战力与旧文档校验点需要重算，但新公式与真实战斗效率的量纲一致。

## ADR-010 · 理想满配模拟不能替代真实掉落过程

**日期**：2026-07-26（M2 内容接入复验）

**背景**：M1 进度曾写“TTK 全程稳定在 4.8–6.7 秒”，但 M2 把区域 1–2 的真实装备、
掉落和穿戴接起来后复查模拟器，发现 `typicalQuality` 会在等级门槛瞬间把全身 8 件装备
从一个品质替换到下一个品质。品质系数从白装 1.0 最终增长到圣器 15.0，
所以理想模型的击杀速度实际从 Lv10 的 0.06 只/秒跳到 Lv120 的 1.21 只/秒，
并不满足“全程稳定 TTK”的说法。

**结论**：现有模拟器继续用于检查指数关系、三职业偏差和击杀上限，但不再用它证明
真实玩家 TTK。M5 套装落地时按真实掉落、逐件比较穿戴、强化进度重写装备模型，
再以“当前最高关 TTK 5±1.5 秒”作为正式验收。

**代价**：在 M5 前，30 天成长曲线只能视为理想上限。M2 真实体验用浏览器流程测试
观察，但不通过拍脑袋改怪物曲线来掩盖模拟模型问题。

## ADR-011 · 角色外观采用同画布分层纸娃娃，不预制装备组合图

**日期**：2026-07-27

**背景**：原人物资源是把衣装、头饰和武器画死在一张完整立绘里。若为
“职业 × 等级 × 动作 × 武器 × 头冠 × 衣装 × 品质 × 强化”预制整图，
区域 1～2 就会产生数千张组合，后续九个区域无法维护。

**结论**：

- 三职业各有一张无外装的 640×960 透明底模。
- 武器、头冠、衣裙、鞋使用同尺寸、同脚底锚点的独立透明层；装备定义只保存静态
  `appearanceId`，运行时外观完全由当前 `equipped` 派生。
- 项链、手镯、戒指、腰带在 100～200px 战斗人物上不可读，当前保留在展示窗的
  八槽装备图标中；数据注册表为后续腰带与披风等真实图层预留。
- 身体衣装之后重新绘制一层只包含脸与刘海的底模安全区，再叠头冠与武器。这样高领、
  蝴蝶结等复杂衣装不会盖住眼睛和嘴；若某套素材仍无法同时通过脸、手、鞋与武器的
  三职业合成验收，则放弃强行分层，改为该职业的整身成品立绘。
- 品质、强化和等级成长由轮廓辉光、武器拖尾、光环和粒子分段表现，不复制装备位图。
- 待机、普攻、施法、触摸回应先对整组图层做 CSS 动作，避免每件装备再复制动作帧。
- 外观不写入存档，因此本批次不提升 `SAVE_VERSION`；未来只有“幻化与实际装备分离”
  才需要新增存档字段和迁移。

**代价**：AI 生成的空心衣装仍需逐职业实际合成校准，武器握持遮挡不如骨骼动画精确；
但资产量随区域线性增长，养成页、战场和顶部头像能共用同一套真实换装结果。

## ADR-012 · 精品商店是高价金币保底，不是装备独占来源

**日期**：2026-07-27（项目所有者指定的首次商店试水）

**背景**：项目所有者希望玩家能把分解掉落物得到的金币用于购买高品质装备和华丽时装，
并以首批紫色、金色、红色珍品验证商店吸引力。项目宪章同时要求“装备靠打不靠抽”，
因此不能让商店成为高阶装备的唯一来源，也不能虚构尚未接入的技能机制。

**结论**：

- 商店只收游戏内挂机、击杀与分解获得的金币，没有钻石、抽卡或现金入口。
- 首批 30 个商品定义中，每个职业实际可见 24 件：3 把职业武器和 21 件通用装备。
  同一商品每角色限购一次，购买后自动锁定，防止误分解。
- 购买逻辑只接收 `offerId`，价格、职业、等级、通关、余额和限购状态全部由
  store 从可信配置重新计算；扣金币、生成 UID、入包与记录已购买在同一同步事务中完成。
- 史诗 / 传说 / 神话珍品使用明确的固定高档词条，不在购买时随机重掷；华丽光效、
  攻击换肤与专属互动已经真实接入。尚未接入的主动技能加成只做视觉说明，不冒充战斗机制。
- 传说与神话同款写入区域 2 对应章节 BOSS 的低概率直掉表；最终关普通击杀只掷
  normal 表，完整跑完波次并击杀 BOSS 才掷一次 boss 表。商店只是昂贵而确定的保底路径。
- 新增 `shop.purchasedOfferIds`，存档升到 v3，并提供 v2 → v3 迁移与测试。

**代价与后续**：

- 价格目前是首次试水区间，尚未进入包含分解、强化与真实购买行为的经济模拟。
  M3 强化金币消耗接入后，必须联合模拟玩家金币净流入和目标商品购买周期，再决定调价。
- 固定词条让珍品价值清楚，但减少重复购买与刷随机词条的空间；首批采用一次性收藏，
  后续若增加刷新商店，必须另写 ADR，不能复用本批逻辑偷偷引入抽卡式随机。

## ADR-013 · 血条先做无状态战况投影，不改挂机经济结算

**日期**：2026-07-27（项目所有者指出人物 / 怪物血量显示错误）

**背景**：M2 挂机产出为了快速结算，使用第一波第一只小怪作为代表怪计算每秒击杀；
旧 UI 却把这份抽象进度套在按波次展示的另一只怪上。首个 BOSS 的实际生命约为代表
小怪的 28 倍，因而最大生命、当前生命和伤害飘字互相矛盾；玩家则完全没有当前生命。

**结论**：

- 新增纯函数 `battleVitalsAtProgress()`，用当前视觉目标的真实属性计算双方最大生命，
  怪物当前生命随遭遇进度从满值降到 0；玩家当前生命复用 `timeToKill()` 与
  `estimateIncomingDps()` 投影本场期望承伤。
- 该函数无状态、不修改参战单位、不读取 UI，也不参与 RNG、金币、经验、掉落和击杀结算。
  `buildIdleContext()` 的代表怪与挂机经济模型保持原样，避免一次血条修复暗中改变玩家收益。
- 每次击杀演出在推进关卡前记录倒下目标，动画期间保持旧目标到 0，结束后才切下一只。
  高速挂机对演出做冷却采样，给中间掉血阶段留出可见时间，但所有击杀仍完整结算。
- M3-4 接入技能优先级与冷却时，建立 seeded 前台战斗事件流，再用真实逐击结果替换本投影。

**代价**：当前血条能与画面目标和既有公式自洽，但仍是期望值投影，不展示某一次真实掷骰
产生的命中、闪避、暴击或治疗；这些事件必须等 M3-4 的前台战斗状态机统一落地。

## ADR-014 · 装备随机只给正向惊喜，已得到的成长不重掷

**日期**：2026-07-27（M3-2）

**背景**：项目所有者希望掉落、打造和强化装备带有“看运气”的惊喜，同时不能让玩家因为
抽到低数值或强化掉级而觉得此前投入被抹掉。旧版所有装备都是固定胚子，每级强化固定
+8%，既没有个体差异，也无法让图标与人物外观反映成长阶段。

**结论**：

- 掉落 / 打造装备生成一次 `baseRollPermille`：80% 为 100.0%～106.0%，18% 为
  106.1%～112.0%，2% 为 112.1%～120.0%。最低值等于旧版，不存在“倒霉就比旧装备弱”。
- 每次**首次**成功到达一个强化等级，生成该级独立增幅：86% 为 8.0%～8.2%，13% 为
  8.3%～9.5%，1% 为 11.0%～12.5%。掉级只暂停高等级增幅，重新升回时恢复原结果，
  不允许反复掉级刷数值；累计强化倍率硬限制为 ×2.35。
- 胚子档位不暗改锁定状态：仅传说及以上品质自动锁；史诗“奇迹胚子”可手动锁定，
  自动清包另按 T4+ 战斗用途冠军规则保护。精品商店与精品 BOSS 同款继续使用可预览
  的固定 100% 模板和固定词条，购买不变成暗抽。
- 装备实例保存固定 15 格增幅和按“UID × 目标等级”分桶的幸运值。v3 → v4 迁移把旧装备
  写成 100% 胚子、已有等级每格 8%、空幸运桶，迁移前后属性不下降。
- 强化交易先验资，再在克隆的 seeded RNG 上规划，最后一次提交金币、材料、装备与随机
  状态。缺资源不推进 RNG；保护符只在实际防住碎裂时消耗；幸运保底成功不消耗保护符。
- +5 / +9 / +12 / +15 分别进入微光、辉光、星铸、樱华外观。锻造阶段只控制装备图标、
  可见纸娃娃层、全身粒子和武器拖尾，不伪装成更高掉落品质；首饰不会错误点亮武器。

**玩家体感**：普通结果至少等同旧版，偶尔会得到值得截图分享的奇迹胚子或奇迹强化；
即使强化掉级，曾经掷出的好成长仍然保留。高段碎裂风险仍存在，但保护符和分目标幸运
保底使连续失败有明确终点。

**代价**：装备实例和存档体积增加；后续洗练、继承与跨装备转移必须明确哪些随机结果
保留，不能通过重新创建实例偷偷重掷。M3-13 还需要把真实强化进度纳入联合经济模拟。

## ADR-015 · 强化材料按真实怪物类型结算，一键强化默认安全

**日期**：2026-07-27（项目所有者指出玄铁不可见与关卡曲线脱节）

**背景**：旧掉落表已经给精英配置玄铁矿，但挂机只执行关卡的 normal 表，精英表从未
进入主流程；玄铁实际只来自最终 BOSS 首通与完整循环，离线弹窗还遗漏这部分额外掉落。
同时，连续强化若直接循环现有单次 store 动作，会每次存档、可能中途碎装，并让全身
第一件装备先耗光全部资源。

**结论**：

- 新增 `enhanceProgression.ts` 作为十章唯一强化成长表，同时定义全身 / 主养推荐等级、
  normal / elite / boss 强化材料、保底与六关首通奖励；`lootTables.ts` 与 `stages.ts`
  只读取它，不再各写一套硬编码。
- 挂机基础收益仍使用 normal 表；`stageLoot.ts` 按真实波次与起始游标统计每种怪物，
  store 只为实际击杀的精英 / BOSS 追加专属表。BOSS 统计与波次计数不一致时直接报错，
  不用空表或普通表兜底掩盖配置错误。
- 区域 1 首轮目标为全身 +5、主养 +8；区域 2 为全身 +9、主养 +10。首个区域最终关
  首通保证 10 玄铁 / 1 幸运九 / 1 保护符，第二区域保证 30 / 2 / 2；+12 以上保留为
  反复刷最终 BOSS 的进阶目标。
- 新增纯函数批量强化：单件连续与全身按 +5 → +9 → +12 → +15 里程碑均衡轮转。
  输入全部克隆，缺资源不推进 RNG，最多 1,024 次；store 只在发生尝试后一次提交钱包、
  装备和随机状态。
- 一键强化冲 +13～+15 时自动保护；非幸运保底但缺少保护符就停止，绝不碎装。手动
  单次强化仍允许玩家明确选择不保护并承担风险。
- 锻造阶段继续只改变视觉，不改变真实品质。新增四张通用透明光环和
  `forgeVisuals.ts` 映射，避免为每件装备复制四套位图；具体按钮与叠层由独立 UI 批次接入。

**玩家体感**：从 1-4 精英开始就能真实看到玄铁，最终关会稳定给一包高阶材料；离线
回来不会再出现“包里有东西、弹窗没显示”。一键全身会先把大家一起推到关键节点，
高阶缺保护符时宁可停下，也不会睡一觉回来发现装备被自动碎掉。

**代价与后续**：前两区材料和批量事务已经单独验证，但完整金币流入、技能 DPS、商店
购买周期仍需等 M3-4 后在 M3-13 做联合模拟。锻造 UI 必须复用现有 store 接口与视觉
映射，禁止在组件内再写成本循环或把锻造阶段伪装成品质升级。

## ADR-016 · 第四职业使用稳定 ID 扩展现有管线，数据与真实结算分阶段交付

**日期**：2026-07-27（喵喵第四职业插单）

**背景**：项目所有者要求以棕白猫吉祥物为原型增加可爱角色“喵喵”，并制作角色外观、
动作、技能、特效和换装全套内容。当前三职业已经有创角、纸娃娃、精品换装、技能预览
和战斗节奏管线，但 M3-4 的真实技能执行器尚未完成；若把表现层直接写成结算逻辑，会
造成同一个技能在 UI 与挂机收益中出现两套事实。

**结论**：

- 新职业使用稳定存档 ID `catkin`，展示名仍为“喵喵”；统一由 `CLASS_IDS` 驱动创角、
  Zod 校验、成长、模拟和职业过滤，禁止在各页面维护不同的职业数组。
- 存档升到 v6。v5 → v6 不改旧玩家数据，只扩展合法职业集合；迁移和 schema 均有测试。
- 角色沿用现有固定画布纸娃娃管线，交付底模、两区换装、三套精品换装、武器图标、
  基础爪击、10 个主动技能大特效与 14 个技能图标。新增动作仍由 CSS 状态驱动，
  不引入与现有三职业不同的骨骼运行时。
- 技能玩法与视觉拆成 `skills.ts` / `skillVisuals.ts` 两张按 `skillId` 关联的表。
  强类型效果能表达多段总倍率、条件、事件来源、印记、状态消费、无视防御、控制、
  必闪和召唤；视觉表允许是玩法表的严格子集，但不能引用不存在的技能。
- 当前战斗只消费无条件伤害技能的视觉节奏；炸毛反击、纸箱奇袭等条件技能留在养成
  预览，直到 M3-4 用真实生命、印记与冷却事件驱动。挂机收益暂不把这些效果算进去。
- 精品 BOSS 掉落增加 `classId` 过滤。含职业专属项却没有职业上下文时直接报错，
  不用“随机给其他职业武器”的错误结果作为兜底。

**玩家体感**：现在可以创建喵喵，看到猫耳、尾巴、肉球爪和蓝色泪滴记号，使用基础装、
两区成长装与三套精品装；挂机和养成页能播放突进、乱抓、横扫、回旋、反击与胜利等动作，
技能图标和大特效具有完整升级预期。基础数值下单体挂机效率维持在四职业均值约 +3%～4%。

**代价与后续**：本批次完成的是“现有三职业同等管线”的第四职业，不等同于完成 M3-3
旧三职业 42 技能或 M3-4 真实调度器。M3-4 必须统一实现逐击、冷却、印记生命周期、
反击来源、状态与 seeded RNG；接入后再做四职业真实技能 DPS 联合模拟。

## ADR-017 · 四职业切换共享账号成长，不建立独立角色存档

**日期**：2026-07-27（项目所有者要求玩家随时更换喜欢的角色并保留全部进度）

**背景**：v6 存档已经用 `player.classId` 表示当前职业，等级、经验、货币、背包、穿戴、
关卡、强化、商店限购、奇遇、统计与 RNG 都是账号级字段。若为了切换职业再复制四份
角色存档，会立即产生“材料给谁、商店限购是否重复、关卡是否重打、离线收益结算给哪份”
等分叉，并让玩家换喜欢的外观时承担重复养成成本。

**结论**：

- 切换职业只修改现有 `player.classId`，其他持久字段继续共享；不增加存档字段，因此
  `SAVE_VERSION` 保持 v6，也不新增空迁移。
- 通用装备继续留在原槽。与目标职业不兼容的专属穿戴完整移回背包并自动锁定；
  UID、胚子、强化、幸运值和词条不得变化。切换事务不裁剪背包、不分解装备、不推进 RNG。
- 切换不调用 `loadFrom()`，因为重新载入会执行离线结算；store 在纯函数计划完整通过后
  一次性提交职业、穿戴和背包，并立即持久化。
- 战斗中切换保留当前怪物掉血比例与已通关关卡的波次目标，但清空旧职业攻击拍子、
  技能冷却和击杀脉冲，再由新职业重新开始演出。
- 当前不自动穿上背包里的目标职业武器，也不记忆四套独立穿戴，避免系统替玩家覆盖选择。

**玩家体感**：玩家可以在养成页随时换成剑姬、魔女、灵巫或喵喵，等级、金币、材料和
推图成果都不会重来；换下来的精品专属武器会安全留在背包，切回后仍保持原强化与属性。
职业基础属性和技能不同，所以战力与挂机速度会合理变化，但不会凭切换重复领取收益。

**代价与后续**：四职业当前共用一套穿戴栏，切回旧职业时需要手动穿回专属武器。
若以后要保存“一职业一套装备”，应与 M5-8 多套装备预设统一设计，并升级存档与迁移；
不能在当前共享结构旁再偷偷维护第二套装备真相。

## ADR-018 · 装备副本采用 8 门户 × 4 档 × 80 件固定矩阵，成功才扣次数

**日期**：2026-07-28（项目所有者要求完整制作装备副本、四职业全套蓝至红装与正式美术）

**背景**：原路线图只写“8 个部位定向副本，每日 3 次”，没有决定品质跨度、职业件数量、
首通体验、保底、存档或素材边界。若每个门户各写一套临时表，会出现职业缺部位、红装
没有来源、每日次数被失败误扣、商店时装被副本复用，以及地图 / 怪物 / 图标缺文件等问题。

**结论**：

- 内容采用 8 个部位门户 × 蓝 / 紫 / 橙 / 红 4 档，共 32 关；开放等级为
  Lv20 / 35 / 50 / 78，并要求同部位逐档首通。
- 装备采用固定 80 件矩阵：每档 4 职业武器 + 4 职业礼服 + 六个通用部位各两款。
  任何修改都必须继续保证四职业在每档可穿齐八槽。
- 八门户共享每日 3 次“成功领奖次数”，北京时间 04:00 重置。失败不扣次数、不推进
  保底或主 RNG；首通额外执行一次同表掉落，通用双款连续两次缺失后触发补偿。
- 存档升 v7，只新增业务日、今日成功次数、总次数和 32 关记录；重复件保底继续使用
  `progress.pity`，不维护第二套计数。
- 四档 2 / 4 / 6 / 8 件共鸣由纯函数统一计数，并进入最终属性与平均技能倍率；
  UI 只能显示核心返回结果，不能复制套装公式。
- 副本美术与珍品商店完全分开。礼服对 ADR-011 做最小例外：每档每职业只有一张
  “穿好该礼服”的整人替换图，用来消除空衣服层错位 / 挡脸；武器、头冠和鞋仍保持
  同画布独立层，首饰仍用槽位与粒子表达。不是为任意混搭预制组合图。
- 168 个运行时素材不进入 PWA 首次预缓存，按需下载后 CacheFirst 30 天。

**玩家体感**：玩家缺哪一格就打哪座门，失败可以原样再试；每天三次胜利都有目标，
首通会一次看到两件，重复款也有短保底。蓝装负责启动定向收集，紫 / 橙 / 红逐档形成
长期追求；四职业都拥有自己的武器与礼服，穿上后角色、头冠、鞋、武器和档位粒子同步变化。

**代价与后续**：当前 80 件解决的是定向装备和四套共鸣，不包含 M5-2 的碎片合成 /
3 换 1，也不等同于 M5-5 的全局装备图鉴。后续增加新档位必须同步扩展装备矩阵、
平衡脚本、存档关卡记录允许列表和完整资产清单，不能只加 UI 卡片。

## ADR-019 · 好感按角色独立，选择无数值惩罚，心虹掉落使用缺件优先保底

**日期**：2026-07-28（人物养成页 Galgame 化第一批）

**背景**：养成页原本的“默契”只是组件内点击次数，离开页面或切换角色就消失，也不参与
真实战斗。项目所有者希望加入更丰富的暧昧剧情、触摸反馈、好感战力与角色专属极品装备。
如果直接复用旅途 NPC 奇遇关系，会把可玩角色与路遇角色混成一份进度；如果 Galgame
选择有最优答案，玩家会被战力逼着照攻略说话；如果 40 件装备逐件使用独立概率，则一次
互动可能同时掉多件，保底也会失去可解释性。

**结论**：

- 四职业各自保存心意、心情、每日次数、剧情选择、连续未掉次数与永久图鉴。角色切换
  继续共享账号等级和背包，但只启用当前职业对应的好感加护。
- 每位角色北京时间 04:00 重置 4 次有效互动；每次固定 +10 心意。阶段门槛为
  0 / 80 / 240 / 520 / 900 / 1400，常规属性加成为 0% / 1% / 2% / 3.5% / 5% / 7%。
- 每幕三个回答奖励相同，不设扣好感或“正确答案”；选择只改变角色回应与后续一句记忆
  回响。回看剧情不重复领奖。
- 心虹装备按“本次互动只掷一次”结算：基础 3%，连续 8 次后每次 +5 个百分点，
  第 16 次必得；掉落后归零。当前池未集齐时只掉缺件，集齐后才允许重复。
- 好感装备采用独立 `prismatic` 品质：倍率 11.8、6 固定词条、百分比倍率 4.0，
  排在神话与圣器之间；获得时强制锁定，批量分解视为高风险。
- 场景图不包含固定角色，剧情运行时叠加玩家当前纸娃娃外观；高潮图只画绶带、星晶、
  月灯愿纸、空手套等关键物件，避免换装后突然切回旧衣服。
- 短震只由明确点击触发，支持独立开关并尊重减少动画；硬件不支持只影响触感，不影响
  互动、掉落或存档主流程。
- 存档升 v9，并用严格迁移一次性增加 `settings.haptics` 与四角色好感状态。

**玩家体感**：玩家可以只培养真正喜欢的角色，不必同时攻略四人；每次选择都能得到尊重，
剧情会记得先前回答。好感会真实增强当前角色，而心虹收藏最坏四天得到一件、未集齐不反复
撞同款，仍保留小概率惊喜。换装后的角色会直接出现在剧情场景里。

**代价与后续**：第一批只有每人三幕和十件珍藏，后续剧情必须继续遵守“选择不惩罚、
先询问再接触、成年平等伙伴”的边界。心虹专属技能效果当前只作为回忆外观文案；
若未来进入真实战斗，必须在技能执行器中建立强类型效果与测试，不能把描述文字当成已结算。

## ADR-020 · 词条完整性以真实来源、动态保护和可达极值门禁收口

**日期**：2026-07-29

**背景**：M4-6 的洗练交互已经可玩，但复核发现三处第一性矛盾：
`elemDmg` 被当作攻击元素来源、自动清包只认八项 Stats、职业红表只打印不阻断。
这些问题短期不一定报错，却会分别制造白送克制、误删极品与平衡假绿。

**结论**：

- `EquipmentDef` 按槽位判别：武器必须显式配置 `element`，非武器禁止配置。
  当前基础攻击只读已穿武器；词条绝不反向赋予属性。元素静态定义本身不需要迁移；
  当前存档升级 v11 是为了下面的词条重标，不能把两件事混写。真实武器来源覆盖三系：
  莓果 / 琥珀炎，月糖 / 晴蓝冰，蔷薇 / 月紫 / 绯樱雷；元素词条只在来源已存在后开放
  （Lv16 炎 / 冰、Lv20 雷），掉落、重铸与模拟器共用同一来源 / 解锁矩阵。
- 自动清包不为减伤、吸血、元素伤害拍固定 CP 权重；按部位与五类用途动态保留
  一件 T4+ 冠军，形成最多 40 个“部位 × 用途”保护位置；另按炎 / 冰 / 雷各保留
  一把评分最高的基础元素武器，最多再增加 3 个位置，且都不写永久锁定。
- 职业词条显式区分输出 / 生存。完整候选池先等概率选定位、再在定位内按权重抽取；
  重铸必须先排除旧 key 与同件已占用 key，再只在剩余有候选的定位中选择。
  魔女增加星纱，灵巫增加灵击；铭刻只改预留职业槽且不能使用定契符。
- T5 系数改为 1.64，职业输出基准改为 `swd_heavy=27`、`wit_power=0.53`、
  `wit_elem=4.3`、`sha_spirit=0.84`、`cat_swift=0.027`。存档升 v11：
  v10→v11 按比例迁移四条既有职业词条、所有 T5 与待确认候选，不重掷 RNG。
  发布版 v10 existing 只校验有限值，重标后保留历史价值、不夹洗；随机 pending 候选才
  投影到当前离散区间，待确认同调基于迁移后的目标值和新相邻品阶比例精确复算。
  v9 反推品阶固定使用旧 T5=1.54，v10 装备定义使用发布时 235 项静态白名单；
  旧错槽 / 超额职业词条确定性保留最优一条到预留槽，其余保品阶与
  百分位转通用并退对应徽记；pending 始终跟随原目标，跨槽型候选同步转入新合法池。
- 付费洗练的事务边界延伸到 IndexedDB：候选生成、采用、保留只有在写事务完成后
  才返回成功。等待期间暂停实时 tick、拒绝第二笔洗练并延迟普通自动保存；前后台恢复
  只登记到事务结束后统一结算。写失败精确回滚本次资产、RNG、共鸣、词条和候选，
  校验 / 配置错误继续抛出，不走存储错误兜底。跨标签写入使用 IDB revision/CAS；
  过期页冲突后停机提示刷新，清档与保存同队列且保留 revision 墓碑。
- v10→v11 在改值或退款前先按发布版冻结边界验证 v10 结构和语义；规范化过程中按当前词条实时重算
  key 占用，非法旧档不会被洗成合法，已转换掉的职业 key 也不会形成幽灵占用。
  v10 合法但外层穿戴错槽的实例在 v11 校验前完整回包，目标槽已占也不覆盖。
- `npm run sim` 直接聚合配对样本的真实 KPS，前三层覆盖普通到圣器，八件职业槽可达
  混合输出 T5 极值层覆盖史诗到圣器，并统一复验 Lv120，硬判四层；
  极值枚举同职业全部输出词条分配，且从真实装备表取得当前等级元素武器；任何一层
  偏离均值超过 20%、或 30 天模型在满级前任一天停滞，都退出非零。

**玩家体感**：属性克制有可追溯的武器来源；低品质装备若洗出真正罕见的 T4/T5
战斗词条，不会被挂机清包悄悄吃掉；四职业无论随缘穿装还是长期定向毕业，
产出差距都不会突然拉开。

**代价与后续**：动态保护本身包含 40 个战斗用途位置与最多 3 个基础元素武器位置；
这不是“总体最多超容量 43 件”的上限，永久锁定、高品质与待确认候选等硬保护仍可能
继续抬高保留量。这是“宁可多留、不可误删”的明确取舍。技能逐击元素与多套自动切换
仍归 M3-4、M5-7 / M5-8；接入时必须扩展同一元素权威与模拟门禁，不能恢复词条 fallback。

## ADR-021：公会首版展示化，防篡改分两层推进

**日期**：2026-07-30

**背景**：项目是纯静态 PWA，本地存档、校验代码和任何客户端密钥都能被玩家读取或改写。公会把多个玩家放进同一经济与竞争环境后，单机时代可接受的存档修改会变成装备复制、虚假贡献和排行榜污染。

**结论**：

- 公会首版只提供 20 人成员关系、公告、共享周远征和展示声望，不发装备、货币、全员属性或按排名发放的战力收益。
- 远征挑战只上传角色与 8 槽装备快照；Edge Function 用同一份核心逻辑复算伤害并归一化贡献。每日最多 3 次，只累计当日最佳成绩的新增差额，`requestId` 全局幂等。
- 防篡改分成两层：第一层为本地存档封装的摘要、递增修订号、备份恢复和异常提示，用来发现误改与低成本编辑；第二层为服务端权威资产账本，让装备 UID、货币、奖励来源和关键消耗以服务端记录为准。
- 客户端 HMAC、混淆或把密钥写进前端包不能称为真正防作弊；它们最多提高随手修改成本。交易、公会战力奖励和竞争性结算必须等待第二层完成。
- 服务端资产操作必须使用幂等请求 ID、单调 revision 与事务日志；客户端存档在联网资产上降级为缓存，断网时可继续单机挂机，但不能离线铸造可进入联机经济的资产。

**玩家体感**：当前公会可以一起打、一起看进度，但不会因为别人的改档破坏自己的养成；后续加强安全时，正常玩家仍可离线挂机，联网后只同步经过服务端认可的关键资产。

**代价与后续**：需要新增独立的存档完整性 OpenSpec，并分阶段迁移旧存档。第一阶段不承诺阻止高级篡改；第二阶段会增加 Supabase 存储与函数调用成本，也需要明确离线收益如何兑换成联机资产。

## ADR-022 · 本地存档完整性与联机资产权威分层

**日期**：2026-07-30

**背景**：项目是纯静态 PWA，玩家能读写自己的 IndexedDB。如果把密钥或签名逻辑
发到客户端，攻击者仍然可以取出并重算；但是对损坏、跨页竞态和低成本直接编辑，
仍需要稳定的检测、恢复与取证流程。

**决策**：

- `SaveData.version` 只表示业务存档结构；物理存储使用独立 `envelopeVersion`，
  因此本批保持 `SAVE_VERSION=12`。
- 信封按稳定键序列化计算公开 SHA-256，记录单调 revision 与前摘要；
  主档、备份和 IndexedDB revision 不一致时拒绝继续写入。
- 异常档不静默回退或覆盖。玩家可先导出原始诊断，再显式恢复备份；
  主备都损坏时只能经二次确认永久清空。
- 手动导入标记为 `imported`，不会因后续普通保存变成「本机可信」；
  导入文件携带的伪造服务端证明不会被接受。
- 只要装备、货币、交易或排行会影响其他玩家，权威仍必须转到服务端账本；
  客户端摘要不作为「这件装备确实打出过」的证明。

**玩家体感**：正常老档无感升级；存档损坏或被直接改写时会看到明确原因和
恢复选项，不再在后台悄悄覆盖。

**代价与后续**：每次保存需要稳定序列化和 SHA-256，并保留一份上次备份。
L5 服务端资产账本需要单独 OpenSpec，不得混入这个本地完整性 PR。

## ADR-023 · 体力每日免费领取定为 3 次 × 30 点，不限时段

**日期**：2026-08-02（M3-6 体力闭环，老板授权团队自定）

**背景**：docs/10 原写「每日免费领取 3 次 × 30 点（固定时段）」，但全项目没有任何
文档写明是哪三个时段。固定时段等于打卡设计：错过时段的玩家当天永久少拿，与
docs/40「不做惩罚『没上线』的机制」红线正面冲突。实现过程中曾短暂按 1 次 × 50
落地（存档 v22），经口径核对后于 v23 改回团队 08-02 18:53 决策的 3 次 × 30。

**结论**：

- 每日免费领取 3 次 × 30 点（共 90 点/日），不限时段；先结算自然恢复，再叠加
  一份 +30 额度，不超当前上限，当日已领满 3 次不再发放。
- 不限时段，按 businessDayKey（北京时间 04:00）日切，与好感 / 试炼 / 副本次数
  同一口径。
- 存档新增 `player.staminaClaimCount`（存档 v23），已领次数跨日归零。
- 实现为纯函数 `dailyStaminaClaim`（src/core/idle.ts）。

**原因**：保留 docs/10 §3.4 原数值口径（日均 288 自然恢复 + 90 免费 = 378 点 ≈
75 次扫荡），去掉「固定时段」的打卡属性；实现更简单，玩家不需要记住时段。

**代价**：固定时段一旦真有运营价值（如拉特定时段在线）就无法再用；若后续经济
模拟显示体力偏紧，应优先调恢复速率或免费额度，不再改回固定时段。

## ADR-024 · 图鉴集齐加成：PvE 战斗乘区，不进 CP、不进试炼/竞技

**日期**：2026-08-03

**决策**：怪物图鉴按区域集齐给 +0.5%/区伤害乘区（r1~r7 共 7 区 = 3.5% 封顶，
r8 后 4%，总上限 5%）；只挂机/副本（本地 PvE）生效；试炼/竞技场不生效；不进 CP。

**背景**：M4-8 图鉴账本落地后，docs/14 的「图鉴集齐给属性」需要定口径。候选是
面板 stats（与套装 2 件档同类）或战斗乘区；是否进 CP 需要拍板。

**结论**：
1. 形态用战斗乘区（CombatBonuses 专用字段），不用面板 stats —— 面板 stats 会经
   combatPower 自动进 CP，且会进入试炼/竞技的服务端复算；服务端拿不到可信图鉴
   状态（与好感战斗加成同待遇：buildTrialCombatant 注释「服务端无法验证，
   纳入会让复算失真」），纳入即制造复算不一致。
2. 不进 CP —— 与 docs/83 Q5（共鸣不进 CP）同原则：收藏奖励是养成面，不是
   静态强度口径；避免 CP_FORMULA_VERSION 连锁升级、结构上界重算与战力榜口径事故。
   战力面板加文案「不含图鉴集齐加成」，登记 KNOWN_RESIDUALS。
3. 生效范围挂机 + 副本；试炼/竞技场（arena-challenge 服务端复算、快照不带图鉴）
   不生效。
4. 幅值 0.5%/区，5% 总上限作未来区域数增长的保险；集齐 = 该区全部 monsterId 已发现。

**代价**：图鉴加成不出现在战力数字里，玩家对「图鉴收益」的感知来自实际刷图提速
（满图鉴约 +3.5% 伤害、TTK 5.0→4.8s 量级）；需在挂机/副本战斗路径接线并在 sim
加满图鉴样本复查。
