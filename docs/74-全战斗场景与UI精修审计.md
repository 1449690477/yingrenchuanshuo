公会接口当前只返回权威总伤害、承伤、时长、贡献和生还状态，不返回逐击日志。
表现层因此按固定拍子压缩播放这些真实总量，并明确写“60 秒战报压缩回放”；不重新计算
胜负、不调用随机数，也不伪造服务器逐击。每段拆分用 `splitExact` 保证相加后精确回到
服务器总数。

## 二、为什么公会复用试炼 Boss

`guildExpeditionBoss` 本身就复用周常试炼的“坚壳 / 幻影 / 狂怒 × 炎 / 冰 / 雷”数据模型，
同名首领应保持同一个形象。公会因此新制独立远征战场，但直接使用已通过尺寸、透明角、
残绿、体积和像素哈希审计的 9 张 Boss；这不是通用怪兜底，而是同一首领的正式资产复用。

公会新场景由内置 ImageGen 生成，母版、最终提示词与重建命令位于
`art-source/guild/`；运行时为 1536×1024 WebP、249KB，通过 `npm run assets:guild:check`。

## 三、UI 精修发现与修复

1. 排行榜子榜有 4 个标签，但选中滑块宽度仍写死为 `100% / 3`，导致白色滑块压住
   “登顶速度”。现由 `VIEW_TABS.length` / `BOARD_TABS.length` 直接注入 `--seg-count`，
   以后新增标签不会再次漏改分母。
2. 背包“装备 / 材料”分页只有 39px，三项批量操作只有 35px，排序仅 28px。
   现分别提升到 44px / 44px / 40px；320 宽仍保持单行、无横向溢出。
3. 竞技场首版实景改造时，人物立绘的固有高度曾把姓名和血条推出 3:2 画布。
   复查矩形坐标后改为 `grid-template-rows: minmax(0, 1fr)`，角色格固定 `height: 100%`
   并裁切；390 和 320 两档下姓名、职业、血条均落在画布内。

## 六、2026-08-01 公会非战斗 UI 精修

本轮继续处理公会页的非战斗部分，边界仍是只改展示与交互，不修改服务端结算、功勋、
声望、存档或团本伤害。

1. 原顶部横幅依赖内容自然撑高，在实际账号截图中塌成约 53px 的细条。现改为带
   `min-height` 的专用主庭院窗口，阶段信息、声望和进度都落在独立的暗色玻璃层内；
   390 / 320 实测高度为 168px / 180px。
2. 新增公会主庭院与赛季据点建设场两张 1536×1024 WebP。更多页公会入口、邀请码、
   今日建设委托和据点阶段均显示有明确地点含义的场景，不再用纯渐变卡代替画面。
3. 成员名册把“查看人物”和“会长移除”拆为两个独立按钮；人物详情复用榜单既有
   `PlayerPeekSheet`，但切换为“席位 / 公会名册 / 返回名册”语境，不再冒充排行榜。
4. 390×844 与 320×568 均完成首页、委托、据点、成员、详情实机截图；两档
   `scrollWidth === clientWidth`、可见图片破损数 0。320 下成员主按钮 58px、移除 / 关闭 /
   返回按钮均不低于 44px。

截图位于 `art-source/qa/guild-ui/`，素材提示词与母版位于 `art-source/guild/`；
`node scripts/validate-guild-assets.mjs` 现在同时检查团本战场、主庭院与赛季据点三张场景。
