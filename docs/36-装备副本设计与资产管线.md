# 36 · 镜界装备回廊：装备副本设计与资产管线

> 本文是 M5-1 / M5-4 的实现真相。数值、掉落、存档和美术路径以代码为准；
> 后续 AI 不得在 Vue 组件里复制规则，也不得用商店时装冒充副本装备外观。

---

## 一、玩家每天在做什么

装备副本名为 **「镜界装备回廊」**。玩家先选择缺少的部位，再选择品质档，
打完「前庭随从 + 守关者」两波自动实战后直接获得该部位装备。

- 8 个门户账号共享每日 **3 次成功领奖次数**；
- 北京时间 **04:00** 重置，失败不扣次数、不推进保底，也不改变主 RNG；
- 每个部位要按蓝 → 紫 → 橙 → 红顺序首通，高档不能越级开启；
- 普通胜利必掉 1 件；每个关卡首次胜利额外执行一次同表掉落，因此首通至少 2 件；
- 武器和礼服按当前职业定向，绝不会掉出其他职业专属件；
- 通用部位每档有两款。某一款连续两次没出现，下一次触发补偿并保留一次正常抽取，
  玩家会看到一次双掉或更多，而不是暗中重置普通奖励。

每日 3 次是“成功领奖次数”，不是入场券。这样玩家可以试战力、观察差距，再决定强化，
不会因为一次误点失去当天进度。

## 二、8 个门户与 32 个关卡

| 部位 | 门户 | 随从 | 守关者 | 设计重点 |
|---|---|---|---|---|
| 武器 | 星刃铸梦炉 | 线轴剑灵 | 誓刃锻造姬·芙蕾雅 | 攻击最高，检查生存 |
| 头冠 | 花冠云端帽坊 | 帽针精灵 | 星冠裁帽师·米蕾 | 命中与闪避 |
| 衣装 | 洛丽塔幻衣厅 | 蕾丝布偶 | 礼装人偶师·露西亚 | 血量最高，检查输出 |
| 项链 | 月链天象馆 | 坠星小灵 | 月相珠宝姬·赛蕾 | 暴击压力 |
| 手镯 | 蝶翼水晶温室 | 腕花蝶灵 | 晶蝶园艺师·芙洛拉 | 快速攻击 |
| 戒指 | 誓约宝戒书库 | 戒页书灵 | 誓戒典藏官·诺雅 | 精准反击 |
| 腰带 | 星缎织梦工房 | 缎带团子 | 织梦裁缝师·佩妮 | 稳定节奏 |
| 鞋子 | 星步舞会回廊 | 舞鞋精灵 | 午夜舞姬·可可 | 速度与闪避最高 |

每个门户各有 4 档，共 32 关：

| 档位 | 品质 | 开放等级 | 入场装备校准 | 套装 |
|---|---|---:|---|---|
| 晴蓝梦匣 | 蓝色稀有 | Lv20 | 区域 2 蓝装约 +3 | 晴蓝茶会 |
| 月紫星匣 | 紫色史诗 | Lv35 | 晴蓝全套约 +5 | 月紫星宴 |
| 琥珀蔷薇匣 | 橙色传说 | Lv50 | 月紫全套约 +8 | 琥珀蔷薇王庭 |
| 绯樱典藏匣 | 红色典藏珍品 | Lv78 | 琥珀全套约 +11 | 绯樱典藏 |

蓝、紫阶段装备生命成长较慢，敌人攻击倍率主动压低；橙、红阶段则主要提高血量，
把挑战放到限时输出上，避免“面板战力达标却被第二波两下带走”。

运行 `npm run balance:equipment-dungeon` 会对四职业、四档、八门户各跑 120 个种子，
共 15,360 场。验收线为总体胜率不低于 72%、单一最难门户不低于 60%、胜局均时不超过
70 秒。当前入场模板的实际最难胜率为 75%，其余组合为 93%～100%，胜局平均约
15～30 秒。

## 三、80 件装备矩阵

数量不是手写凑数，而是固定矩阵：

```text
4 个品质档 ×
（4 职业武器 + 4 职业礼服 + 6 个通用部位 × 2 款）
= 80 件
```

每一档恰好 20 件：

- 剑姬、魔女、灵巫、喵喵各 1 把职业武器；
- 四职业各 1 套职业礼服，包括骑士姬礼裙、魔女洛丽塔、祈灵华礼服与猫耳小礼裙；
- 头冠、项链、手镯、戒指、腰带、鞋各有“输出 / 灵巧”和“守护”两款。

每件装备有 1 条与定位相符的固定词条，其余词条继续使用原有 seeded RNG 随机生成；
胚子仍有稳定、精工、奇迹三档。副本装备不是商店固定模板，也不会借用
`boutiqueTheme`：礼服使用独立整人换装，头冠、鞋和武器使用独立纸娃娃层，
首饰在装备槽与套装粒子中表达。

装备定义集中在：

- `src/data/equipmentDungeonGear.ts`：80 件名称、职业、固定词条、图标和外观；
- `src/data/equipmentDungeonSets.ts`：四套 2 / 4 / 6 / 8 件共鸣；
- `src/data/equipmentDungeons.ts`：8 门户、32 关、两波怪物与掉落表。

## 四、套装共鸣

套装只统计当前八个穿戴槽，背包内装备不生效；混穿时每套独立计数。

| 套装 | 2 件 | 4 件 | 6 件 | 8 件 |
|---|---|---|---|---|
| 晴蓝茶会 | 攻击 +4% | 生命 +8% | 防御 +6%、暴击 +2% | 平均技能倍率 +0.05 |
| 月紫星宴 | 攻击 +6% | 生命 +10% | 防御 +8%、暴击 +3% | 平均技能倍率 +0.08 |
| 琥珀蔷薇王庭 | 攻击 +9% | 生命 +14% | 防御 +11%、暴击 +4% | 平均技能倍率 +0.12 |
| 绯樱典藏 | 攻击 +12% | 生命 +18% | 防御 +15%、暴击 +5% | 平均技能倍率 +0.18 |

纯函数 `resolveEquipmentSetBonuses()` 负责计数和激活，
`applyEquipmentSetStats()` 负责把百分比与固定值应用到最终属性。
store 只消费结果，并把 8 件技能共鸣接到挂机与装备副本的技能倍率。

## 五、存档与事务

`SAVE_VERSION` 从 v6 升到 v7，新增：

```ts
equipmentDungeon: {
  dayKey: string
  clearsToday: number
  totalClears: number
  records: Record<stageId, {
    clears: number
    firstClearedAt: number
    bestDurationMs: number
  }>
}
```

重复装备补偿沿用账号已有的 `progress.pity`，不制造第二套保底真相。
v6 → v7 迁移用旧档 `lastActiveAt` 计算 04:00 业务日，不伪造通关记录。

一次挑战先在纯函数内完整规划：

1. 检查等级、前置首通和每日次数；
2. 克隆 RNG，演算两波战斗；
3. 失败直接返回原次数、原保底和原 RNG；
4. 胜利后才掷掉落，并在局部变量中生成全部装备实例；
5. 所有定义、品质和部位验证通过后，store 才一次性提交次数、记录、保底、RNG、
   UID、背包与持久化。

因此配置错误不会留下“扣了次数但没装备”的半截存档。

## 六、美术资产

本批运行时资产共 **168 个**：

| 类型 | 数量 | 规格 | 运行路径 |
|---|---:|---|---|
| 门户战场 | 8 | 1536×1024 WebP，≤520 KiB | `assets/dungeons/equipment/` |
| 随从 / Boss | 16 | 512×512 RGBA WebP，≤140 KiB | `assets/monsters/equipment-dungeon/` |
| 装备图标 | 80 | 256×256 RGBA PNG，≤120 KiB | `assets/equipment/dungeon/<tier>/` |
| 四职业换装 | 64 | 640×960 RGBA PNG | `assets/characters/modular/dungeon/<tier>/` |

四职业换装每档 16 张：

- 4 张礼服为“角色已穿好衣服”的整人替换图，避免空衣服层错位或挡脸；
- 4 张职业武器层与 4 张花冠层由该档独立图标对齐到成熟纸娃娃锚点；
- 礼服整身图负责真实鞋型，4 张鞋层只叠加小型足下徽光，禁止把鞋图标放大成悬浮巨鞋；
- 项链、手镯、戒指、腰带在角色两侧装备槽和档位粒子中显示。

所有透明主体都由独立 ImageGen 调用生成纯 `#00ff00` 母版，再使用官方
`remove_chroma_key.py` 软遮罩与去绿边；地图直接生成不透明场景。

可重复构建与审计：

```bash
npm run assets:equipment-dungeon
npm run assets:equipment-dungeon:check
npm run balance:equipment-dungeon
```

构建脚本检查精确清单，禁止少文件、重复路径、错误尺寸、不透明四角、空主体、
明显残绿和超体积文件。装备副本大图不进入 PWA 首次预缓存，首次访问按需下载后使用
`CacheFirst` 保存 30 天，避免安装包一次塞入全部美术。

## 七、界面与验收边界

副本页按 390×844 竖屏设计：

- 顶部显示 32 关收集进度和今日 3 次奖励；
- 第一步用 4×2 网格选择部位，第二步选择蓝 / 紫 / 橙 / 红；
- 主舞台显示门户地图、守关者、我的 / 推荐战力、规则、套装节点与职业定向预览；
- 战斗弹窗真实使用规划出的两波血量、伤害、耗时、当前换装角色和怪物图；
- 奖励卡展示品质、胚子档、固定 / 随机词条，首通明确说明双掉；
- 所有动画覆盖 `prefers-reduced-motion` 和游戏内减弱动效。

完成定义：

1. `npm run verify`、`npm run build`、资产审计与平衡模拟全部通过；
2. 四职业分别检查礼服、头冠、武器和档位粒子，脸与手脚无遮挡；
3. 390×844 检查 8 门户、锁定、胜利双掉、失败不扣、红色典藏与窄屏滚动；
4. 刷新后 v7 次数、通关纪录和装备实例仍在；
5. GitHub Pages 部署后再次检查资源 404 与控制台 error。

本地最终验收结果：34 个测试文件 / 493 个测试全绿；168 个运行资产按精确清单通过
尺寸、透明度、残绿、边距和体积审计；15,360 场 seeded 模拟中入口档最差胜率 75%，
其余档位 93%～100%；390×844 下逐一切换 8 门户均无破图，首通真实掉落 2 件并自动
锁定，刷新后次数从 3 / 3 正确回读为 2 / 3，页面无横向溢出和控制台告警。验收截图
统一归档在 `art-source/qa/equipment-dungeon-*.png`。
