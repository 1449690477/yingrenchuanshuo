# 第一部分 · 给老板的操作页

## 1 一句话背景

上一批冰雪素材 **32 个文件全部是照着「绯夜」套描下来的**（18 个甚至逐像素一模一样），
现已从货架和 7-5 BOSS 掉落两条路一起下架。这份文档是发给画师重画用的。

## 2 需要随文档一起上传的附件

| # | 附件 | 用途 | 在文档里怎么说明 |
| --- | --- | --- | --- |
| 1 | **5 张角色基础图**（剑姬 / 魔女 / 灵巫 / 喵喵 / 樱酱各一张站立全身） | 让画师知道衣服要穿在什么身型上、手脚脸在哪 | 「这是要穿衣服的人，**请按这个身型和手脚位置画**」 |
| 2 | **2–3 张绯夜套的图** | **反面教材** | 「上一批就是照着这几张描的，**你画的必须和它们明显不一样**」 |
| 3 | **1 张冰雪货架场景图** | 正面基调参考（这张是原创的，可以用） | 「主题气氛参考这张，配色和质感照这个走」 |

> ⚠ **附件 2 的说明一定要写清楚是「不许长这样」**。
> 只把图丢过去、不写用途，画师大概率会当成模板再描一遍 —— 上一批就是这么出事的。

## 3 发包时贴给画师的话

把**第二部分**整段复制给它，然后补一句：

> 上面三组图我已经上传。第一组是身型参考，请照着画；第二组是**上一版的失败品，你画的必须和它明显不同**；第三组是气氛参考。

## 4 收到 zip 之后

放进工作目录后告诉我们一声，我们跑：**尺寸/透明度/命名校验 → 机器查重（防描图）→ 重建管线 → 十项门禁 → 恢复上架**。
恢复上架时**货架和 7-5 掉落两行要一起打开**，代码里已经留了注释。

> **退回时不用整份重发。** 若只是穿戴层锚点对不上（衣服画得没问题、只是位置不对），
> 重发**身型参考图 + 那一件的规格**就够了，省您的回合数。

⚠ **查重必须在您给的原图上做，不能等我们构建完再查。**
上一批就是我们自己的构建步骤（漂白提亮）把一张 1:1 复制洗成了「看起来不像」，
守卫因此报绿 —— 实测：母版对绯夜相似度 **1.0000**，构建后的成品只剩 **0.6950**。

## 5 ★ 两个必须提前知道的风险

1. **网页版 GPT 很难精确输出「640×960、透明底、手脚落在指定像素」的图。**
   如果它做不到，交付物仍然有用 —— 我们这边有重新定位的步骤，但**这一步需要人工逐件对齐，20 件不是几分钟的事**。
   发包时可以先让它出 **1 件**（建议先出「冰晶华年公主裙 · 剑姬」）看看精度，再决定要不要一次性全出。
2. **它一次会话画不完 32 件。** 建议按「先 20 件穿戴层、再 12 件图标」分两批，每批再分几次。
   分批时**每次都要重贴一遍身型参考和「不许长这样」那句**，否则后面几件会开始跑偏。

# 第二部分 · 给画师的正文（可直接整段复制）

## 一、你要做什么

为一款中国手机端二次元放置类 RPG 画一套**春节限定服装「冰雪华年」**，共 **32 个 PNG 文件**。

这套素材上一版**因为是照着游戏里已有的另一套服装描下来的、只改了颜色没改外形，已经全部作废**。
所以这次有一条**高于一切的要求**：

> ### ★ 每一件的**外轮廓**都必须是你自己设计的，和参考图里那套旧服装**一眼就能看出不同**。
>
> 只改颜色、只挪位置、只放大缩小、只左右镜像 —— **这四种都会被我们的机器查重直接拒收**，不看画得多好。
> 判断标准很朴素：**把两张图都变成纯黑剪影并排放，普通人应该一眼说得出「这是两件不同的衣服」。**

## 二、整体风格

- **主题**：中国春节 + 冰雪，**华丽、洁白、可爱柔和**。不要冷硬写实盔甲，不要欧美魔幻风。
- **主色**：象牙白、冰晶蓝、淡樱粉。
- **点缀**（少量、克制）：中国结红、银流苏、珍珠、雪花冰晶。
- **可读性**：这是手机屏幕上很小的一个人物，**先要能读出「白色礼服 + 职业武器」，再谈雪花珍珠这些细节**。
  不要把细节堆到缩小后糊成一团。
- **不要出现**：文字、字母、数字、logo、边框、背景场景、人脸五官特写、玫瑰、蝴蝶。

## 三、技术规格（每一件都必须满足）

| 项 | 要求 |
| --- | --- |
| 格式 | PNG，**带透明通道** |
| 背景 | **完全透明**（不是白色、不是绿色） |
| 穿戴层尺寸 | **640 × 960 像素** |
| 图标尺寸 | **256 × 256 像素** |
| 边缘 | 柔和抗锯齿，不要生硬锯齿边，也不要一圈半透明脏边 |
| 每个文件 | **只画那一个部位**，其他部位留空透明 —— 例如「鞋」那张图里**只有一双鞋**，没有腿、没有裙子 |

## 四、穿戴层 20 件

**这 20 件是「贴在角色身上的图层」**，会直接叠加在我上传的 5 张角色基础图上。
所以：

- **必须对准身型**。武器要在手里，帽子要在头上不遮脸，裙摆不能穿过腿，鞋底不能悬空或陷进地面。
- 同一件衣服要**为 5 个不同角色各画一版**（她们体型不同），但**看得出是同一套服装**。

白绒毛边礼帽，帽檐有雪晶点缀，**垂下银色流苏**。

> **★ 外轮廓必须变的地方**：**银穗必须垂到帽檐以外**，让剪影明显不是一顶光溜溜的帽子。
> 旧版是一顶贴合头顶的圆帽，剪影就是个半圆 —— 你的不能是。

⚠ 帽子的内容**必须集中在画面最上方**（960 高的画面里，只用最上面约 180 像素的范围），下面全部透明。

象牙白公主礼裙，裙摆上有雪花与珍珠，腰间一枚**小小的中国结**。

>
> 光是「把深红改成白色」是这次被作废的原因，**请务必真的改形状**。

#### ③ `shoes` —— 踏雪珍珠短靴（5 张）

白色短靴，靴面缀珍珠。

> **★ 外轮廓必须变的地方**：**靴口加一圈蓬松雪绒毛边**，剪影在脚踝处要明显鼓出来。

#### ④ `weapon` —— 5 个角色各不相同（5 张）

## 七、我们会怎么验收

你的交付会过一遍机器检查，**以下任意一条不过就整批退回**：

1. **文件名或尺寸不对**、背景不透明、边缘有脏边。
2. **外轮廓与旧套过于接近** —— 我们会把两张图都转成剪影后做形状比对。
   **只换色、只平移、只缩放、只镜像都会被这一步抓到**，不看颜色画得多好。
3. **同一套内部两件撞形** —— 例如 5 件武器里有两件剪影几乎一样。
4. 穿到角色身上出现**穿模、武器离手、帽子压脸、裙摆穿腿、鞋底漂移**。

> 第 2 条是这次重画的全部意义。**如果拿不准，就把你的图和参考图各自转成纯黑剪影并排看一眼** ——
> 看起来像同一个东西，就重画。

# 第三部分 · 我们自己的实测附录（不要发给画师）

## A 范围与判定依据

冰雪套共 38 个产出文件，**32 个必须重画，6 个是原创、不要动**。

| 类别 | 件数 | 判定 | 处置 |
| --- | --- | --- | --- |
| 穿戴层母版 | 20 | **全部描自绯夜**（18 逐像素相同 + 2 描后微调） | 重画 |
| 装备图标 | 12 | **全部描自绯夜**（轮廓 IoU 恰好 1.0000，仅换色） | 重画 |
| 攻击特效 | 5 | **原创**（对旧主题最高 IoU 0.55–0.67） | **保留** |
| 货架场景 | 1 | **原创**（与另一张场景感知差异 83/256） | **保留** |

被抄对象**全部是 rose-night 的运行时成品，不是它的母版**：
绯夜母版 `0cbaa27c7c793ad3` ≠ 绯夜运行时 `eda385cb3504b62c` = 冰雪母版 `eda385cb3504b62c`。
**只比母版的检查结构上看不见这批复制。**

## B ★ 根因：反抄袭守卫一直在，但它比错了两侧

`scripts/validate-ice-snow-assets.mjs` 同一个文件里三条路，产出质量与「有没有跨主题对照」**完全对应**：

| 路径 | 对照对象 | 产出 |
| --- | --- | --- |
| 特效（`:206`、`:239`） | 四个旧主题，**跨主题比** | **原创** ✅ |
| 穿戴层（`:402-405`） | source 与 target **两侧都是冰雪自己** | 全抄 ❌ |
| 图标 | **没有任何相似度检查**，只查尺寸 | 全抄 ❌ |

穿戴层那条的判定方向还是**反的**：

```js
if (alphaMismatch === 0) fail('与旧精品母版 Alpha 轮廓完全相同，属于换色复用');  // :380
if (mae < 24)            fail('与绯夜母版色差过小');                            // :393
```

它要求运行时**必须**与母版有差异。而实际发生的是漂白让 alpha 从 76017 膨胀到 97805（+29%）、颜色大改 ——
**正是这套伪装动作让它一路绿灯。守卫没有漏检抄袭，它给伪装发了合格证。**

帽区（`:375`）更直接：`slot === 'head'` 时 `alphaMismatch !== 0` **才**判失败，
即**帽子被强制要求与那份抄来的母版逐像素相同**。

阈值也是恒真的：`calibrateWearableShapeGate`（`:283`）拿**冰雪母版自己**当参照标定 0.95 ——
被抄的那张图既当被告又当尺子。

> **一句话教训：判据再精密（这条有 0.95 阈值、平移容忍、镜像比对、色差 MAE），比错两侧就全是装饰。**

## C 查重阈值：**0.96**

| 类别 | 合法侧实测分布 | 上界 |
| --- | --- | --- |
| 穿戴层（小库，运行时两两） | 0.2963 – 0.9065 | 0.9065 |
| 穿戴层（小榜，66 对） | — | 0.9053 |
| 穿戴层（小督，60 对） | — | **0.9325**（最保守，取它） |
| 装备图标（小库，同名两两） | 0.3320 – 0.8899 | 0.8899 |

冰雪两件微调品是 **0.9757 / 0.9952**，都在 0.96 之上。
⇒ **0.96 同时满足「不误伤合法」与「抓全 20 件」。**

> ⚠ 我一度建议 **< 0.90**，那是错的：合法侧实测已有 0.9053–0.9065 的样本，
> 0.90 会让**已上线的合法资产**当场红。开机即红的门禁不会被修，只会被关掉 —— 那等于回到没有守卫。
> **让合法样本失败的阈值不是更严格，是不可用。**

## C2 ★★ 查重必须在**母版层**做，查构建产物会放行

这是从线上真实字节量出来的，不是推演 —— 这批素材实际走过的就是这条路：

| 对比 | 轮廓 IoU |
| --- | --- |
| 冰雪**母版** vs 线上绯夜 | **1.0000**（完美复制） |
| **线上冰雪成品** vs 线上绯夜 | **0.6950** |

漂白让 alpha 从 76214 膨胀到 98050（**+28.7%**），包围盒从 340×408 撑到 423×506。

> **我们自己的构建步骤把一次 1:1 复制洗到了 0.6950 —— 低于任何人提过的阈值（0.90 / 0.96）。
> 任何只查构建产物的守卫，对这一整批都会报绿。**

⇒ **intake 顺序必须是**：
`zip → 校验命名/尺寸/透明 → ★查重（母版层）→ 才允许进 art-source → build → 十项门禁`。
**先 build 再查，等于我们亲手把描图洗干净然后放行。**

### C3 UI 下架 ≠ 文件下架

这 32 个文件在 `public/` 下，Vite 原样拷进部署。藏货架只是让界面不再引用它们，
**文件仍在固定 URL 上公开可取** —— 实测 `assets/characters/modular/shop/ice-snow/swordsman-body.png`
**HTTP 200、142443 字节**，图标与货架图同样 200。

> ⚠ 措辞要准：线上跑的是**漂白后的衍生物**，不是绯夜原图逐字节
> （线上冰雪像素哈希 `4f0c2aef283d6e45` ≠ 线上绯夜 `eda385cb3504b62c`）。
> 它**源自一次 1:1 复制、是衍生作品**，但别说成「线上直接摆着绯夜的原图」，会被一验就推翻。

要不要把这 32 个文件也从部署里撤掉（或换占位图）**是产品判断**。技术上两条都不会毁存档：
删文件 ⇒ 已持有玩家背包出现裂图；换占位图 ⇒ 优雅降级。
**装备定义无论哪条都不能删**（会 400，见 §B 与 `submit-trial/index.ts:195`）。

## D ★ 每条判据都必须先做对照组

今天三个人各错一次，形状完全相同：**用一把没验过分辨力的尺子下「这件没问题」的结论。**

- 不裁包围盒直接归一化 ⇒ 同一张图只量到 0.6491，`swordsman-head` 因此被三个人先后判为「原创」。
- 图标若整张不透明，alpha IoU 会毫无分辨力 —— 必须先确认合法侧分布不是一排 1.0000。

**做法**：拿一组**确定各自独立创作**的同类样本两两量。若合法侧分布也贴着上限，说明量具饱和，读数作废、换判据。

## F 必须保留的技术约束

1. **画布**：穿戴层 640×960、图标 256×256、特效 512×512、货架 960×640。
2. **人体锚点**：新轮廓仍须围绕原手部、脸部、膝腿、脚底锚点展开。
3. **帽区校正**：构建器对 `head` 槽做 `640×180 → 640×100` 纵向压缩后下补透明至 960
   （`scripts/build-ice-snow-assets.mjs:358`）。帽子有效内容必须落在**顶部 180px 内**。
4. 角色基础层在 `public/assets/characters/modular/{class}/base.png`，均为 640×960 —— 附件 1 取这五张。

## G 复现口径

`sharp` 解码为 RGBA raw → alpha > 8 视为可见 → 裁到 alpha 包围盒 →
`resize(64, 64, { fit: 'fill' })` → 逐像素交并比。
**换任何一步都会得到不同的数**，引用本文数字时请连口径一起引用。
