# 13 · 技能体系

> 传奇的技能特点：**少而精，每个都有辨识度**。
> 不要做成「50 个技能但没人记得住」。每职业 14 个，玩家能全部叫得出名字。

---

## 通用规则

- 技能分 **主动** / **被动**
- 主动技能在挂机中**自动释放**（按优先级 + 冷却），玩家只配置「技能栏」（最多 4 个主动）
- 技能升级消耗「技能书」+ 金币；主动伤害的总倍率通常每级绝对增加 `0.06`
  （例如 `1.50 → 1.56`），治疗与被动等按各自 `LevelScalar` 配置
- 技能等级上限 = 角色等级 / 2（向下取整）
- 每个技能有**属性**（炎/冰/雷/无），参与克制计算

### 技能字段

```ts
{
  id: 'skill_swordsman_flame',
  name: '烈火剑法',
  class: 'swordsman',
  type: 'active',
  element: 'fire',
  unlockLevel: 35,
  cooldownSec: 8,
  priority: 30,
  effects: [
    {
      kind: 'damage',
      target: { kind: 'primary-enemy' },
      multiplier: { base: 2.4, perLevel: 0.06 },
      element: 'fire',
    },
    {
      kind: 'trigger',
      event: 'on-hit',
      chance: 0.3,
      maxTriggers: 1,
      effects: [
        {
          kind: 'apply-status',
          target: { kind: 'primary-enemy' },
          statusId: 'burn',
          stacks: 1,
          maxStacks: 1,
          durationSec: 5,
          refresh: 'duration',
        },
      ],
    },
  ],
}
```

全部成长数值使用 `LevelScalar`；比例统一采用 `0.2 = 20%`，百分点另用
`percentage-points`。多段技能的 `multiplier` 是整次施法总倍率，`hitWeights` 只决定
每段相对伤害权重；视觉时间由 `skillVisuals.hitOffsetsMs` 指定。统一技能执行链使用
整数毫秒处理冷却、控制、持续伤害、护盾与召唤，只接收 seeded RNG。五职业全部读取
同一份 `SkillEffect` 数据，本地挂机、试炼、副本、竞技场和 Edge 复算不得另写职业特例。
状态条件必须显式写明读取自身还是主目标；状态倍率还要写明读取自身资源还是受击目标，
防止「剑意」与「猫爪印记」被错误地从同一侧读取。

可受击召唤物必须在召唤表显式登记 `targetWeight`，主人权重由 core 固定为 `1`。敌方每次
选取受击目标时使用 seeded RNG 按当前存活目标的权重抽取；召唤死亡后立即从候选池移除，
后续攻击自然回到主人，不能用组件状态或 `Math.random()` 另走一套选敌规则。

### 挂机自动技能演出卡组（2026-07-28 已接入）

挂机战斗窗口会从 `data/skills.ts` 与 `data/skillVisuals.ts` 自动生成技能卡带：

- 390px 宽时同屏展示 4 张，更多技能横向滑动；低等级不足 4 张时展示最近的真实
  解锁条件，不生成假技能；
- 卡片、战场动作与冷却共用 `core/battleRhythm.ts` 的稳定 `skillId` 和只读运行快照，
  切关、切职业、暂停或配置重排都不会把冷却串给另一技能；
- 自动轮转技能显示同源剩余冷却与最近拍子；治疗、召唤及带条件技能显示
  「条件待机」，不冒充对敌伤害；
- 点按卡片只打开详情抽屉，不会手动施放；触觉反馈只响应这次真实点按，自动轮转
  不会持续震动；
- 新职业只需登记技能、视觉定义、图标与基础攻击图，不允许在 Vue 组件中增加职业分支。

技能卡带是战斗结算事件的**视觉投影**：它只消费同源事件，不自行决定伤害、冷却或条件。
当前从 `DEFAULT_ACTIVE_SKILL_ORDER` 的职业显式顺序中筛选已解锁项并取前 4 栏；
`priority` 只决定多个已入栏技能同时就绪时先释放谁，不能兼任选栏价值。这样终极技、
双治疗不会挤掉低冷却循环和职业招牌技。M3-5 的玩家自选栏位只替换栏位输入，
不会更换效果执行器或另建一套伤害规则。满级默认栏为：

| 职业 | 默认四槽 | 设计理由 |
|---|---|---|
| 剑姬 | 天绝斩 / 逐日剑法 / 破魂斩 / 野蛮冲撞 | 冻结真实技能接入前的既有默认选择，避免夹带旧职业重排 |
| 魔女 | 末日审判 / 魔法盾 / 流星火雨 / 灭天火 | 冻结既有默认选择，保留脆皮保命与高投入群伤 |
| 灵巫 | 治愈术 / 召唤神兽 / 万灵归寂 / 群体施毒 | 只带一治疗、一召唤和两输出，避免双治疗挤掉核心毒术 |
| 喵喵 | 百爪樱岚 / 炸毛反击 / 纸箱奇袭 / 月影猫步 | 冻结既有默认选择，保留反击、破防和印记终结循环 |
| 樱酱 | 奥义·千樱居合 / 居合·一闪 / 破甲斩 / 拔刀斩 | 千樱叠剑意、破甲再叠一层、一闪消耗、拔刀补循环 |

## 六、职业平衡目标

五职业在**同等装备水平**下，挂机效率应该各有优势，不能有明显最优解：

| 指标 | 剑姬 | 魔女 | 灵巫 | 喵喵 | 樱酱 |
|---|---|---|---|---|---|
| 单体 DPS | 100% | 95% | 85% | **105%** | **105%** |
| 群体 DPS | 85% | **125%** | 90% | 105% | 95% |
| 生存能力 | **120%** | 70% | 105% | 75% | 85% |
| 离线稳定性 | 105% | 85% | **120%** | 85% | 95% |
| BOSS 战 | **110%** | 100% | 90% | **115%** | **115%** |

> 「离线稳定性」指长时间无人值守时不会因为死亡中断挂机。
> 魔女数值最高但需要玩家更用心堆装备 —— 这是**给高投入玩家的回报**，合理。

**实现方式**：职业差异靠 `CLASS_ATK_MUL` 百分比系数实现，**不是**靠每级属性成长。
原因见 [ADR-007](32-决策记录.md) —— 装备是职业通用的，会把线性属性差异冲淡到失效。

```
剑姬 1.00 × spd 1.0 = 100%
魔女 1.06 × spd 0.9 =  95%
灵巫 0.86 × spd 1.1 =  95%
喵喵 0.76 × spd 1.25 = 95%
樱酱 0.85 × spd 1.15 = 98%
```

**平衡验证方法**：跑 `npm run sim`。词条样本必须覆盖普通到圣器的全部品质，并在
Lv120 再验区间末端；脚本同时校验基础角色、新鲜掉落、全 T5 与八件职业槽的
**可达混合输出 T5 极值**四层真实 `killsPerSecond`。极值层会枚举同职业多种输出
词条的全部槽位分配，任何一层在任一等级段偏离均值 ±20% 以上都会退出非零，
不能只测“八条同 key”，也不能只打印红表后继续通过。

完整职业专属池生成采用“先输出 / 生存各 50%，再在定位内按权重抽具体词条”。
重铸会先排除旧 key 与同件已占用 key，然后只在剩余仍有候选的定位间等概率抽取；
若一个定位已无候选，就只抽另一个定位。这样魔女有两条输出词条、灵巫有三条生存词条，
也不会因为池子条数不同而改变完整候选池的两种定位总概率，更不会为维持表面 50 / 50
而生成重复词条。
下表是 2026-07-29 的四职业旧基线，只保留作迁移前对照，不再作为五职业真实技能执行器
的验收结论：

| 等级 | 剑姬 | 魔女 | 灵巫 | 喵喵 |
|---|---|---|---|---|
| 10 | +7.3% | +8.0% | −15.7% | +0.4% |
| 30 | +4.6% | +2.3% | −7.6% | +0.8% |
| 50 | +0.7% | +2.7% | −4.7% | +1.3% |
| 70 | +1.1% | +2.0% | −4.1% | +1.1% |
| 90 | +1.2% | +1.8% | −3.9% | +0.9% |

四层门禁的最大偏离依次为 **15.72% / 13.73% / 17.80% / 18.03%**，
全部在 ±20% 内。Lv10 基础偏差最大是因为低等级时裸属性占比高、装备还没起作用。

完整验收必须重新跑五职业四层 `npm run sim`；单体 Boss、普通多目标、治疗续航、召唤与
控制都读取真实技能事件。旧的 `averageSkillMultiplier` 结果只能作历史对照，不能拿来证明
新执行器平衡。
