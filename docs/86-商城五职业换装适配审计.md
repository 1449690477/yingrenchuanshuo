# 商城五职业换装适配审计

> 负责人：小锻  
> 日期：2026-08-03  
> 范围：珍品商城与竞技场荣誉商店全部 70 件在售装备 × 五职业；纸箱猫专属套另行保留原整身替换合同。

## 一、先把“穿上正确”写成可验证合同

商城商品不是“文件存在”就算完成。一个可见换装槽必须同时满足：

1. 数据层把当前职业解析到它自己的图层，禁止跨职业复用；
2. 运行时层是 640×960 RGBA，与职业底模共享脚底锚点；
3. 衣裙、头饰、鞋和武器分别停在对应身体区域，武器还要命中持握或佩刀锚点；
4. 整身图必须走 `replacementClasses`，普通衣裙才走 `layer`；
5. 整套与单件试穿都要真实改变外观，且脸、鞋、帽不能被旧底模重新覆盖；
6. 不只比较完整 PNG SHA，还比较逐像素 alpha 轮廓；同轮廓改色不能冒充独立设计；
7. 390×844 与 320×568 的真实商店详情页无破图、无横向溢出、无控制台错误。

自动门禁为 `node scripts/audit-shop-appearance.mjs`，输出：

- `art-source/qa/shop-appearance-audit.json`：每张图层与攻击演出的 bbox、alpha 像素、武器锚点、完整 SHA-256 与 alpha SHA-256，并记录商品图标在白底上的平均亮度与近白比例；
- `art-source/qa/shop-appearance-contact.webp`：同一张接触表横向比较五职业，纵向比较商城主题；
- `art-source/qa/shop-appearance-icons-contact.webp`：把珍品店与荣誉商店全部 74 张商品图标放在同一白底矩阵里，直接检查错图、空图和近白消失；
- `src/data/__tests__/shopAppearanceVisual.spec.ts`：把解析模式、职业路径和像素合同纳入常规 Vitest。

## 二、实锤缺陷与根因

### 1. 旧离线预览永远漏掉第五职业

`scripts/appearance_preview.py` 的职业数组仍只有剑士、魔女、萨满、喵喵。旧报告即使全绿，也没有渲染过樱酱。现已补到五职业，并让樱酱商城衣裙在离线合成中按整身替换处理。

### 2. 樱酱商城衣裙素材是整身图，数据却按普通衣裙层解析

四套商城的樱酱 body bbox 均覆盖近乎完整人物（约 x110..545 / y4..925），但 `buildBoutiqueAppearances()` 没有给 body 声明 `replacementClasses: ['kenshi']`。实际流程因此是：

`base-noshoes → 完整樱酱人物再叠一遍 → 鞋 → 把旧底模脸覆盖回来 → 帽 → 刀`

与正确整身替换逐像素对比，莓霜、月糖、绯夜分别约有 8.4 万、7.6 万、9.6 万个颜色通道被错误改写，绯夜脸部最明显。正确流程应为：

`樱酱整身衣裙作为 base → 鞋 → 该衣裙自己的安全脸层 → 帽 → 刀`

通用修复会同时覆盖旧三套和新增冰雪套；不能把商品 body 直接设为全职业 `replacement`，否则会误伤仍是普通衣裙层的老四职业。

### 3. 绯樱星愿剑士礼帽帽檐压眼

旧层 bbox 为 x249..395 / y9..138，整帽过大且下沉。现由透明母版确定性重建为 130px 宽、锚点 (258, 0)，bbox 固定为 x258..387 / y0..114；帽檐离开眼睛安全区，其他职业不受影响。

重建命令：

```bash
node scripts/build-shop-appearance-fixes.mjs
node scripts/build-shop-appearance-fixes.mjs --check
```

### 4. 冰雪馆白底图标可辨识度

只读复核发现首轮冰雪图标中剑士/魔女武器在白底接近消失。加描边后的单轴亮度门禁一度显示通过，但 74 图白底接触表仍能看到二者在 96px 接近消失，而真实商品卡只有 58px：剑为 `meanLum 208.73 / meanChroma 6.6 / darkRatio 28.4%`，法杖为 `207.96 / 7.0 / 29.0%`。同亮度的莓霜武器因平均色差 57/63 仍可辨，说明只看平均亮度会假绿。

最终白底合同同时守三种可辨来源：原有 `meanLum <= 228 / nearWhite <= 45%` 保留；若 `meanLum > 205`，则平均色差必须 `>= 16`，或亮度不高于 200 的实色像素至少占 40%。当前 74 张只精确拒绝冰雪剑与法杖，修复要求是加深霁蓝轮廓/核心阴影，不改动已经清楚的其余 72 张。

### 5. 冰雪穿戴层与攻击演出是绯夜同轮廓改色

首轮门禁只比较完整 RGBA SHA，因此“保持 alpha 不动、只重着色”会被误判为独立素材。二轮逐像素复核确认：

- 冰雪 body / shoes / weapon 三槽 × 五职业共 15 张运行时层，与绯夜同职业同槽的 alpha SHA-256 一一相同；
- 冰雪五职业 512×512 攻击演出与绯夜对应演出的 alpha 差异像素均为 0；
- 生成器文件头也明确写着沿用 `rose-night` 透明层、只改颜色和纹样。

这不是锚点复用，而是完整轮廓复用；例如冰雪剑士演出仍是蔷薇刀光，只漂成近白，和“冰晶雪花、银穗、新春”设计不符。该批次在 20 张素材换成独立设计前 HOLD Pages；新门禁会永久拒绝同 alpha 轮廓改色。

### 6. 荣誉商店樱酱戒指是假可见层

荣誉商店共有五职业 × 四部位 = 20 件。武器、头饰、战衣与樱酱戒指共登记 16 张直接上身层，老四职业戒指保持 `slot-only`。但樱酱 `blinkbloom-return-ring.png` 只有 242 个 alpha 像素，来源是把商品图标缩到人物画布；在手机人物上几乎不可辨，也不符合“真实可穿层”合同。该层必须改成贴合手部的圣痕环与小型樱花光晕，达到 `alphaPixels > 2000` 且右手/手腕锚点内 `alpha >= 900`；不能通过隐藏成 `slot-only` 或把光效移到人物别处消债。

### 7. 樱酱整身替换图仍含鞋，混穿时会叠出两双鞋

把 body 改成 `replacement` 只能修复“双身体”，不能自动修复“双鞋”。旧莓霜、月糖、绯夜与首轮冰雪的樱酱 body 都画了完整鞋履；解析器随后又按商品合同叠加独立 shoes。同主题颜色接近时不明显，跨主题混穿便会同时露出两种鞋型。

不能把 `shoes` 塞进 `replacementIncludes` 来隐藏问题，因为商城鞋是独立在售商品，玩家穿上必须看到变化。最终合同是：

- 樱酱 body 保持完整角色与衣裙，但鞋履遮罩内必须和 `base-noshoes` 一致；
- 独立 shoes 继续由解析器叠加；
- 门禁用每套真实鞋层作为遮罩，比较 body 与 `base-noshoes` 的预乘 RGB MAE 和 alpha MAE，两项均不得超过 0.1；
- 同一合同扩展到樱酱 R1–R7 普通区域、四档副本和莓霜/月糖/绯夜精品共 14 张 replacement body，由 `assets:kenshi` 门禁负责；冰雪精品另由冰雪管线负责。赤金/幽影/血月套装没有随后叠加的独立可见鞋层，必须保留整身鞋型，不能误裁成赤脚。

### 8. 纸箱猫不能套用樱酱的无鞋合同

进一步把“卸下鞋”和 `slot-only` 鞋纳入后，发现喵喵 `base-noshoes` 在脚踝以下是透明的；若把纸箱猫照樱酱精品裙裁成无鞋 replacement，玩家会直接少掉双脚。纸箱猫商品本身是自带键帽靴的完整机动工装，且本主题没有独立鞋商品，因此正确合同是保留完整专属靴，并声明 `replacementIncludes: ['shoes']`：外部鞋层不再重复叠加，解析结果把鞋列入 `silentVisualSlots`，界面能诚实说明“当前整身工装不会改变鞋外观”。

樱酱四套精品裙仍使用无鞋 replacement，因为这些主题各自确实出售独立 shoes；两类完整造型不能只因都叫 replacement 就套同一裁法。

### 9. 饰品文案把“系列演出”误写成“逐件可见外观”

项链、手镯、戒指和腰带没有独立纸娃娃层，运行时只会启用当前穿戴中品阶最高的精品主题。旧商城详情与背包装备详情却直接展示 `uniqueEffect`，会让玩家误以为每件饰品都能单独触发描述中的视觉。

现由共享 `equipmentVisualPresentation()` 统一商城和装备详情：有真实层的商品标“专属视觉”；无独立层的精品饰品明确标“系列演出”，并写明只在该主题是当前最高品阶主题时启用；非精品 `slot-only` 只说明没有独立人物层，不再冒充尚未接入的技能机制。

### 10. 320×568 商城详情被底层“更多”页撑出视口

商城作为绝对定位子页打开时，底层 `.more-content` 只加了 `inert`，仍参与父容器高度计算。实机回验中详情面板底部到 777px，超出 568px 视口，购买按钮无法正常参与操作。

打开商城、公会或图鉴时现同步隐藏底层内容；320×568 复测详情底部为 500/568，关闭按钮 44×44、焦点正确，文档宽度 320/320，无横向溢出。该条件已进入组件回归测试。

## 三、矩阵结果

- 四套主题目标为 4 × 5 × 4 = 80 张运行时可见层，纸箱猫另有 2 张专属层；当前冰雪 15 张同轮廓复制仍待替换；
- 商品卡片：四套主题 48 张图标 + 纸箱猫 2 张图标 + 4 张樱酱衣裙职业展示图，共 54 张均为 256×256 RGBA，并通过白底 `meanLum <= 228 / nearWhite <= 45%` 可辨识门禁；
- 攻击演出：四套 × 五职业 + 纸箱猫 = 21 张 512×512 RGBA；当前冰雪 5 张同轮廓复制仍待替换；
- 混穿解析：四套 body × shoes × head × weapon × 五职业 = 1,280 个组合逐一检查底模、层序、素材来源和可见槽计数；
- 荣誉商店：20 件商品图标 + 16 张直接上身层，连同珍品店共 74 张实际商品展示图、98 张运行时上身层；
- 跨店混穿：珍品整身 / 荣誉战衣分别与另一商店的帽、鞋、武器组合，检查 replacement 不双脸、不双底模且层序稳定；
- 老四职业：衣裙保持独立层，穿鞋时使用 `base-noshoes`；
- 樱酱：衣裙为整身替换，帽/鞋/刀继续独立叠加；
- 武器：二十把珍品商城职业武器全部命中各职业持握区，樱酱使用已定稿居合佩刀区；
- 纸箱猫：body 继续整身替换、weapon 独立叠加，不向其他职业暴露。

最终门禁固定覆盖珍品店 82 张可见层 / 54 张展示图与荣誉商店 16 张可见层 / 20 张展示图，合计 98 层 / 74 图；以后新增商品而计数不变即视为门禁漏项。
