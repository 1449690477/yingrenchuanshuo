## 一、现状诊断

以下是立项时的旧系统诊断，保留用于说明为什么要改；本轮实施后的真实状态见后文。
旧系统在 `data/constants.ts` 的 `AFFIX_POOL` 中共有 12 条：

| 现状 | 问题 |
|---|---|
| 12 条词条**全部通用**，四职业共用一池 | 没有职业身份，剑姬和魔女洗出来的东西一样 |
| 词条**只在掉落时掷一次，永久固定** | 没有任何重掷途径，装备到手即定终身 |
| **12 条里有 4 条不进战斗结算** | `dmgReduce` / `elemDmg` / `lifesteal` / `skillMul` 在 `applyAffix` 里直接 return，注释写着「M5 再处理」 |
| 数值是 `rng.float(min, max)` 的连续值 | **玩家看不出这条洗得好不好** —— 这是「洗词条没意思」的根本原因 |
| 普通品质词条数为 0 | 白装完全没有词条 |

> **最关键的一条是第四条。** 一个 `atk +37` 和 `atk +42`，玩家无法判断哪个接近上限。
> 没有「好坏可辨」，就没有「值得再洗一次」。

### 1.1 本轮实施状态

- 五档品阶、职业槽、重铸 / 淬炼 / 定契 / 铭刻 / 同调、20 点共鸣保底均已接入。
- 付费候选与原词条同时写入 v11 存档；刷新后仍须由玩家选择「采用」或「保留原样」。
  生成、采用、保留只有在 IndexedDB 写事务完成后才返回成功，失败会完整回滚本次事务。
- `dmgReduce` / `elemDmg` / `lifesteal` 已接入真实伤害、吸血与挂机承伤效率。
- 当前可生成 11 条通用词条、11 条职业专属词条；完整职业候选池先按输出 / 生存
  各 50% 选择定位，再在定位内按权重抽具体词条。重铸先排除旧 key 与同件已占用 key，
  再只在剩余有候选的定位中选择，某定位耗尽时不会为维持表面 50 / 50 放回重复词条。
- `skillMul` 仅为 v9 旧档兼容保留，不进入新掉落和新候选，也不能继续淬炼或同调。
- 基础攻击元素只读已穿武器定义；`elemDmg` / `wit_elem` 只加成同系攻击，

  都有同级或更早的真实武器来源。

## 二、核心结构

新体系由**四层**组成，缺一不可：

```
装备实例
 └── 词条槽（数量由品质决定）
      └── 每个槽 = 词条类型 × 词条品阶
                    │            └── 五档，决定数值系数（这一层是新增的核心）
                    └── 来自「通用池」或「职业专属池」
```

### 2.1 词条槽数量

| 品质 | 原值 | **实施值** | 其中职业专属槽 |
|---|---:|---:|---:|
| 普通 common | 0 | **1** | 0 |
| 精良 fine | 1 | **1** | 0 |
| 稀有 rare | 2 | **2** | 0 |
| 史诗 epic | 3 | **3** | 1 |
| 传说 legendary | 4 | **4** | 1 |
| 神话 mythic | 5 | **5** | 1 |
| 棱彩 prismatic | 6 | **6** | 1 |
| 神圣 divine | 6 | **6** | 1 |

**「职业专属槽」的含义**：该槽位**只能**出当前职业的专属词条。
这保证史诗以上装备一定带职业特色，而不是靠运气。

> ⚠ 普通品质从 0 条改为 1 条，会让最低档装备也有词条。
> 这是所有者明确要求的「装备全部都要加上词条」。
> 由此带来的整体战力抬升必须跑 `npm run sim` 复验，见第七节。

### 2.2 词条品阶（本次设计的核心）

**同一条词条也分五档。** 这是让「慢慢养成」成立的机制。

| 品阶 | 名称 | 权重 | 出现概率 | 数值系数 | 建议配色 |
|---|---|---:|---:|---:|---|
| T1 | 粗糙 | 40 | 40% | **0.62** | `--q-common` 灰 |
| T2 | 普通 | 27 | 27% | **0.76** | 白 |
| T3 | 优良 | 18 | 18% | **0.88** | `--q-fine` 绿 |
| T4 | 卓越 | 11 | 11% | **1.10** | `--q-rare` 蓝 |
| T5 | 极品 | 4 | 4% | **1.64** | `--q-legendary` 金 |

**数值公式**

```
词条数值 = 基准值(装备等级) × 品阶系数 × (1 ± 3% 微浮动)

其中 基准值 = (AFFIX_POOL 的 min + max) / 2 × 等级缩放
     等级缩放 = scalesWithLevel ? level^1.3 : 1
```

微浮动只有 ±3%，**刻意做得很小** —— 让玩家一眼读的是「品阶」而不是小数点。
品阶名与颜色必须直接显示在词条上。

**期望值推演**

```
新鲜掉落的期望系数 = 0.40×0.62 + 0.27×0.76 + 0.18×0.88 + 0.11×1.10 + 0.04×1.64
                   = 0.7982
全 T5 完美系数     = 1.64
```

> 词条区间从新鲜掉落的期望值到全 T5 约提升 **105%**；映射到整套装备总战力后，
> 2026-07-29 配对抽样实测为 **+12.46%～24.69%**（门槛 +12%～25%）——
> 词条只占总战力约两成，不能把词条局部倍率误写成整套战力倍率。
>
> ⚠ 神话以上职业槽由 2 降为 1：职业池虽已补到每职同时拥有输出 / 生存定位，
> 但两槽会显著放大玩家定向追逐可达输出组合 T5 的极值。恢复前必须扩展组合门禁，
> 不能只凭“词条条数够了”解除限制。

### 3.2 职业专属池（当前 11 条可生成）

**设计原则**：每个职业必须同时有至少一条输出与一条生存词条。完整候选池生成职业槽时，
先在 `offense / sustain` 两个定位中等概率选择，再在选中的定位内按权重抽具体词条。
因此增加一条生存词条不会偷偷提高该职业整类生存词条的总概率。重铸必须先排除
被替换的旧 key 与同件已占用 key，再在剩余仍有候选的定位间等概率选择；若只剩一种
定位可用，就只从该定位抽取。

基准值不再机械地按“通用同类 +30%”推导，而是由真实 KPS 四层门禁反推；
玩家八件职业槽的**可达混合输出 T5 极值**也必须在 ±20% 内，不能只验八条同 key。

## 四、洗练玩法

### 4.1 四种词条操作 + 一种临时保护

洗练的深度来自**同一件装备上多种互斥的资源分配**，不是靠堆按钮。

| 类型 | 材料 | 效果 | 玩家在决策什么 |
|---|---|---|---|
| **重铸** | 洗练石 | 随机重掷**一条**词条：类型与品阶全变 | 这条我不要了，赌一个更好的 |
| **淬炼** | 凝晶砂 | 从未定契词条中随机一条，**只重掷品阶**，保留类型与属性系别 | 这批类型我满意，只想赌更高档 |
| **铭刻** | 职业徽记 | 只改写史诗以上装备末尾的**预留职业槽**，候选来自当前职业专属池；不能改通用槽或新增职业槽 | 用稀有材料换确定性 |
| **同调** | 同调结晶 | 玩家指定一条，确定**提升一个品阶** | 攒着突破瓶颈，还是现在就用 |
| **定契（临时保护）** | 定契符 | 只在重铸 / 淬炼前锁住若干条，本次不动；铭刻不接受定契 | 保几条？锁得越多越贵 |

> **「淬炼」是这套系统里最重要的一个操作。** 它把「词条类型」和「品阶」拆开，
> 玩家先用重铸凑齐想要的词条组合，再通过定契缩小范围、用淬炼把品阶慢慢推高 ——
> **这才是「慢慢养成到位」的实际路径**，而不是无脑重掷。

### 4.2 消耗公式

设装备需求等级 `L`、当前词条品阶 `T`（1~5）：

```
重铸（换一条）
  洗练石 = ceil(L / 5) + 1
  金币   = L × 50
  当前区域两个 common 材料 = 各 10
  当前区域 fine 材料        = 2

淬炼（只洗品阶）
  凝晶砂 = ceil(L / 4) + T          ← 品阶越高越贵，防止无痛刷满
  金币   = L × 80

定契（锁定）
  未锁任何词条时 = 0
  锁 N 条的总价 = 2^(N-1)           ← 锁 1 / 2 / 3 / 4 条为 1 / 2 / 4 / 8
  锁定在本次操作后解除

铭刻（保专属）
  职业徽记 = 1
  同时仍需支付一次重铸的洗练石与金币
  只能改写预留职业槽，不可使用定契符

同调（升一阶）
  同调结晶 = T                      ← 从 T4 升 T5 需要 4 个
  金币     = L × 300
```

**定契的指数成本是这套系统的核心张力**：
锁 1 条很便宜，锁 4 条要 8 个定契符。玩家必须判断
「哪几条值得保、哪几条可以赌」，而不是全锁了无脑刷。

### 4.3 保底：共鸣值

纯概率会让非酋玩家连续几十次洗不出高阶而弃坑
（`docs/12` 已有同源结论）。

```
每次重铸 / 淬炼后：
  出 T1 → 共鸣值 +3
  出 T2 → 共鸣值 +2
  出 T3 → 共鸣值 +1
  出 T4 或 T5 → 共鸣值清零

共鸣值 ≥ 20 时，下一次操作**必定出 T4 或以上**，然后清零。
```

共鸣值**按装备实例单独记录**，存档字段见第六节。
自然出 T4+ 的概率是 15%，不考虑共鸣时平均约 6.67 次出现一次。
共鸣不是“固定洗 20 次”：T1 / T2 / T3 分别加 3 / 2 / 1 点，何时到 20
取决于实际结果。固定种子抽样中，平均约 5.4 次得到一条 T4+，保底贡献约 22.8%；
进度条在每次低阶结果后都有反馈，但正常高阶掉落仍会立即清零。

### 4.4 铁律：绝不强制覆盖

**每次洗练的结果必须先展示，由玩家选择「采用」或「保留原样」。**

这条是硬要求，理由见 [`40-玩法设计透镜.md`](40-玩法设计透镜.md) 红线清单：
强制覆盖会制造「洗坏了」的挫败，属于惩罚性机制。
材料在**点击洗练时**扣除（保证有成本），
但**结果是否采用由玩家决定**。

## 六、存档与数据结构

### 6.1 `Affix` 结构扩展

```ts
export interface Affix {
  key: AffixKey;
  value: number;
  element?: Element;          // elemDmg / wit_elem 的火、冰、雷系别
  tier: 1 | 2 | 3 | 4 | 5;
}
```

定契只是一笔操作的临时选择，不写进 `Affix`，避免把已经失效的锁定状态留在存档。

### 6.2 `EquipmentInstance` 新增字段

```ts
/** 洗练共鸣值，0~20，满 20 下次必出 T4+ */
reforgeResonance: number;

/** 已扣材料但还没有采用 / 保留的候选 */
pendingAffixChange?: {
  operation: 'reforge' | 'temper' | 'inscribe' | 'resonate';
  affixIndex: number;
  candidate: Affix;
};
```

`pendingAffixChange` 必须指向现有随机词条；候选必须符合目标槽位、去重、
装备等级、品阶、±3% 浮动与小数精度。淬炼必须保持类型和元素，同调必须
严格提升一级。导入存档时不满足这些语义条件会直接拒绝，不以“修一修再读”掩盖坏档。

付费事务的“完成”以 IndexedDB 提交为准，不以 Pinia 内存已经改过为准：

1. 事务等待期间暂停实时挂机 tick，并拒绝第二笔洗练，避免 RNG 或资产交叉写入；
2. 普通自动保存若在此期间被请求，会在事务结束后补写，不得插到付费快照前后制造乱序；
3. 等待期间若页面 hidden→visible，只登记一次延迟恢复；提交或回滚完成后才统一做离线
   结算并恢复循环。`pagehide` 使用显式暂停状态，不依赖可能仍为 `visible` 的页面属性；
4. 真正的 IndexedDB 写失败使用 `SaveWriteError` 返回 `persistence-failed`，精确恢复
   金币、材料、RNG、词条、候选与共鸣；采用后的战力提示也只在写盘成功后触发；
5. 每个标签页记住最后读取的 revision；保存会在同一个 IDB 事务内完成
   “比较 revision → 备份旧主槽 → 写新主槽 → revision+1”。另一标签已先写入时返回
   `SaveConflictError`，本页回滚当前洗练、停止挂机与后续自动保存，并明确要求刷新；
6. `clearSave` 与保存共用写队列，并在同一 IDB 事务里先比较本页 revision、再写入递增
   revision 墓碑；旧标签既不能覆盖、也不能删除另一标签的新档。重开角色等待清档期间会
   隔离旧内存档并门禁保存、导入、新建、前后台恢复与循环启动，确保没有旧快照排在墓碑后
   “复活”；清档冲突同样停机提示刷新；
7. 页面在载入存档期间进入后台时，初始化完成也不会抢跑 rAF；回到前台只恢复一条循环。
   重复 `pagehide` 不覆盖首次离线起点，避免同一段后台时间重复或漏算；
8. Zod / 配置校验错误不是“存储失败”，恢复事务现场后仍继续抛出，不能被友好提示吞掉。

### 6.3 存档迁移

**历史：v9 → v10（首次接入洗练持久化）**

- 旧装备实例的每条词条按其数值反推品阶：
  `tier = 数值 / 基准值` 落入哪个系数区间就是哪一阶，
  落在区间外则就近取，**保证迁移后战力不变**。
- `reforgeResonance` 初始化为 0。
- v9 不存在待确认候选，因此迁移时不伪造 `pendingAffixChange`。
- 普通品质装备原本 0 词条，迁移后**不补发**词条（避免旧号凭空变强）；
  新掉落的普通装备才带 1 条。

**当前：v10 → v11（最终词条重标）**

- `SAVE_VERSION` 升至 **11**，不把元素静态定义接入误写成升级原因。
- 迁移入口先用**发布版 v10 的冻结规则**验证整份旧档，再进行任何重标、换槽或退款：
  装备 ID 使用当时 235 项白名单，不能反向接纳后续新增定义；重复 key、未知字段、非有限值
  与非法 pending 直接拒绝，不能被归一化“洗成合法”，更不能因此铸造徽记。发布版对
  existing affix 只要求有限数，因此不拿随机候选的掷骰范围 / 精度反查历史成品。
- 对旧档 `swd_heavy 9.1→27`、`wit_power 0.78→0.53`、
  `wit_elem 8.5→4.3`、`cat_swift 0.039→0.027` 按基准值比例迁移；
  `sha_spirit` 是本轮新词条，没有 v10 旧值需要搬迁。
- 所有 T5 词条在上述职业基准比例之外再乘 `1.64 / 1.54`；普通词条与职业词条
  一视同仁，不能只迁移当前穿戴或只迁移四个职业 key。
- existing affix 只按旧 → 新比例重标并保留发布版已接受的历史价值，**不夹回**后来才定义
  的随机区间；v9 反推旧品阶固定使用 v10 的 `0.62 / 0.76 / 0.88 / 1.10 / 1.54` 快照。
  待确认的重铸 / 淬炼 / 铭刻候选先按 v10 发布规则严格验真，重标后才投影到 v11 当前
  可生成离散边界，避免边界舍入导致整档拒读。待确认同调必须先验证为合法 v10 晋阶，
  再根据迁移后的 target 与 v11 相邻品阶比例**精确复算**。全程不重掷类型、品阶、元素、
  微浮动或 RNG 状态。
- v11 同时收紧“每件最多一个职业槽”的结构：旧职业词条若位于通用区，按
  `品阶 → 当前区间百分位 → 原本已在预留槽 → 原索引` 保留最优一条并移动到末尾预留槽；
  超额职业词条按语义确定性映射成同品阶、同百分位的已开放通用词条，并按原词条所属职业
  每条退还 1 枚徽记。固定词条、其他随机词条和待决候选都参与 key 去重。
- 每次职业词条转换或换位后，都从当前规范化词条和待决候选重新计算实时占用 key；
  已被转换掉的旧职业 key 不得作为“幽灵占用”继续阻塞跨槽候选。
- v10 尚未校验 `equipped` 外层槽位与装备定义是否一致；v11 收紧该约束前，迁移会把
  所有错槽实例按稳定顺序完整移回背包。正确槽、UID、强化、词条与 pending 都不改；
  即使正确目标槽已占或同时存在多个错槽，也不覆盖、不丢件。
- 所有 pending 索引跟随**原目标词条身份**换位。换位若改变重铸槽类型，候选按新槽合法池
  转换：职业池读取迁移时 `save.player.classId`，数值仍保留品阶和百分位；无合法候选直接
  `MigrationError`。无职业槽的旧稀有铭刻改成通用重铸并退徽记；淬炼 / 同调目标若被转成
  通用词条，其候选同步换 key，同调再按新相邻品阶精确复算。
- 迁移不改变金币、其他材料、RNG、共鸣或永久锁定；v11 再次读取不会重复退款。

## 九、提案自检（对照 40 号文档十二问）

1. **决定什么** —— 洗哪条、锁哪几条、材料花在重铸还是淬炼、徽记留给哪件装备
2. **放弃什么** —— 锁定成本指数增长，多锁一条就少一次重铸；同调结晶用了就没了
3. **随机改变什么** —— 词条类型与品阶；边界是权重表与 T5 上限，不会掷出超模属性
4. **环境如何回应** —— 共鸣值随霉运累积并保底；专属槽保证职业特色不落空
5. **为何再开一局** —— 词条从新鲜掉落期望 0.7982 到 T5 1.64 仍有成长空间，永远有下一条可以推
6. **如何验证** —— `npm run sim` 硬判战力、TTK、η 与四层职业偏离；材料收支手算
7. **决策还是点击** —— 决策。四种词条操作与定契保护竞争同一批材料
8. **内在还是外部动机** —— 胜任感驱动：品阶颜色让「我把这件养好了」清晰可见
9. **同屏决策数** —— 洗练面板同时只需判断「采用 / 保留」，未超载
10. **峰与终** —— 峰＝洗出 T5 极品；终＝每次洗练都以「采用与否」这个正面选择收尾
11. **不玩会损失什么** —— 什么都不损失。材料不过期、共鸣值不衰减、无限时活动
12. **红线** —— 无强制覆盖、无碎裂、无掉阶、无付费专属概率、结果先看后定

## 十、一句话总结

> **词条类型让玩家选「要什么」，词条品阶让玩家选「什么时候满意」。**
> 前者靠重铸，后者靠淬炼 —— 两条路都要材料，材料从挂机来，
> 于是挂机回来之后，永远有一件事可以做。
