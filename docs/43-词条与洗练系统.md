## 一、现状诊断

当前词条系统在 `data/constants.ts` 的 `AFFIX_POOL`，共 12 条：

| 现状 | 问题 |
|---|---|
| 12 条词条**全部通用**，四职业共用一池 | 没有职业身份，剑姬和魔女洗出来的东西一样 |
| 词条**只在掉落时掷一次，永久固定** | 没有任何重掷途径，装备到手即定终身 |
| **12 条里有 4 条不进战斗结算** | `dmgReduce` / `elemDmg` / `lifesteal` / `skillMul` 在 `applyAffix` 里直接 return，注释写着「M5 再处理」 |
| 数值是 `rng.float(min, max)` 的连续值 | **玩家看不出这条洗得好不好** —— 这是「洗词条没意思」的根本原因 |
| 普通品质词条数为 0 | 白装完全没有词条 |

> **最关键的一条是第四条。** 一个 `atk +37` 和 `atk +42`，玩家无法判断哪个接近上限。
> 没有「好坏可辨」，就没有「值得再洗一次」。

## 二、核心结构

新体系由**四层**组成，缺一不可：

```
装备实例
 └── 词条槽（数量由品质决定）
      └── 每个槽 = 词条类型 × 词条品阶
                    │            └── 五档，决定数值系数（这一层是新增的核心）
                    └── 来自「通用池」或「职业专属池」
```

### 2.1 词条槽数量

| 品质 | 现值 | **新值** | 其中职业专属槽 |
|---|---:|---:|---:|
| 普通 common | 0 | **1** | 0 |
| 精良 fine | 1 | **2** | 0 |
| 稀有 rare | 2 | **3** | 0 |
| 史诗 epic | 3 | **4** | 1 |
| 传说 legendary | 4 | **5** | 1 |
| 神话 mythic | 5 | **6** | 2 |
| 棱彩 prismatic | 6 | **6** | 2 |
| 神圣 divine | 6 | **6** | 2 |

**「职业专属槽」的含义**：该槽位**只能**出当前职业的专属词条。
这保证史诗以上装备一定带职业特色，而不是靠运气。

> ⚠ 普通品质从 0 条改为 1 条，会让最低档装备也有词条。
> 这是所有者明确要求的「装备全部都要加上词条」。
> 由此带来的整体战力抬升必须跑 `npm run sim` 复验，见第七节。

### 2.2 词条品阶（本次设计的核心）

**同一条词条也分五档。** 这是让「慢慢养成」成立的机制。

| 品阶 | 名称 | 权重 | 出现概率 | 数值系数 | 建议配色 |
|---|---|---:|---:|---:|---|
| T1 | 粗糙 | 40 | 40% | **0.70** | `--q-common` 灰 |
| T2 | 普通 | 28 | 28% | **0.85** | 白 |
| T3 | 优良 | 18 | 18% | **1.00** | `--q-fine` 绿 |
| T4 | 卓越 | 10 | 10% | **1.25** | `--q-rare` 蓝 |
| T5 | 极品 | 4 | 4% | **1.60** | `--q-legendary` 金 |

**数值公式**

```
词条数值 = 基准值(装备等级) × 品阶系数 × (1 ± 3% 微浮动)

其中 基准值 = (AFFIX_POOL 的 min + max) / 2 × 等级缩放
     等级缩放 = scalesWithLevel ? level^1.3 : 1
```

微浮动只有 ±3%，**刻意做得很小** —— 让玩家一眼读的是「品阶」而不是小数点。
品阶名与颜色必须直接显示在词条上。

**期望值推演**

```
新鲜掉落的期望系数 = 0.4×0.70 + 0.28×0.85 + 0.18×1.00 + 0.10×1.25 + 0.04×1.60
                   = 0.887
全 T5 完美系数     = 1.60
```

> **这个设计是刻意的**：刚掉落的装备只有潜力的 **88%**，
> 洗满可以到 **160%** —— 中间 **1.8 倍**的差距，就是玩家要花时间去追的东西。
> 换句话说，同一件装备在「刚捡到」和「养成到位」之间存在近乎两倍的差距。

## 四、洗练玩法

### 4.1 四种操作 = 四种决策

洗练的深度来自**同一件装备上多种互斥的资源分配**，不是靠堆按钮。

| 操作 | 材料 | 效果 | 玩家在决策什么 |
|---|---|---|---|
| **重铸** | 洗练石 | 随机重掷**一条**词条：类型与品阶全变 | 这条我不要了，赌一个更好的 |
| **淬炼** | 凝晶砂 | **只重掷品阶**，保留词条类型 | 这条类型我满意，只想赌更高档 |
| **定契** | 定契符 | 锁定一条词条，本次操作不动它 | 保几条？锁得越多越贵 |
| **铭刻** | 职业徽记 | 本次重铸**必定**出该职业专属词条 | 用稀有材料换确定性 |
| **同调** | 同调结晶 | 直接把一条词条**提升一个品阶** | 攒着突破瓶颈，还是现在就用 |

> **「淬炼」是这套系统里最重要的一个操作。** 它把「词条类型」和「品阶」拆开，
> 玩家先用重铸凑齐想要的词条组合，再用淬炼把每一条的品阶慢慢推高 ——
> **这才是「慢慢养成到位」的实际路径**，而不是无脑重掷。

### 4.2 消耗公式

设装备需求等级 `L`、当前词条品阶 `T`（1~5）：

```
重铸（换一条）
  洗练石 = ceil(L / 5) + 1
  金币   = L × 50

淬炼（只洗品阶）
  凝晶砂 = ceil(L / 4) + T          ← 品阶越高越贵，防止无痛刷满
  金币   = L × 80

定契（锁定）
  定契符 = 2^(已锁定条数)           ← 1 / 2 / 4 / 8 / 16 …
  锁定在本次操作后解除

铭刻（保专属）
  职业徽记 = 1
  同时仍需支付一次重铸的洗练石与金币

同调（升一阶）
  同调结晶 = T                      ← 从 T4 升 T5 需要 4 个
  金币     = L × 300
```

**定契的指数成本是这套系统的核心张力**：
锁 1 条很便宜，锁 4 条要 8 个定契符。玩家必须判断
「哪几条值得保、哪几条可以赌」，而不是全锁了无脑刷。

### 4.3 保底：共鸣值

纯概率会让非酋玩家连续几十次洗不出高阶而弃坑
（`docs/12` 已有同源结论）。

```
每次重铸 / 淬炼后：
  出 T1 → 共鸣值 +2
  出 T2 → 共鸣值 +1
  出 T3 → 共鸣值不变
  出 T4 或 T5 → 共鸣值清零

共鸣值 ≥ 20 时，下一次操作**必定出 T4 或以上**，然后清零。
```

共鸣值**按装备实例单独记录**，存档字段见第六节。
自然出 T4+ 的概率是 14%，平均约 7 次就能出；
共鸣值满约需 19 次 —— 它只保护极端霉运，不改变正常手感。

### 4.4 铁律：绝不强制覆盖

**每次洗练的结果必须先展示，由玩家选择「采用」或「保留原样」。**

这条是硬要求，理由见 [`40-玩法设计透镜.md`](40-玩法设计透镜.md) 红线清单：
强制覆盖会制造「洗坏了」的挫败，属于惩罚性机制。
材料在**点击洗练时**扣除（保证有成本），
但**结果是否采用由玩家决定**。

## 六、存档与数据结构

### 6.1 `Affix` 结构扩展

```ts
export interface Affix {
  key: AffixKey;          // 已有
  value: number;          // 已有
  tier: 1 | 2 | 3 | 4 | 5;   // 新增：品阶
  locked?: boolean;          // 新增：本次洗练是否锁定（不持久化亦可）
}
```

### 6.2 `EquipmentInstance` 新增字段

```ts
/** 洗练共鸣值，0~20，满 20 下次必出 T4+ */
reforgeResonance: number;
```

### 6.3 存档迁移

当前 `SAVE_VERSION` 已到 v9（好感批次）。本次需 **v9 → v10**：

- 旧装备实例的每条词条按其数值反推品阶：
  `tier = 数值 / 基准值` 落入哪个系数区间就是哪一阶，
  落在区间外则就近取，**保证迁移后战力不变**。
- `reforgeResonance` 初始化为 0。
- 普通品质装备原本 0 词条，迁移后**不补发**词条（避免旧号凭空变强）；
  新掉落的普通装备才带 1 条。

## 七、数值校验（实施后必须跑）

| 检查项 | 目标 | 工具 |
|---|---|---|
| 全身满配战力变化 | 相比当前**不超过 +8%**（新鲜掉落状态） | `npm run sim` |
| 洗满（全 T5）战力上限 | 相比新鲜掉落 **约 +40%~55%** | 手算 + sim |
| TTK | 仍在 5 ± 1.5 秒 | `npm run sim` |
| 四职业效率偏离 | ±20% 内（专属词条不得打破平衡） | `npm run sim` |
| 洗练材料收支 | 日常挂机产出略高于一件装备洗到 T4 的消耗 | 手算 |

> **专属词条的权重设计有意让「立刻可用」的两条权重更高**（30 / 25），
> 需要新逻辑的两条较低（25 / 20）—— 这样即使后两条延后接入，
> 玩家也不会觉得专属槽经常「空转」。

**第 1、2 步做完就已经能上线**：玩家立刻能看出词条好坏，
四条死词条也活了。第 4 步做完，洗练玩法成立。

## 九、提案自检（对照 40 号文档十二问）

1. **决定什么** —— 洗哪条、锁哪几条、材料花在重铸还是淬炼、徽记留给哪件装备
2. **放弃什么** —— 锁定成本指数增长，多锁一条就少一次重铸；同调结晶用了就没了
3. **随机改变什么** —— 词条类型与品阶；边界是权重表与 T5 上限，不会掷出超模属性
4. **环境如何回应** —— 共鸣值随霉运累积并保底；专属槽保证职业特色不落空
5. **为何再开一局** —— 每件装备都有 88% → 160% 的成长空间，永远有下一条可以推
6. **如何验证** —— `npm run sim` 复验战力、TTK、职业偏离；材料收支手算
7. **决策还是点击** —— 决策。四种操作互斥竞争同一批材料
8. **内在还是外部动机** —— 胜任感驱动：品阶颜色让「我把这件养好了」清晰可见
9. **同屏决策数** —— 洗练面板同时只需判断「采用 / 保留」，未超载
10. **峰与终** —— 峰＝洗出 T5 极品；终＝每次洗练都以「采用与否」这个正面选择收尾
11. **不玩会损失什么** —— 什么都不损失。材料不过期、共鸣值不衰减、无限时活动
12. **红线** —— 无强制覆盖、无碎裂、无掉阶、无付费专属概率、结果先看后定

## 十、一句话总结

> **词条类型让玩家选「要什么」，词条品阶让玩家选「什么时候满意」。**
> 前者靠重铸，后者靠淬炼 —— 两条路都要材料，材料从挂机来，
> 于是挂机回来之后，永远有一件事可以做。
